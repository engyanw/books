## 1. 威胁建模总览
### 1.1 定位与核心价值
威胁建模是整套安全架构的风险底数与设计靶心，所有防护能力、检测规则、运营流程均基于威胁模型推导而来，是风险驱动设计方法论的核心落地载体。

本卷针对 AI Agent 的原生特性，将传统威胁建模方法升级为**全链路攻击链闭环模型**，从攻击面分析到恢复机制形成完整逻辑链条，系统性识别所有潜在风险，明确防护、检测、响应、恢复的全流程应对方案。同时全面对齐四大国际主流威胁与风险管理框架，确保威胁识别的专业性与行业通用性。

本卷核心解决三类痛点：
1. **风险底数不清**：全面梳理 AI Agent 全场景攻击面，识别原生威胁与攻击路径，避免防护盲区
2. **防护针对性弱**：明确每类威胁的对应管控与检测措施，实现精准防护、资源合理分配
3. **标准对齐不足**：对标国际主流威胁框架，满足合规审计与行业对标需求

### 1.2 设计原则
1. **全链路覆盖原则**：覆盖攻击前、攻击中、攻击后全周期，形成防护-检测-响应-恢复的完整闭环
2. **原生特性优先原则**：重点聚焦 AI Agent 特有的原生威胁，传统 IT 通用威胁仅做补充对齐
3. **可落地验证原则**：所有威胁均对应可执行的防护、检测、响应方案，而非纯理论描述
4. **持续迭代原则**：威胁模型随攻击手法演进动态更新，保持与攻防对抗节奏同步
5. **标准对齐原则**：全面对齐国际主流威胁框架，术语、分类、分级与行业保持一致

### 1.3 模型整体框架
本威胁建模体系采用「**1 套方法论 + 1 条完整攻击链 + 10 大威胁域 + 4 大标准映射**」的整体结构：
- 1 套方法论：标准化 AI Agent 威胁建模流程，可复用、可推广
- 1 条攻击链：从攻击面到恢复的九环节全链路闭环模型
- 10 大威胁域：覆盖 AI Agent 所有原生核心威胁的详细拆解
- 4 大标准映射：对齐 MITRE ATT&CK、MITRE ATLAS、OWASP LLM Top 10、NIST AI RMF

## 2. 威胁建模方法论
### 2.1 标准化建模流程
AI Agent 威胁建模遵循六步标准化流程，适用于所有业务场景的风险识别：

1. **资产梳理**：明确保护对象，包括数据资产、模型资产、系统资产、业务能力资产，定义资产价值与影响等级
2. **攻击面分析**：全面梳理所有可被攻击者利用的入口、接口、功能、依赖，划定攻击面范围
3. **信任边界划分**：明确不同信任域的边界，识别跨边界的数据流与控制流，定位风险交汇点
4. **威胁识别**：基于攻击链模型，识别所有可能的威胁类型、攻击路径、发生概率
5. **风险评级**：按「发生概率 × 影响程度」计算风险值，划分高、中、低三级风险
6. **措施映射**：为每项风险匹配对应的防护、检测、响应、恢复措施，形成风险处置闭环

### 2.2 核心概念定义
| 概念 | 定义 | 在 AI 场景的特殊性 |
|------|------|--------------------|
| 攻击面（Attack Surface） | 攻击者可尝试进入系统或发起攻击的所有入口点与暴露面总和 | 不仅包括网络接口，还包括语义输入、提示接口、工具调用入口、记忆写入入口等语义级攻击面 |
| 信任边界（Trust Boundary） | 不同安全等级信任域之间的分界线，跨边界数据与操作必须经过校验 | 新增 Agent 与工具、Agent 与记忆、Agent 之间等多重新型信任边界 |
| 入口点（Entry Point） | 攻击者可注入恶意载荷或触发攻击的具体位置 | 包括用户输入、RAG 数据源、第三方插件、记忆数据、多 Agent 通信等多类入口 |
| 杀伤链（Kill Chain） | 攻击者完成一次完整攻击所需的步骤与阶段 | 从指令注入、权限绕过、工具调用到数据窃取、持续影响，形成 AI 专属攻击链路 |
| 威胁（Threat） | 可能对资产造成损害的潜在攻击行为与风险事件 | 以语义攻击、投毒攻击、自主行为滥用为核心，区别于传统网络攻击 |
| 管控（Control） | 用于降低攻击发生概率的防护性措施 | 以运行时动态管控为核心，叠加身份、数据、基建多层防护 |
| 检测（Detection） | 用于识别攻击正在发生或已经发生的监测机制 | 语义级行为检测 + 传统特征检测结合，覆盖动态行为风险 |
| 响应（Response） | 攻击发生后的处置与止损措施 | 包括权限冻结、任务终止、隔离排查、人工介入等 |
| 恢复（Recovery） | 攻击后的修复与业务恢复措施 | 包括数据修复、记忆清理、模型回滚、权限重置等 |

## 3. 全链路攻击链模型
### 3.1 攻击链总结构
本架构将 AI Agent 攻击完整生命周期拆解为九个环节，形成从攻击准备到业务恢复的全链路闭环，确保每个环节都有对应管控手段。

```
攻击面 → 信任边界 → 入口点 → 杀伤链 → 威胁 → 管控 → 检测 → 响应 → 恢复
```

### 3.2 各环节详细说明
#### 环节 1：攻击面（Attack Surface）
**定义**：所有可被攻击者利用的暴露面总和，是攻击的前提条件。
**分析维度**：
- 接口类攻击面：用户交互接口、API 接口、工具调用接口、多 Agent 通信接口
- 数据类攻击面：用户输入、RAG 知识库、记忆存储、训练数据、上下文数据
- 依赖类攻击面：第三方插件、开源框架、基础模型、供应链组件
- 人员类攻击面：内部操作人员、管理员、第三方维护人员

#### 环节 2：信任边界（Trust Boundary）
**定义**：不同安全等级域的分界线，是风险的交汇点，绝大多数攻击发生在跨边界场景。
**核心边界**：
- 外部用户与内部系统边界
- Agent 执行域与外部工具域边界
- 业务域与数据资产域边界
- 普通计算域与机密计算域边界
- 多 Agent 之间的信任边界
- 第三方组件与内部系统边界

#### 环节 3：入口点（Entry Point）
**定义**：攻击者可注入恶意载荷、触发攻击的具体位置，是攻击的实际切入点。
**典型入口点**：
- 用户自然语言输入框
- 上传的文件、文档、图片
- RAG 检索的外部知识库
- 第三方工具返回结果
- 持久化记忆数据
- 多 Agent 协作消息
- 系统配置与策略
- 模型微调数据集

#### 环节 4：杀伤链（Kill Chain）
**定义**：攻击者完成一次完整攻击的分步执行路径，对应攻击的不同阶段。
**AI Agent 标准杀伤链（七阶段）**：
1. **侦察探测**：收集目标 Agent 信息，测试防护规则，寻找绕过点
2. **载荷投递**：通过各类入口点注入恶意指令或投毒内容
3. **绕过防护**：利用提示注入、越狱等手法绕过安全检测与对齐机制
4. **权限获取**：诱导 Agent 调用高权限工具、访问敏感数据，获取操作权限
5. **目标执行**：执行窃取数据、篡改系统、发起欺诈等恶意操作
6. **持续驻留**：通过记忆投毒、篡改上下文等方式实现长期影响
7. **痕迹清除**：诱导删除日志、修改记录，掩盖攻击痕迹

#### 环节 5：威胁（Threat）
**定义**：具体的攻击行为与风险事件，是威胁建模的核心对象。
本架构共识别十大类核心原生威胁，详见第 4 章。

#### 环节 6：管控（Control）
**定义**：预防性措施，用于降低攻击发生概率，阻止攻击推进。
**管控层级**：
- 边界层管控：接入认证、流量清洗、边界防火墙
- 身份层管控：身份认证、权限校验、最小权限限制
- 运行时管控：输入检测、决策校验、工具网关、沙箱隔离
- 数据层管控：加密、脱敏、权限管控、水印溯源
- 基建层管控：容器安全、供应链管控、机密计算

#### 环节 7：检测（Detection）
**定义**：监测识别措施，用于发现正在发生或已经发生的攻击。
**检测维度**：
- 特征检测：基于规则、关键词、特征匹配已知攻击
- 行为检测：基于行为基线、异常模式识别未知攻击
- 语义检测：基于语义分析识别恶意意图与变种攻击
- 事后检测：基于审计日志、行为记录回溯发现攻击

#### 环节 8：响应（Response）
**定义**：攻击发生后的应急处置措施，目标是快速止损、控制影响范围。
**分级响应机制**：
- 低危事件：自动拦截、记录日志、定期复盘
- 中危事件：告警通知、人工复核、影响排查
- 高危事件：立即阻断、隔离受影响对象、启动应急流程、升级上报
- 重大事件：启动应急预案、全范围排查、业务降级、成立专项组

#### 环节 9：恢复（Recovery）
**定义**：事件处置后的修复与恢复措施，目标是恢复业务正常运行，消除攻击残留影响。
**恢复动作**：
- 业务恢复：恢复受影响的 Agent 服务与功能
- 数据恢复：清理恶意数据、修复被篡改内容、恢复正常记忆
- 权限恢复：重置异常权限、加固薄弱点
- 加固优化：升级防护规则、修补漏洞、完善检测能力
- 复盘总结：根因分析、流程优化、经验沉淀

## 4. 十大原生威胁域详解
### 4.1 提示注入攻击
#### 威胁概述
攻击者通过在用户输入、文档、网页等内容中嵌入恶意指令，诱导 Agent 忽略原始系统指令，执行攻击者指定的操作，是 AI Agent 最典型、最高发的原生威胁。分为直接注入、间接注入、多轮注入等多种形态。

#### 攻击面与入口点
- 攻击面：所有文本输入接口、文件上传接口、RAG 数据源、工具返回结果
- 入口点：用户输入框、上传文档、网页抓取内容、第三方工具返回、邮件/消息内容

#### 典型杀伤链
1. 攻击者构造包含隐藏恶意指令的文本、文档或网页
2. 通过用户输入、RAG 检索、工具调用等方式进入 Agent 上下文
3. 利用指令优先级混淆，绕过系统提示词约束
4. 诱导 Agent 执行恶意操作：泄露数据、调用工具、生成违规内容等
5. 通过输出将结果返回给攻击者，完成攻击目标

#### 管控措施
- 三层检测架构（规则+小模型+语义校验）全量覆盖输入检测
- 系统指令与用户输入物理隔离，明确指令边界
- 关键操作强制独立鉴权，不依赖上下文指令
- 工具调用参数白名单校验，不直接使用输入内容拼接指令

#### 检测方法
- 实时输入注入检测，识别典型注入特征与变种
- 异常指令模式识别，检测偏离系统角色的行为
- 工具调用异常检测，识别非预期的工具调用行为
- 输出异常检测，识别非预期的数据泄露与违规内容

#### 响应预案
- 实时拦截恶意输入，返回标准化拒绝响应
- 记录攻击特征与来源，加入黑名单与规则库
- 高频攻击触发限流与验证码校验
- 追溯攻击来源，封禁恶意账号与 IP

#### 恢复机制
- 更新检测规则，覆盖本次攻击变种
- 验证所有受影响场景的防护有效性
- 复盘攻击绕过点，优化防护体系
- 无数据泄露与系统变更时无需业务恢复

### 4.2 越狱攻击
#### 威胁概述
攻击者通过角色扮演、逻辑诱导、情感操控、多轮话术等方式，绕过模型的安全对齐机制，使 Agent 突破内容安全限制，生成违规、违法、有害内容，或执行被禁止的操作。

#### 攻击面与入口点
- 攻击面：所有对话交互接口、多轮会话场景
- 入口点：用户多轮对话输入、角色扮演指令、逻辑诱导话术

#### 典型杀伤链
1. 攻击者构造越狱 Prompt，通常采用角色扮演、虚拟场景、逻辑陷阱等形式
2. 通过多轮对话逐步引导 Agent 放松约束
3. 突破安全对齐机制，使 Agent 同意执行违规操作
4. 生成违规内容、执行被禁止的工具调用
5. 持续扩大操作范围，达成攻击目标

#### 管控措施
- 多层内容安全检测，输入输出双向校验
- 系统角色强化，明确边界与禁止项
- 高风险操作强制跳出上下文独立鉴权
- 对话轮次风险累积机制，持续高风险对话自动升级管控

#### 检测方法
- 越狱特征检测，识别典型越狱话术与模式
- 角色偏离检测，识别 Agent 偏离系统设定的行为
- 内容合规检测，识别输出中的违规内容
- 多轮对话风险评估，识别渐进式诱导行为

#### 响应预案
- 拦截违规输出，返回安全提示
- 高风险会话强制中断，重置对话上下文
- 恶意账号触发限流与封禁
- 记录攻击手法，更新检测规则

#### 恢复机制
- 优化检测规则与对齐策略
- 加固系统提示词与边界约束
- 清理异常会话上下文
- 无持久化影响时无需业务恢复

---

### 4.3 工具滥用攻击
#### 威胁概述
攻击者利用 Agent 的工具调用能力，通过注入、诱导等方式，让 Agent 执行未授权的工具操作，比如越权访问数据、修改系统配置、执行高危命令、发起网络请求等，是危害最大的 AI 原生威胁之一。

#### 攻击面与入口点
- 攻击面：所有可被 Agent 调用的工具、API、业务系统接口
- 入口点：用户输入、工具返回结果、上下文数据

#### 典型杀伤链
1. 攻击者通过注入或诱导，让 Agent 生成恶意工具调用请求
2. 绕过工具权限校验，调用高权限工具
3. 利用工具执行高危操作：数据查询、配置修改、命令执行
4. 将执行结果返回给攻击者，或直接造成破坏
5. 利用工具权限进一步横向渗透，扩大影响范围

#### 管控措施
- 统一工具安全网关，所有工具调用必经网关校验
- 参数级白名单管控，禁止超出白名单的参数值
- 最小权限原则，每个 Agent 仅授予完成任务必需的工具权限
- 高危操作强制人工二次审批，不可由 Agent 直接执行
- 工具返回结果二次安全校验，防止返回值注入

#### 检测方法
- 工具调用异常检测，识别非预期的工具与参数
- 高危操作行为检测，识别越权与异常操作模式
- 调用频率与范围异常检测，识别批量扫描与探测行为
- 工具返回结果注入检测

#### 响应预案
- 实时拦截越权工具调用
- 暂停对应 Agent 实例的工具权限
- 排查已执行的操作，评估影响范围
- 高危操作立即回滚，止损降害

#### 恢复机制
- 回滚恶意操作造成的变更
- 修复被篡改的数据与配置
- 加固工具权限与校验规则
- 重置受影响 Agent 的权限与上下文

---

### 4.4 记忆投毒攻击
#### 威胁概述
攻击者向 Agent 的持久化记忆中写入恶意或误导性内容，篡改 Agent 的认知与行为，使其在后续对话中持续输出错误信息、执行恶意操作，是 AI 场景特有的持续性攻击。

#### 攻击面与入口点
- 攻击面：Agent 长期记忆存储、用户画像、知识库
- 入口点：对话输入、文档上传、外部数据同步

#### 典型杀伤链
1. 攻击者通过正常对话向 Agent 传递错误或恶意信息
2. 信息被 Agent 写入长期记忆，持久化存储
3. 后续会话中，Agent 基于被投毒的记忆进行决策与输出
4. 持续产生错误结果、泄露数据或执行恶意操作
5. 投毒内容长期生效，难以被发现与清理

#### 管控措施
- 记忆写入前安全校验，过滤恶意与误导性内容
- 记忆读取权限管控，按身份与场景授权
- 高价值决策场景不依赖单一记忆源，交叉验证
- 定期全量记忆风险巡检，识别异常内容

#### 检测方法
- 写入时实时检测，识别投毒特征
- 定期存量扫描，发现已写入的恶意记忆
- 异常行为检测，识别由记忆偏差导致的异常输出
- 记忆变更审计，所有写入操作全量留痕

#### 响应预案
- 拦截恶意记忆写入
- 隔离已被投毒的记忆数据
- 排查受影响的 Agent 实例与会话
- 评估投毒造成的业务影响

#### 恢复机制
- 清理被投毒的记忆内容
- 回滚到投毒前的记忆版本
- 对受影响的业务结果进行复核与修正
- 优化记忆校验规则与巡检机制

---

### 4.5 RAG 投毒攻击
#### 威胁概述
攻击者篡改、污染 RAG 检索的知识库数据源，使 Agent 检索到错误、恶意或误导性信息，进而输出错误结论、执行错误操作，属于间接注入的一种高级形态。

#### 攻击面与入口点
- 攻击面：RAG 知识库、外部文档源、网页数据源、第三方数据接口
- 入口点：可编辑的知识库、可爬取的外部网页、上传的文档

#### 典型杀伤链
1. 攻击者通过编辑权限、上传文档或篡改网页，向知识库注入恶意内容
2. 用户提问时，Agent 从知识库检索到被投毒的内容
3. Agent 将投毒内容作为可信依据，生成错误或恶意的输出
4. 误导用户决策、泄露敏感信息或执行错误操作
5. 投毒内容长期存在于知识库，持续影响所有相关查询

#### 管控措施
- 知识库接入安全评审，可信数据源白名单机制
- 文档入库前安全检测，过滤恶意与误导内容
- 高价值场景多源交叉验证，不依赖单一数据源
- 检索结果风险评估，可疑内容标记提示，不直接作为结论依据
- 知识库定期安全巡检，识别异常内容

#### 检测方法
- 入库内容安全检测，识别投毒特征
- 检索结果风险评分，标识可疑内容
- 输出偏差检测，识别与事实偏离的异常结论
- 知识库定期全量扫描，发现存量投毒

#### 响应预案
- 下架被投毒的知识库内容
- 暂停对应数据源的检索权限
- 排查近期受影响的查询与输出
- 追溯投毒来源，封堵注入路径

#### 恢复机制
- 清理知识库中的恶意内容
- 恢复正确的知识库版本
- 通知受影响的用户复核相关结论
- 加固数据源准入与校验机制

### 4.6 数据泄露风险
#### 威胁概述
通过注入攻击、越权调用、权限漏洞等方式，诱导 Agent 泄露敏感数据，包括客户信息、商业秘密、代码数据、内部文档等，是最直接造成经济与声誉损失的威胁。

#### 攻击面与入口点
- 攻击面：所有可接触敏感数据的 Agent 场景、数据接口、工具接口
- 入口点：用户输入、工具调用、文件导出、对话输出

#### 典型杀伤链
1. 攻击者探测 Agent 的数据访问范围与输出边界
2. 通过注入、越权调用等方式获取敏感数据访问权限
3. 诱导 Agent 将敏感数据拼接进输出内容
4. 通过对话、文件、代码等形式将数据带出
5. 收集、扩散、售卖泄露的数据，造成实际损害

#### 管控措施
- 数据分类分级与字段级动态脱敏
- 输出敏感数据检测与自动脱敏
- 数据访问最小权限管控，Agent 权限不超过用户权限
- 高敏感数据禁止 Agent 直接访问，通过受控接口查询
- 数据外发水印溯源，泄露后可定位源头

#### 检测方法
- 输出敏感信息检测，识别未脱敏的敏感数据
- 数据访问异常检测，识别批量查询、越权访问行为
- 导出行为检测，识别大批量数据导出操作
- 注入攻击检测，识别旨在窃取数据的注入指令

#### 响应预案
- 实时拦截敏感数据输出
- 冻结对应 Agent 的数据访问权限
- 排查泄露范围与涉及的数据量级
- 追溯泄露源头，阻断攻击路径
- 按数据泄露应急流程启动合规通知

#### 恢复机制
- 加固数据访问权限与脱敏规则
- 评估泄露影响，开展合规处置
- 通知受影响主体，采取补救措施
- 优化防护体系，堵塞泄露漏洞

---

### 4.7 模型窃取攻击
#### 威胁概述
通过大量查询、侧信道攻击、权重提取等方式，窃取企业核心模型的能力、参数甚至完整权重，盗取企业核心数字资产，造成知识产权损失。

#### 攻击面与入口点
- 攻击面：模型推理接口、API 服务、部署环境
- 入口点：API 调用接口、用户交互界面、部署环境漏洞

#### 典型杀伤链
1. 攻击者通过公开接口对模型进行大量查询采样
2. 收集输入输出对，训练替身模型，提取模型能力
3. 利用环境漏洞或侧信道信息，进一步提取模型参数
4. 最终获得完整或近似的模型副本
5. 用于自身业务、售卖牟利或进一步挖掘漏洞

#### 管控措施
- 模型访问权限管控，调用频率与总量限制
- 模型推理接口输入输出水印，被盗用可溯源
- 核心模型部署在可信执行环境中，防止内存窃取
- 模型权重加密存储，运行时动态解密
- API 层异常调用检测，防御批量探测

#### 检测方法
- 调用行为异常检测，识别批量探测式查询
- 查询内容相似性检测，识别系统性采样行为
- 访问频率与时段异常检测
- 环境侧异常检测，识别内存读取、进程调试等行为

#### 响应预案
- 限制异常账号的调用频率与权限
- 封禁恶意访问来源
- 排查模型暴露范围与窃取程度
- 评估知识产权损失风险

#### 恢复机制
- 升级模型防护策略与调用限制
- 核心模型更换水印与接口特征
- 高风险场景部署新的模型版本
- 完善知识产权保护体系

---

### 4.8 供应链攻击
#### 威胁概述
通过污染 AI 供应链环节（开源框架、第三方插件、预训练模型、数据集、依赖组件等），植入后门、漏洞或恶意代码，随组件部署进入企业系统，实现持久化攻击。

#### 攻击面与入口点
- 攻击面：模型、数据集、框架、插件、依赖库、开发工具全供应链
- 入口点：组件引入、模型微调、插件安装、依赖更新

#### 典型杀伤链
1. 攻击者向开源组件、公共模型、数据集植入恶意代码或后门
2. 企业在不知情的情况下引入受污染的组件
3. 组件在系统中运行，触发后门或恶意逻辑
4. 窃取数据、破坏系统、预留持久化访问权限
5. 长期潜伏，持续造成损害，难以发现与排查

#### 管控措施
- AI-BOM 全量资产台账，梳理所有供应链组件
- 第三方组件准入安全评审，高危组件禁止接入
- 组件漏洞扫描与风险监测，持续跟踪漏洞情报
- 核心组件多供应商备选，避免单一依赖
- 运行时沙箱隔离，第三方组件最小权限运行

#### 检测方法
- 组件漏洞情报监测，及时发现公开漏洞
- 运行时异常行为检测，识别组件异常操作
- 供应链威胁情报跟踪，预警投毒与后门事件
- 定期全量组件风险扫描，发现存量风险

#### 响应预案
- 禁用存在风险的供应链组件
- 回滚到安全版本，替换受影响组件
- 排查组件造成的影响范围与损害
- 跟进官方修复方案，及时升级补丁

#### 恢复机制
- 替换为安全版本组件
- 修复被篡改的数据与系统配置
- 加固组件准入与扫描机制
- 完善供应链风险管控体系

---

### 4.9 Agent 仿冒攻击
#### 威胁概述
攻击者伪造或冒用合法 Agent 身份，骗取用户信任或系统权限，诱导用户泄露信息、执行恶意操作，或接入内部系统获取权限。

#### 攻击面与入口点
- 攻击面：多 Agent 协作接口、用户交互界面、系统接入接口
- 入口点：协作消息、第三方 Agent 接入、仿冒交互界面

#### 典型杀伤链
1. 攻击者构造仿冒的 Agent 服务或身份凭证
2. 接入多 Agent 协作体系，或直接面向用户提供服务
3. 骗取其他 Agent 或用户的信任，获取信息与权限
4. 窃取数据、传播恶意内容、诱导执行危险操作
5. 长期潜伏，持续实施欺诈

#### 管控措施
- Agent 统一身份体系，所有 Agent 身份可验证、可追溯
- 跨域 Agent 接入强制身份认证与权限审批
- Agent 间通信强制身份校验，无身份消息直接丢弃
- 用户侧明确标识官方 Agent 身份，提示仿冒风险
- 敏感操作二次确认，不轻易信任 Agent 身份

#### 检测方法
- 身份凭证异常检测，识别伪造与冒用身份
- 行为异常检测，识别偏离正常角色的 Agent 行为
- 接入异常检测，识别未授权接入的 Agent
- 用户举报与反馈机制

#### 响应预案
- 立即封禁仿冒 Agent 身份与接入权限
- 通知受影响的用户与其他 Agent
- 排查仿冒造成的影响与损失
- 追溯仿冒来源，封堵接入漏洞

#### 恢复机制
- 加固身份验证机制
- 清理仿冒身份与相关数据
- 通知受影响主体，提醒防范
- 优化身份信任体系

---

### 4.10 内部威胁
#### 威胁概述
内部人员利用合法权限，通过 Agent 超出授权范围获取数据、执行操作，或恶意利用 Agent 规避安全管控，实施违规行为。

#### 攻击面与入口点
- 攻击面：所有内部人员可访问的 Agent 服务、管理后台、配置接口
- 入口点：合法账号、管理权限、配置修改权限

#### 典型杀伤链
1. 内部人员利用合法账号访问 Agent 服务
2. 通过 Agent 间接访问超出自身权限的数据与系统
3. 利用 Agent 绕过传统安全管控，执行违规操作
4. 窃取数据、篡改系统、谋取私利
5. 利用 Agent 黑盒特性掩盖操作痕迹

#### 管控措施
- 三级身份穿透，Agent 权限不超过用户权限
- 所有操作全量审计，可追溯到具体人员与 Agent
- 最小权限原则，Agent 与用户权限严格对齐
- 高危操作强制多人审批，单人无法完成
- 行为异常检测，识别内部人员异常操作模式

#### 检测方法
- 用户行为异常检测，识别偏离日常基线的操作
- 权限滥用检测，识别利用 Agent 越权的行为
- 批量操作检测，识别大批量数据导出与查询
- 管理操作审计，识别异常配置变更

#### 响应预案
- 暂停异常账号与对应 Agent 的权限
- 启动内部调查，核查操作内容与影响
- 保全审计日志与证据
- 按内部违规流程处置

#### 恢复机制
- 重置相关账号与权限
- 修复被篡改的配置与数据
- 完善权限管控与审计机制
- 加强内部安全意识培训

## 6. 威胁分级与优先级
### 6.1 风险评级标准
采用「发生概率 × 影响程度」二维评级标准，将所有威胁划分为高三级：

| 风险等级 | 判定标准 | 处置优先级 |
|----------|----------|------------|
| 高危 | 发生概率高 + 影响程度大；或发生概率中 + 影响极大 | P0，必须立即修复，优先投入资源 |
| 中危 | 发生概率中 + 影响中等；或概率高 + 影响小；或概率低 + 影响大 | P1，规划期内修复，纳入近期建设计划 |
| 低危 | 发生概率低 + 影响程度小 | P2，择机修复，纳入长期优化计划 |
