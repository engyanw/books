## 1. 厂商映射总览
### 1.1 定位与核心价值
本卷是企业开展 AI Agent 安全厂商选型的统一对标标尺，基于第 5 卷标准化的安全能力模型，对主流厂商的 AI 原生安全能力做客观、系统化的横向对比，配套选型方法论与场景化落地指引，解决企业选型过程中的三类核心痛点：
1. **标准不统一**：各厂商能力口径不一、概念包装多，难以横向对比真实防护能力
2. **选型风险高**：缺乏体系化评估方法，容易出现“上线后才发现能力缺口”的踩坑问题
3. **适配性不足**：厂商能力与企业业务场景、技术栈、合规要求不匹配，造成投入浪费

本卷所有评估均基于公开生产级能力与行业落地实践，保持客观中立，无厂商偏向，可直接作为企业选型、商务评估、POC 测试的参考依据。

### 1.2 设计原则
1. **客观中立原则**：基于统一能力标准客观评估，不预设厂商倾向，所有结论对应可验证的能力项
2. **落地导向原则**：仅评估可落地的生产级能力，概念性、宣传性功能不纳入评分
3. **标准对齐原则**：所有能力项严格对齐第 5 卷安全能力模型，确保评估口径统一、可比
4. **动态更新原则**：随厂商能力迭代与版本更新按季度修订，保持信息的时效性与准确性

### 1.3 覆盖厂商范围
本次覆盖两大类共 7 类主流方案，均为全球与国内企业级市场的主流选择，覆盖绝大多数企业的选型场景：
| 厂商类别 | 包含厂商 | 核心特点 |
|----------|----------|----------|
| 国内云厂商 | 阿里云、腾讯云、华为云、百度智能云 | 本土化适配好，合规资质完善，符合国内企业使用习惯 |
| 海外云厂商 | AWS、Microsoft Azure | 全球化能力强，国际合规完善，适配跨国企业场景 |
| 专业第三方 AI 安全厂商 | 通用专业安全方案 | AI 原生安全能力最强，可跨云部署，适配异构环境 |

> 选取标准：企业级市场份额靠前、AI Agent 安全能力体系相对完善、有规模化生产落地案例的厂商方案。

### 1.4 评估维度与评分标准
#### 评估维度
基于第 5 卷 8 大能力域，补充服务与成本维度，共 9 大评估维度，全面覆盖企业选型核心关注点：
1. 身份与访问安全
2. 运行时安全防护
3. 数据与模型安全
4. 基础设施安全
5. 威胁检测与运营
6. 合规与治理
7. 可观测性能力
8. 基础支撑能力
9. 服务与成本（技术支持、生态完善度、整体拥有成本）

#### 评分标准
采用五级星级制，统一评估标尺：
| 评分 | 等级定义 | 说明 |
|------|----------|------|
| ★★★★★ | 行业领先 | 能力完整成熟，防护效果与落地体验处于行业标杆水平 |
| ★★★★ | 良好 | 核心能力完善，可独立支撑生产级场景落地 |
| ★★★ | 一般 | 基础能力具备，高级能力需补充或二次开发 |
| ★★ | 待完善 | 仅有基础雏形，多数场景需要企业自建补充 |
| ★ | 缺失 | 无对应专项能力，完全依赖其他方案补充 |

## 2. 厂商选型方法论
### 2.1 标准化选型六步流程
企业开展 AI 安全厂商选型，建议遵循标准化六步流程，降低决策风险：

1. **需求梳理阶段**
   - 全面盘点 Agent 业务场景、风险等级、数据敏感度
   - 明确合规要求、现有技术栈、部署模式约束
   - 确定核心诉求排序：安全强度优先 / 成本优先 / 体验优先 / 合规优先

2. **厂商初筛阶段**
   - 基于部署模式（公有云/私有化/混合云）缩小候选范围
   - 基于行业合规资质、生态适配性筛选出 2-3 家核心候选
   - 排除明显不符合核心约束的厂商方案

3. **能力对标阶段**
   - 对照本卷能力矩阵，逐项对比候选厂商的能力匹配度
   - 识别核心能力缺口，评估缺口的可接受程度与补充成本
   - 形成能力差距分析报告

4. **POC 测试阶段**
   - 针对核心业务场景搭建测试环境，实测防护效果
   - 核心验证项：高危威胁检出率、误报率、性能损耗、兼容性
   - 输出 POC 测试报告，量化验证效果

5. **商务评估阶段**
   - 评估全生命周期成本：建设成本 + 运营成本 + 扩容成本
   - 评估厂商服务能力、技术支持水平、生态完善度
   - 评估商务条款、数据主权、安全责任边界

6. **决策落地阶段**
   - 综合能力、成本、服务、风险多维度评分
   - 确定最终厂商与落地方案
   - 制定分阶段实施计划

### 2.2 权重化评估模型
采用加权评分法开展综合评估，不同类型企业可调整各维度权重，匹配自身核心诉求。以下为三类典型企业的权重参考：

| 评估维度 | 强合规行业（金融/政务） | 互联网行业 | 制造业 |
|----------|--------------------------|------------|--------|
| 合规与治理 | 30% | 10% | 5% |
| 数据与模型安全 | 20% | 10% | 15% |
| 运行时安全防护 | 15% | 25% | 20% |
| 身份与访问安全 | 10% | 10% | 10% |
| 威胁检测与运营 | 10% | 15% | 10% |
| 基础设施安全 | 10% | 10% | 25% |
| 服务与成本 | 5% | 20% | 15% |

### 2.3 典型选型误区规避
1. **误区一：只评估大模型能力，忽略安全能力**
   - 风险：AI 上线后才发现安全短板，无法规模化进入核心场景
   - 建议：安全与模型能力同步评估，安全是规模化落地的前提

2. **误区二：追求功能大而全，忽略实际需求**
   - 风险：为低频功能支付高额成本，投入产出比低
   - 建议：基于业务风险按需选型，核心能力达标即可，避免过度建设

3. **误区三：完全依赖厂商原生能力，无兜底方案**
   - 风险：厂商能力覆盖不到的场景形成防护盲区
   - 建议：厂商原生能力作为底座，核心高风险场景配套专业方案兜底

4. **误区四：只看初期建设成本，忽略长期运营成本**
   - 风险：初期采购成本低，后续运营人力、扩容成本持续高企
   - 建议：按 3 年全生命周期评估总成本，避免只看首期投入

## 4. 分厂商能力详解
### 4.1 阿里云
#### 核心优势
- 本土化生态最完善，与百炼 Agent 平台深度集成，一站式交付 AI 安全能力
- 合规资质最全，覆盖金融、政务、等保、关基等国内绝大多数合规要求
- 运行时安全与数据安全能力成熟，支持提示注入检测、敏感数据脱敏、水印溯源等核心能力
- 云原生安全体系完整，可无缝复用企业已有的阿里云安全能力，降低重复建设
- 信创适配完善，支持国产化环境私有化部署

#### 能力短板
- 海外节点与全球化合规能力弱于 AWS、Azure，跨国业务适配不足
- AI 原生威胁检测与运营深度不及专业第三方厂商，高级攻防场景需补充
- 高阶能力订阅成本偏高，小企业全量开通投入较大

#### 最佳适配场景
- 国内大中型企业、全栈使用阿里云生态的企业
- 金融、政务、央企等强合规、强数据安全要求的行业
- 基于阿里云百炼平台规模化落地 Agent 的企业

#### 落地建议
- 优先复用阿里云原生安全底座，核心高风险场景补充第三方专业检测能力兜底
- 安全日志与告警统一接入企业现有 SOC，避免形成运营孤岛
- 按业务场景分级开通安全能力，核心场景高配、长尾场景基础版，优化成本

---

### 4.2 腾讯云
#### 核心优势
- C 端与生态连接能力强，适配面向用户的客服、营销类 Agent 场景
- 运行时基础防护与内容安全能力成熟，适配中文语境的违规内容检测
- 与混元大模型、腾讯生态工具深度打通，一站式交付体验好
- 本土化服务响应快，技术支持与商务对接灵活度高
- 成本相对可控，中小企业友好度高

#### 能力短板
- 政务、金融等强合规行业的深度适配略逊于阿里云、华为云
- 多 Agent 治理、供应链安全等高级能力仍在完善中
- 私有化部署与信创适配能力相对较弱

#### 最佳适配场景
- 互联网、零售、服务类企业，面向 C 端用户的 Agent 场景
- 基于腾讯生态开展业务的企业
- 中等规模、追求性价比的企业

#### 落地建议
- 重点用好内容安全与基础注入检测能力，核心工具调用场景补充专项网关
- 对接企业现有身份与运营体系，补齐治理能力短板
- 业务快速增长期提前评估架构扩展性，避免后期重构

---

### 4.3 华为云
#### 核心优势
- 信创与国产化适配能力最强，全面支持国产芯片、操作系统、中间件
- 政务、能源、制造业等行业深度适配，满足央企、关基单位的自主可控要求
- 基础设施安全与算力隔离能力突出，适配 GPU 大规模算力场景
- 线下服务能力强，可支撑大型私有化项目定制交付
- 盘古大模型与行业方案深度绑定，行业 Agent 落地配套完善

#### 能力短板
- 互联网生态与通用场景适配性略弱
- AI 原生运行时检测、威胁运营的精细度不及互联网云厂商与专业厂商
- 整体成本偏高，中小企业落地门槛较高

#### 最佳适配场景
- 政务、央企、军工、能源等强自主可控、强信创要求的单位
- 制造业、工业场景的生产级 Agent 落地
- 私有化部署、本地化运行的大型项目

#### 落地建议
- 重点复用基建安全与信创适配能力，AI 原生安全配套专业方案补充
- 建立分级防护体系，核心高敏场景强化安全，普通场景复用基础能力
- 配套专属运营团队，保障私有化部署的长期运维效果

---

### 4.4 百度智能云
#### 核心优势
- 文心大模型生态完善，AI 原生技术积累深，模型层安全能力突出
- 搜索与语义技术基础好，RAG 场景的安全检测有技术优势
- 成本相对亲民，适合基于百度生态开展 AI 业务的企业
- 行业方案覆盖广，配套的行业 Agent 与安全一体化交付

#### 能力短板
- 云原生安全底座厚度不及阿里、腾讯、华为
- 企业级治理、合规审计、身份体系的完善度有差距
- 私有化与大型项目交付能力相对弱

#### 最佳适配场景
- 基于百度大模型开展 AI 业务的企业
- 知识管理、搜索类 Agent 场景
- 中等规模、业务场景相对聚焦的企业

#### 落地建议
- 重点用好模型层与语义检测能力，企业级安全治理对接现有体系
- 核心业务场景配套第三方专业安全方案，补足治理与运营短板
- 统一纳入企业整体安全运营体系，避免形成独立安全域

---

### 4.5 AWS
#### 核心优势
- 全球基础设施覆盖最广，全球化部署与合规能力最强
- 云原生安全体系最成熟，基建安全、身份治理、威胁运营处于行业标杆水平
- Bedrock 平台安全能力完善，适配多模型的统一安全管控
- 架构标准化程度高，生态最丰富，第三方方案兼容性最好
- 可观测与自动化运营能力领先，支撑超大规模场景

#### 能力短板
- 国内本土化服务、合规资质不足，无法满足国内强监管要求
- 中文语境下的注入检测、内容安全效果弱于国内厂商
- 整体成本偏高，技术支持响应速度慢于国内厂商

#### 最佳适配场景
- 跨国企业、海外业务为主的企业
- 全球化部署、有多区域合规要求的 Agent 业务
- 基于 AWS 技术栈的海外业务团队

#### 落地建议
- 优先复用 AWS 原生的身份、基建、合规能力
- 中文场景与深度 AI 安全补充本土化专业方案
- 建立全球统一管控、区域分级执行的运营体系

---

### 4.6 Microsoft Azure
#### 核心优势
- 与 OpenAI 生态深度整合，Azure OpenAI 服务安全能力原生配套
- 身份与合规能力突出，Active Directory 生态企业级适配最好
- 全球化合规完善，满足欧盟、北美等多地区监管要求
- 与微软办公、企业软件生态打通，适配企业内部 Agent 场景
- 企业级治理与权限管理体系成熟

#### 能力短板
- 国内落地受政策约束，本土化服务与支持弱
- 运行时安全深度不足，高级注入攻击防护能力有限
- 成本较高，大规模部署投入大

#### 最佳适配场景
- 外资企业、跨国企业的全球统一 AI 部署
- 深度使用微软生态的企业内部 Agent 场景
- 有强身份治理、全球合规要求的企业

#### 落地建议
- 充分复用 Azure 身份与合规底座，与企业 AD 体系打通
- 核心业务场景补充专业 AI 运行时安全能力
- 国内业务配套本土化安全方案，满足国内合规要求

---

### 4.7 第三方专业 AI 安全厂商
#### 核心优势
- AI 原生安全能力最强，提示注入、越狱、工具滥用等核心威胁的检出率与防护深度优于云厂商
- 跨云、跨环境部署能力强，可适配公有云、私有化、混合云、多云等所有部署模式
- 威胁运营与攻防研究专注度高，规则迭代速度快，跟进新型攻击的响应更及时
- 可与企业现有安全体系无缝对接，不替换已有投资
- 定制化能力强，可适配企业个性化场景需求

#### 能力短板
- 基础设施安全、身份管理等底层能力不具备，需要对接企业现有体系
- 整体部署工作量略高于云原生方案
- 品牌知名度与市场份额低于头部云厂商

#### 最佳适配场景
- 核心高风险 Agent 场景的深度防护
- 多云、混合云、私有化等异构环境的统一安全管控
- 对 AI 原生安全要求高、云原生能力无法满足需求的企业
- 有统一安全中台建设规划的大型集团企业

#### 落地建议
- 采用「云厂商底座 + 专业厂商核心能力」的混合模式，性价比最优
- 重点承载运行时防护、威胁检测、攻防运营等核心能力
- 身份、基建、数据安全复用企业现有能力，避免重复建设

---

## 5. 分场景选型指引
### 5.1 按企业规模选型
#### 小型企业
- **选型策略**：优先公有云原生安全能力，开箱即用，控制初期与运维成本
- **推荐方案**：阿里云/腾讯云基础安全套件，随业务发展逐步升级
- **核心关注点**：成本、易用性、开箱即用、基础合规

#### 中型企业
- **选型策略**：云厂商原生能力为主体，核心高风险场景补充 1-2 项专业能力
- **推荐方案**：主云厂商安全体系 + 第三方运行时检测/数据安全专项能力
- **核心关注点**：体系完整性、扩展性、运营效率、投入产出比

#### 大型集团企业
- **选型策略**：统一安全中台模式，云厂商底座 + 专业厂商核心能力 + 自建运营体系
- **推荐方案**：混合架构，统一身份、统一策略、统一运营，多厂商能力组合
- **核心关注点**：体系化、可扩展、多租户、跨业务线统一管控、长期演进能力

### 5.2 按行业选型
| 行业 | 核心诉求 | 首选厂商 | 备选方案 |
|------|----------|----------|----------|
| 金融行业 | 合规、数据安全、审计、风险管控 | 阿里云、华为云 | Azure（外资行）+ 专业安全厂商 |
| 政务/央企 | 信创、自主可控、等保合规 | 华为云、阿里云政务云 | 专业私有化安全方案 |
| 互联网行业 | 性能、弹性、成本、C 端场景适配 | 腾讯云、AWS | 第三方专业检测方案 |
| 制造业 | 基建适配、边缘部署、生产安全 | 华为云、阿里云 | 工业级专业安全方案 |
| 跨国企业 | 全球化、多区域合规、统一管控 | AWS、Azure | 全球化专业安全厂商 |

### 5.3 按部署模式选型
#### 公有云部署
- 优先选择对应云厂商的原生安全能力，集成度最高、运维成本最低
- 核心高风险场景叠加第三方专业能力增强防护
- 避免多套安全体系并存，优先统一到云厂商运营体系

#### 私有化部署
- 优先选择支持私有化交付、信创适配的厂商方案
- 重点评估厂商的本地化服务能力与长期运维支持
- 推荐：华为云、阿里云私有化版本 + 第三方专业私有化方案

#### 混合云/多云部署
- 采用统一安全中台架构，上层统一管控，下层复用各云原生能力
- 优先选择跨云适配能力强的第三方方案作为统一中台
- 避免每套云单独建设安全体系，造成重复建设与策略不一致

## 6. 多云与混合部署统一方案
### 6.1 架构思路
多云、混合云场景下，推荐采用「**统一安全中台 + 云厂商原生执行点**」的两层架构，兼顾统一管控与原生能力复用：
- **上层统一中台**：统一身份、统一策略、统一运营、统一审计，跨云、跨环境标准一致
- **下层原生执行点**：各云厂商、各环境的原生安全能力作为执行节点，复用基础设施与基础能力

该架构可避免多云环境下的重复建设，实现防护标准一致、运营统一管理、投资充分复用，是大型集团企业的主流落地方案。

### 6.2 核心落地要点
1. **身份统一**：通过身份联邦对接所有云厂商与环境的身份体系，全局唯一身份、全链路可追溯
2. **策略统一**：统一策略中台管理所有安全规则，跨环境秒级同步，确保防护标准一致
3. **运营统一**：全量安全日志、告警统一汇聚到中央 SOC，全局态势统一运营
4. **数据分级流动**：核心数据留存私有域，非敏感计算上公有云，数据跨域流动全程可控可审计

### 6.3 典型厂商组合方案
| 部署场景 | 推荐厂商组合 | 架构说明 |
|----------|--------------|----------|
| 国内+海外混合 | 阿里云 + AWS + 第三方统一中台 | 国内业务用阿里云，海外用 AWS，第三方中台拉通统一管控 |
| 公有云+私有云混合 | 主云厂商 + 第三方私有化安全组件 | 公有云复用原生能力，私有云部署专业组件，策略统一同步 |
| 多云异构环境 | 第三方专业 AI 安全平台为主 + 各云原生基建安全 | 第三方平台做统一安全中台，云厂商提供底层基建安全 |
