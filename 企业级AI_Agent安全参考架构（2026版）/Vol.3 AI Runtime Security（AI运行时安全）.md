## 1. 模块定位
AI运行时安全是企业级AI Agent安全体系的核心执行层，纵向承接总体架构中的**运行时平面（Runtime Plane）**与**安全平面（Security Plane）运行时防护域**，横向覆盖Agent从输入接收、任务规划、工具调用、记忆读写到结果输出的全执行链路。

与传统应用运行时安全不同，本模块针对Agent自主决策、动态规划、多工具调用、记忆持久化等原生特性，构建「旁路检测+实时拦截+动态风控+隔离执行」四位一体的防护体系，弥补静态代码扫描、上线前安全评审等左移手段无法覆盖的动态运行风险。

- **架构定位**：纵深防御体系的核心拦截层，是风险进入业务系统前的最后一道安全闸门
- **能力定位**：AI原生攻击的主要检测与处置载体，覆盖90%以上的动态运行风险
- **落地定位**：以无侵入、旁路化方式接入现有Agent体系，最小化业务改造成本

## 2. 设计目标
1. **全链路实时防护**：覆盖Agent执行全流程关键节点，实现输入、规划、调用、输出、记忆全环节的安全校验，无防护盲区
2. **零侵入业务接入**：采用Sidecar、网关、代理等旁路部署模式，无需修改Agent业务代码即可接入安全能力
3. **高性能低损耗**：核心安全校验新增延迟≤100ms，安全资源占用≤整体Agent资源的15%，高并发场景下业务无感知
4. **细粒度精准管控**：支持工具级、操作级、参数级、字段级的精细化权限管控与风险校验，避免一刀切式拦截
5. **AI原生攻击适配**：针对提示注入、越狱、记忆投毒、工具滥用等AI专属攻击，提供语义级检测能力，检测准确率≥95%
6. **弹性可扩展**：支持万级Agent实例并发接入，安全能力随业务规模弹性伸缩，无性能瓶颈
7. **故障透明兜底**：安全组件故障时自动旁路降级，不影响Agent核心业务运行，实现安全故障零业务影响

## 3. 设计原则
本卷严格遵循Vol.1定义的13项架构原则，并针对运行时场景强化以下核心设计原则：
- **Runtime First（运行时优先）**：以动态运行期防护为核心，所有安全能力优先在运行时落地，弥补静态防护的局限性
- **Bypass First（旁路优先）**：优先采用旁路、代理、Sidecar模式部署安全能力，避免侵入业务代码，降低接入与迭代成本
- **Context Aware（上下文感知）**：所有安全决策基于完整对话上下文、任务场景、历史行为综合判断，而非单条指令孤立检测
- **Tiered Protection（分级防护）**：按风险等级匹配不同强度的防护策略，低风险场景轻量化校验，高风险场景全量深度检测
- **Fail Open（故障透传）**：安全组件异常时默认放行业务流量，日志本地留存事后补审，优先保障业务可用性
- **Precision Interception（精准拦截）**：以极低误报率为核心指标，拦截准确率优先于拦截覆盖率，避免过度防护影响业务效率

## 4. 功能职责
AI运行时安全承担七大核心功能域，覆盖Agent运行全生命周期：

### 4.1 输入侧安全治理
- 直接用户输入的恶意指令检测：提示注入、越狱诱导、多模态隐藏指令
- 间接输入的安全校验：RAG检索结果、工具返回内容、第三方数据中的隐藏指令与恶意内容
- 输入内容合规初审：违法违规、敏感信息、不当内容的前置过滤
- 输入上下文风险评估：多轮对话的风险累积评估，识别渐进式攻击

### 4.2 Agent行为动态管控
- 任务规划合法性校验：验证Agent规划的执行路径与原始任务目标的一致性，防范任务偏离
- 行为基线动态比对：基于Agent历史正常行为建立基线，识别异常行为模式
- 动态权限评估：基于当前任务场景、风险等级动态调整Agent权限范围
- 思考链安全审计：对Agent的推理过程、中间步骤进行安全校验与留存

### 4.3 工具调用全链路防护
- 工具调用身份鉴权：验证Agent身份、用户身份、任务场景的合法性
- 细粒度权限校验：工具级、接口级、操作级、参数级的多层权限控制
- 参数合法性校验：参数格式、范围、内容的白名单校验，防范参数注入
- 调用频次与行为风控：批量调用、异常时段调用、高危操作的实时风控
- 调用全链路审计：完整记录调用请求、参数、返回结果、执行结果

### 4.4 输出侧安全管控
- 输出内容合规审核：违法违规、暴力色情、政治敏感等内容的语义级检测
- 敏感数据脱敏：结构化与非结构化敏感信息的识别与动态脱敏
- 反泄露校验：防范代码、数据、凭证、商业秘密等通过输出泄露
- 输出一致性校验：验证输出内容与任务目标、安全规则的一致性

### 4.5 运行时隔离与沙箱
- Agent运行环境隔离：进程级、容器级、虚拟机级多层隔离可选
- 代码执行沙箱：Agent生成代码、第三方插件的隔离执行，防范恶意代码
- 资源配额限制：CPU、内存、磁盘、网络的精细化配额管控
- 系统调用约束：白名单机制限制系统调用范围，缩小攻击面

### 4.6 动态风险决策引擎
- 实时风险评分：基于多维度数据对当前会话进行综合风险打分
- 分级处置决策：根据风险等级匹配对应处置动作（放行、告警、拦截、人工审核）
- 处置动作执行：拦截、限流、降级、冻结权限、终止会话等动作的精准执行
- 风险联动处置：与身份、数据、威胁检测等模块联动，实现跨模块协同处置

### 4.7 记忆读写安全管控
- 记忆写入内容校验：写入记忆的内容进行安全审核，防范记忆投毒
- 记忆读取权限管控：不同Agent、不同用户的记忆数据隔离与权限控制
- 记忆污染检测：定期巡检记忆数据，识别异常、恶意、错误内容
- 记忆生命周期管理：记忆有效期、归档、清理的安全管控

## 5. 逻辑架构
AI运行时安全采用「1个管控中心 + 4类执行点 + 1个检测引擎集群」的分层逻辑架构，实现管控与执行分离、检测与处置解耦。

### 5.1 运行时安全管控中心（Runtime Security Control Center）
**定位**：运行时安全的统一管控中枢，负责策略管理、规则配置、模型调度、全局风控
- **策略管理模块**：安全策略的全生命周期管理，包括编写、测试、灰度、发布、回滚
- **规则引擎**：可配置化的安全规则引擎，支持灵活编排检测逻辑与处置逻辑
- **风控中心**：全局风险策略、风控模型、黑白名单的统一管理
- **配置下发模块**：策略、规则、配置的精准下发与状态同步
- **效果运营模块**：防护效果统计、误报分析、规则优化建议

### 5.2 Agent安全Sidecar
**定位**：与Agent实例一一对应旁路部署的轻量安全探针，是最贴近Agent的执行点
- **流量劫持模块**：透明劫持Agent的输入、输出、工具调用流量，无侵入接入
- **本地规则执行器**：加载高频基础规则，执行低开销快速检测
- **上下文管理器**：维护当前会话的完整上下文，为检测提供上下文支撑
- **处置执行模块**：执行拦截、告警、脱敏等处置动作
- **本地日志缓存**：安全日志本地缓存，异步上报，不阻塞主链路

### 5.3 工具安全网关（Tool Security Gateway）
**定位**：所有工具调用的统一入口与安全校验节点，是工具侧防护的核心执行点
- **身份认证模块**：双向TLS认证 + 身份令牌校验，验证调用方合法性
- **权限校验引擎**：基于ABAC的细粒度权限评估，支持多维度动态鉴权
- **参数校验模块**：参数格式、范围、内容的白名单校验与语义校验
- **流量控制模块**：限流、熔断、降级、配额管理
- **审计日志模块**：全量调用日志的结构化记录与脱敏存储

### 5.4 代码执行沙箱（Code Execution Sandbox）
**定位**：不可信代码与插件的隔离执行环境，防范恶意代码执行风险
- **隔离运行引擎**：提供多层级隔离执行环境，支持gVisor、Kata、Firecracker等多种技术
- **资源管控模块**：CPU、内存、磁盘、网络带宽的精细化配额限制
- **系统调用拦截**：基于Seccomp/BPF的系统调用白名单管控
- **文件系统隔离**：只读根文件系统 + 临时可写目录，隔离持久化存储
- **网络访问控制**：网络白名单管控，禁止未授权的外部访问

### 5.5 记忆安全代理（Memory Security Proxy）
**定位**：Agent记忆读写的中间代理层，实现记忆数据的安全管控
- **写入校验模块**：记忆写入内容的安全检测与合规校验
- **读取鉴权模块**：记忆读取的身份验证与权限校验
- **数据脱敏模块**：敏感记忆数据的动态脱敏
- **污染检测模块**：记忆内容的异常检测与污染识别

### 5.6 AI安全检测引擎集群
**定位**：语义级安全检测的算力底座，提供AI原生攻击的深度检测能力
- **提示注入检测模型**：识别直接/间接、显式/隐式的提示注入攻击
- **越狱检测模型**：识别角色扮演、逻辑诱导、多轮绕过等越狱行为
- **内容安全模型**：多维度语义级内容合规检测
- **敏感信息识别模型**：语义级敏感数据识别，支持非结构化数据
- **模型调度框架**：多模型路由、批量推理、弹性伸缩、负载均衡

## 6. 数据流
### 6.1 正常业务请求运行时防护数据流
1. **输入接入**：用户请求到达Agent实例前，先经过安全Sidecar，Sidecar提取输入内容与上下文，执行基础规则检测，同步调用AI安全检测引擎做深度语义检测
2. **规划校验**：Agent生成任务规划与思考链后，Sidecar对规划路径进行一致性校验与风险评估，高风险规划直接拦截并要求Agent重新规划
3. **工具调用**：Agent发起工具调用请求，Sidecar做预校验后转发至工具安全网关；网关完成身份鉴权、权限校验、参数校验、限流控制后，转发至后端工具服务
4. **结果返回**：工具返回结果经过网关时做内容安全初检，再回到Sidecar做二次校验，防范返回结果中的隐藏指令与恶意内容
5. **输出审核**：Agent生成最终输出后，Sidecar执行输出内容合规检测、敏感信息脱敏、反泄露校验
6. **结果交付**：校验通过的结果返回给用户，全链路安全日志异步上报至管控中心与审计系统
7. **记忆更新**：Agent写入记忆时，请求经过记忆安全代理，完成内容校验与权限校验后写入记忆存储

### 6.2 高风险事件处置数据流
1. **检测触发**：Sidecar、网关或检测引擎识别到高风险行为，立即生成风险事件，携带上下文、证据数据上报至管控中心
2. **风险研判**：动态风险决策引擎联动身份、权限、历史行为数据进行综合研判，确认风险等级与攻击类型
3. **指令下发**：根据风险等级生成处置指令，通过管控中心下发至对应执行点
4. **实时处置**：执行点接收指令后执行对应动作：拦截当前请求、冻结Agent权限、终止会话、触发人工审核
5. **事件归档**：处置结果、完整证据链、上下文数据归档至安全运营平台，生成事件工单
6. **规则反馈**：事件处置结果反馈至检测模型与规则引擎，用于模型迭代与规则优化

### 6.3 代码执行场景数据流
1. **代码提交**：Agent生成可执行代码或调用第三方插件，请求提交至代码执行沙箱
2. **静态扫描**：沙箱入口先对代码进行静态安全扫描，识别已知恶意代码与高危依赖
3. **隔离执行**：扫描通过后，在隔离环境中加载代码，分配限定资源，启动执行
4. **运行时监控**：执行过程中实时监控系统调用、文件访问、网络访问、资源占用
5. **结果返回**：执行完成后，清理运行环境，返回执行结果；异常行为直接终止执行并上报风险
6. **环境销毁**：执行结束后立即销毁沙箱实例，无残留数据

## 7. 控制流
### 7.1 安全策略下发控制流
1. 安全运营人员在管控中心完成策略规则的编写、自动化测试与审批
2. 管控中心生成策略版本，按灰度策略分批下发至各类执行点（Sidecar、网关、沙箱、代理）
3. 执行点加载新策略，验证生效后回执状态至管控中心
4. 灰度期间管控中心实时监控误报率、拦截率、业务错误率等指标
5. 灰度验证通过后全量发布；出现异常则自动回滚至上一稳定版本

### 7.2 检测模型迭代控制流
1. 安全算法团队基于新攻击样本、误报漏报数据训练优化检测模型
2. 模型版本提交至管控中心，在影子模式下并行运行，不实际拦截
3. 管控中心对比新模型与线上模型的检测结果，评估准确率、召回率、性能指标
4. 评估通过后按比例灰度切流，逐步替换旧模型
5. 全量上线后持续监控效果，形成「数据-训练-上线-反馈」的闭环迭代

### 7.3 动态风控指令控制流
1. 风控中心基于全局风险态势、专项攻击事件生成动态风控指令
2. 指令通过管控中心实时下发至所有执行点，即时生效
3. 执行点按指令调整检测强度、拦截阈值、权限范围
4. 风控周期结束后自动恢复原有策略，全程自动执行无需人工干预

## 8. 接口设计
### 8.1 数据面执行接口
| 接口名称 | 交互双方 | 协议 | 核心能力 |
|----------|----------|------|----------|
| 输入检测接口 | Sidecar → 检测引擎 | gRPC | 提交输入内容，返回检测结果与风险等级 |
| 工具调用鉴权接口 | 工具网关 → 权限引擎 | gRPC | 提交身份+操作+参数，返回鉴权结果 |
| 代码提交接口 | Agent → 沙箱引擎 | RESTful | 提交代码与执行参数，返回执行结果 |
| 记忆读写接口 | Agent → 记忆安全代理 | gRPC | 记忆读写请求，返回校验后的数据 |
| 输出审核接口 | Sidecar → 检测引擎 | gRPC | 提交输出内容，返回审核结果与脱敏后内容 |

### 8.2 控制面管控接口
| 接口名称 | 交互双方 | 协议 | 核心能力 |
|----------|----------|------|----------|
| 策略下发接口 | 管控中心 → 各执行点 | gRPC + Stream | 策略配置下发、增量更新、状态回执 |
| 事件上报接口 | 各执行点 → 管控中心 | Kafka | 安全事件、审计日志、指标数据异步上报 |
| 处置指令接口 | 管控中心 → 各执行点 | gRPC | 实时拦截、冻结、降级等处置指令下发 |
| 配置同步接口 | 管控中心 → 各执行点 | HTTP/2 | 基础配置、黑白名单、风控规则同步 |

### 8.3 接口设计规范
- 所有接口强制携带全局Trace ID，实现全链路关联追溯
- 安全检测接口支持超时配置，超时自动降级放行，避免阻塞业务
- 核心接口支持批量调用，提升高并发场景下的吞吐性能
- 所有控制面接口双向认证，加密传输，防篡改防重放

## 9. 核心安全机制
### 9.1 分层式提示注入防护体系
构建「规则过滤 + 特征匹配 + 语义检测 + 一致性校验」四层检测体系，覆盖直接注入、间接注入、多模态注入等多种攻击形态：
1. **规则层**：基于正则、关键词、特征指纹快速拦截已知攻击模式，开销极低，覆盖80%以上的已知攻击
2. **特征层**：基于攻击样本提取的统计特征与结构特征，识别变种攻击
3. **语义层**：基于大语言模型的语义理解能力，识别无明显特征的隐式注入、逻辑诱导
4. **一致性层**：校验Agent执行结果与原始用户意图的一致性，从结果侧验证是否被注入篡改

针对间接注入（RAG文档、工具返回、图片OCR等），在所有外部数据进入Agent上下文前统一经过检测节点，实现全输入源覆盖。

### 9.2 细粒度工具权限管控机制
采用ABAC（基于属性的访问控制）模型，实现四层级精细化权限控制：
1. **工具级**：控制Agent是否有权调用某一工具
2. **操作级**：控制Agent可调用工具下的具体接口与动作（如只读/读写）
3. **参数级**：控制接口参数的取值范围、格式、白名单，防范参数注入与越权操作
4. **数据级**：控制工具返回数据的字段范围，敏感字段自动脱敏

权限决策同时关联五大属性维度：用户身份属性、Agent身份属性、任务场景属性、环境风险属性、时间频次属性，实现动态自适应授权，而非静态角色绑定。所有权限单次有效，无持久授权。

### 9.3 多层级沙箱隔离机制
针对不同风险等级的代码与插件，提供三级隔离方案，企业可按需选择：
| 隔离级别 | 技术方案 | 隔离强度 | 性能损耗 | 适用场景 |
|----------|----------|----------|----------|----------|
| L1 轻量隔离 | 容器 + Seccomp + 命名空间 | 中 | 5%以内 | 可信内部插件、低风险代码 |
| L2 标准隔离 | gVisor / Kata Containers | 高 | 10%-15% | 第三方插件、通用代码执行 |
| L3 强隔离 | Firecracker 微虚拟机 | 极高 | 20%-30% | 高风险不可信代码、未知来源插件 |

所有级别均配套系统调用白名单、文件系统只读、网络白名单、资源配额管控，形成纵深隔离体系。沙箱实例一次性使用，执行结束立即销毁，无环境复用。

### 9.4 上下文感知动态风控机制
基于会话全量上下文、历史行为基线、实时风险态势构建动态风险评分体系，避免单条指令的误判：
- **上下文维度**：对话主题、历史指令、任务目标、当前执行阶段
- **行为维度**：用户历史行为、Agent常规操作模式、工具调用频次基线
- **环境维度**：当前全局威胁态势、专项攻击预警、账号风险等级
- **处置分级**：低风险放行、中风险告警、高风险拦截、极高风险终止会话并冻结权限

风险评分随对话进程动态更新，渐进式攻击可通过累积风险值触发拦截，避免单轮绕过。

### 9.5 语义级输出反泄露机制
突破传统正则匹配的局限，采用语义理解技术实现精准数据防泄露：
- 支持非结构化文本中的敏感信息识别，包括自然语言描述的业务数据、代码、凭证、内部文档内容
- 支持上下文关联判断，识别碎片化拼接的敏感信息泄露
- 提供分级脱敏能力：替换、掩码、删除、泛化，适配不同场景需求
- 支持自定义敏感实体类型，企业可基于自身业务定义专属敏感数据范畴

### 9.6 记忆投毒防护机制
针对记忆持久化特性构建三重防护：
1. **写入前校验**：所有写入记忆的内容必须经过安全检测与可信度评估，恶意、错误、高偏差内容禁止写入
2. **存储中隔离**：不同租户、不同用户、不同安全级别的记忆数据物理/逻辑隔离，禁止跨权限读取
3. **定期巡检**：后台巡检任务定期扫描记忆数据，识别已污染内容，自动清理或标记风险
4. **有效期管理**：为记忆设置自动过期机制，降低污染内容的长期影响

## 10. AI能力协同
### 10.1 双模型并行检测架构
- **业务模型**：负责Agent任务推理与规划，聚焦业务效果，运行在业务资源池
- **安全模型**：独立部署的安全专用模型集群，聚焦攻击检测，运行在独立安全资源池
- 两者并行运行：主链路业务模型推理的同时，安全模型异步/并行执行检测，关键路径串行校验，非关键路径旁路检测，兼顾安全与性能

### 10.2 对抗性检测能力迭代
- 建立红蓝对抗机制，红队持续生成新型攻击样本，蓝队基于样本优化检测模型
- 检测模型采用多模型集成方案，不同架构、不同训练方式的模型组合判定，降低被单一绕过的概率
- 支持对抗样本训练，定期用最新攻击手法强化检测模型的鲁棒性
- 建立攻击样本库，持续积累企业内部与行业公开的攻击样本，驱动模型迭代

### 10.3 安全Agent辅助研判
部署专属安全Agent，辅助安全运营人员进行事件研判与处置：
- 自动关联分析安全事件的全链路上下文，还原攻击路径
- 自动生成事件分析报告与处置建议
- 辅助进行规则调优与策略生成
- 自动执行复盘分析与防护效果评估

安全Agent与业务Agent物理隔离，仅访问安全域数据，纳入更严格的安全管控。

## 11. 高可用设计
### 11.1 执行层高可用
- **安全Sidecar**：Sidecar故障时自动旁路，流量直接透传，业务无感知；日志本地缓存，恢复后补报
- **工具安全网关**：集群化部署，多实例负载均衡，单节点故障自动摘除；支持跨AZ多活部署
- **检测引擎集群**：无状态化设计，水平扩展；多模型路由，单模型故障自动降级为备用模型
- **沙箱引擎**：弹性池化管理，实例故障自动销毁重建；任务自动重试，用户无感知

### 11.2 管控层高可用
- 管控中心多副本部署，跨AZ分布，数据层多副本同步
- 配置数据多副本存储，支持本地缓存，管控中心故障时执行点本地缓存策略继续运行
- 策略下发支持断点续传与增量更新，网络中断不影响已下发策略的正常运行

### 11.3 多级降级机制
| 降级级别 | 触发条件 | 降级动作 | 业务影响 |
|----------|----------|----------|----------|
| L1 轻度降级 | 检测引擎负载过高 | 关闭深度语义检测，保留规则与特征层检测 | 防护强度略有下降，性能恢复 |
| L2 中度降级 | 管控中心故障或网络中断 | 执行点使用本地缓存策略运行，日志本地留存 | 策略无法更新，功能正常 |
| L3 重度降级 | 安全组件大面积异常 | 所有安全校验旁路，流量透传，全量日志留存 | 实时防护暂停，事后审计补漏 |

降级自动触发，自动恢复，无需人工干预；所有降级操作全程审计可追溯。

### 11.4 限流与熔断
- 执行点多级限流：按实例、按租户、按Agent、按接口多级限流，防止流量冲击
- 下游依赖熔断：检测引擎、权限服务等依赖故障时自动熔断，快速失败，避免级联阻塞
- 熔断后自动恢复：按时间窗口试探恢复，逐步放量，避免故障重试风暴

## 16. 优缺点分析
### 16.1 架构优势
1. **防护全面**：覆盖Agent运行全链路，针对AI原生攻击做专项设计，弥补传统安全方案的盲区
2. **无侵入接入**：Sidecar+网关+代理的旁路模式，无需修改Agent业务代码，接入成本低
3. **精细可控**：多级粒度权限管控、分级防护、动态风控，平衡安全与业务灵活性
4. **高可用保障**：多级降级、故障旁路、集群部署，安全组件故障不影响业务可用性
5. **弹性扩展**：全组件无状态化设计，支持水平扩展，适配企业规模化部署
6. **可迭代性强**：检测模型、安全规则、策略独立迭代，不影响业务Agent发布节奏

### 16.2 架构局限
1. **性能开销**：多层安全校验与语义检测带来一定的延迟与资源开销，极致性能场景需优化
2. **误报挑战**：语义级检测存在一定误报率，需要针对企业业务场景持续调优
3. **复杂场景适配**：多Agent深度协作、长周期任务等复杂场景下，上下文风控的准确率仍有提升空间
4. **运维复杂度**：组件较多，需要专业团队进行策略运营、模型调优、效果分析
5. **对抗性风险**：针对检测模型的对抗性攻击持续演进，需要持续跟进更新防护能力

## 17. 企业最佳实践
### 17.1 分级防护落地策略
- 按业务场景风险等级匹配防护级别：核心生产场景启用全量四层检测+强隔离；内部办公场景启用标准防护；探索创新场景启用轻量化防护
- 按数据敏感级调整输出脱敏强度与工具权限范围
- 新上线Agent先在观察模式运行一周，统计误报漏报，调优策略后再进入拦截模式

### 17.2 Sidecar部署最佳实践
- 优先基于企业现有服务网格体系扩展安全能力，避免重复建设Sidecar基础设施
- 核心检测逻辑下沉，Sidecar仅执行规则层与快速校验，深度检测调用远端引擎，降低Sidecar资源占用
- Sidecar资源配额严格限制，避免安全组件抢占业务资源

### 17.3 工具网关接入规范
- 所有工具接入必须经过统一安全网关，禁止直连
- 工具接入前完成安全评审，定义清晰的权限粒度与参数白名单
- 高危工具强制开启二次审批与操作审计
- 定期审计工具权限，及时回收冗余权限

### 17.4 误报优化方法论
- 建立业务申诉快速响应通道，24小时内处理误报申诉
- 基于申诉样本持续优化检测规则与模型
- 针对企业内部业务术语、专有名词训练定制化检测模型，降低误报
- 建立误报率核心指标，纳入安全团队KPI，持续优化

### 17.5 性能调优建议
- 常用检测结果缓存，重复内容无需重复检测
- 低风险内容走快速通道，跳过深度检测
- 检测引擎批量推理，提升吞吐降低单请求耗时
- 非关键审计、日志、分析全异步化，不阻塞主链路
