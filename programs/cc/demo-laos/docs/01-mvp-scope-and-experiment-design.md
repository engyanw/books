# 01 MVP 范围与实验设计

> 对应任务 #1（Phase0 MVP领域边界与实验设计）。本文件锁定第一版最小可验证闭环的范围、被试、基线与验收口径。

## 1. 设计原则

不在第一版做整个高中语文。先在一个**知识结构清晰、可客观评分、易构造 Q 矩阵、可做迁移测试**的领域，把"诊断 → 决策 → 干预 → 再测 → 状态更新"完整跑通。

## 2. MVP 领域边界：文言文阅读

### 2.1 纳入范围

```
文言文阅读
 ├── 实词（语境义判断）
 ├── 虚词（辨析）
 ├── 句式（判断/翻译）
 ├── 特殊用法
 ├── 句意理解
 ├── 信息筛选
 ├── 内容概括
 ├── 推断
 └── 迁移（陌生文本）
```

### 2.2 排除范围（第一版不做）

- 全部现代文阅读
- 全部作文
- 全部古诗词鉴赏
- 全部高中语文知识点

> 闭环跑通前不得扩展。扩展需以 MVP 验收（任务 #30）通过为前提。

## 3. 知识节点规模

- 第一版知识节点：**约 100 个**（实词义项、虚词用法、句式类型等）
- 题目：**300~500 道**高质量标注题
- 被试：**50~100 名**真实高中学生（先小后大，见 §4）

## 4. 实验组设计

### 4.1 被试分层

建议 100~300 名，分 5 水平层：

```
高水平 / 中高水平 / 中水平 / 中低水平 / 低水平
```

分层依据：最近一次校/区统考语文成绩 + 文言文专项成绩。

### 4.2 分组

| 组别 | 用途 | 规模建议 |
| --- | --- | --- |
| 实验组 | 接受系统诊断+干预 | ≥ 主体 |
| 对照组 | 随机练题（Decision Quality 验收用） | 与实验组可比 |
| 预测试组 | 题目参数估计、Q 矩阵验证 | 50~100 |

> Decision Quality 验收（任务 #30）要求 Treatment vs Control，故对照组须与实验组在水平层上匹配。

## 5. 基线（Baseline）对比

见任务 #2 / `02-baseline-comparison-framework.md`。五条基线：

- Baseline A：单纯正确率
- Baseline B：正确率 + 知识标签
- Baseline C：IRT
- Baseline D：DINA/GDINA
- Baseline E：本系统（概率认知图 + CDM + IRT + Evidence）

后续所有技术提升须与基线比较，不得只与本系统历史版本比。

## 6. 闭环定义

第一版必须稳定运行的最小链：

```
学生
 ↓
10~20 道诊断题
 ↓
Evidence
 ↓
CDM
 ↓
Student State
 ↓
找到 Top 3 认知缺口
 ↓
生成 7 天学习任务
 ↓
完成训练
 ↓
迁移测试
 ↓
更新 Student State
 ↓
成长报告
```

若此链不能稳定运行，不扩展系统。

## 7. 验收口径

以任务 #30 的五项为准：Measurement Validity / Diagnostic Validity / Adaptive Efficiency / Learning Effect / Decision Quality。本文件不重复，见 `TODO-研发任务跟踪.md` §四。

## 8. 伦理与合规约束（来自 V2.2 §35 风险8）

- 未成年人须监护人同意
- 数据最小化、去标识化
- 云 LLM 调用脱敏，禁可识别信息出境
- 学生可申诉诊断结论并人工复核
