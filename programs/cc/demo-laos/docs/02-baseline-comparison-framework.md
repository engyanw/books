# 02 Baseline 对比框架

> 对应任务 #2（Phase0 五个Baseline对比框架）。定义五条基线的方法、输入输出、评测指标与对比协议，确保后续技术提升可被客观比较。

## 1. 目的

任何认知诊断/学习决策的改进，都必须相对固定基线证明增益，禁止只与本系统历史版本自比。

## 2. 五条基线

| 基线 | 方法 | 输入 | 输出 | 定位 |
| --- | --- | --- | --- | --- |
| A | 单纯正确率 | 作答对错 | 正确率 | 最弱参照 |
| B | 正确率 + 知识标签 | 作答 + 题目知识标签 | 分知识点正确率 | 常见"刷题工具"水平 |
| C | IRT | 作答 | 单维 θ + 题目参数 | 测量学经典 |
| D | DINA/GDINA | 作答 + Q 矩阵 | 属性掌握概率 | 认知诊断经典 |
| E | 本系统 | 作答 + Evidence + CDM + IRT + 融合 | 概率状态 + 不确定性 + 证据链 | 目标系统 |

## 3. 对比协议

### 3.1 同题量、同被试

所有基线在**相同题目集合、相同被试**上运行，唯一变量是方法。

### 3.2 留一/外部锚定

诊断有效性用**留一交叉验证** + **外部锚题**评估，不得用训练题自证。

### 3.3 指标

| 维度 | 指标 | 适用基线 |
| --- | --- | --- |
| 预测效度 | AUC / F1 / Precision / Recall | A-E |
| 校准度 | 预测概率 vs 实际表现（Brier Score / 可靠性曲线） | A-E |
| 诊断准确性 | 与专家判断一致率 | D, E |
| 测评效率 | 达精度所需题量 / 时间 | C, D, E |
| 状态稳定性 | Test-Retest 一致性 | C, D, E |

> AUC 不作为唯一指标。诊断类（D/E）须额外看校准度与专家一致性。

## 4. 实现要求

- 每条基线封装为独立服务/脚本，输入统一 Evidence，输出统一结果格式。
- 评测脚本固定，结果写入对比表（含模型版本、题版本、被试版本）。
- 基线版本化：A-E 各自打版本号，复现实验时锁定版本。

## 5. 对比表模板

```text
方法版本 | 题版本 | 被试N | AUC | F1 | Calibration | 诊断准确率 | 题量 | 时间
A_v1     | QM_v1  | n    |     |    |             |            |      |
B_v1     | ...
C_v1     | ...
D_v1     | ...
E_v1     | ...
```

## 6. 通过门槛（示例，待校准）

- E 相对 D：诊断准确率提升 ≥ 5 个百分点，且校准度不劣化。
- E 相对 C：达同等诊断精度所需题量减少 ≥ 20%。
- 以上阈值为待校准参数（V2.2 §5.1），非理论常数，须大样本实证确定。
