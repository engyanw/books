## 1. 环境要求

- **Python ≥ 3.10**（用了 `dataclass`、`enum`、`typing` 联合类型 `X | None`、`from __future__ import annotations`）。
- **零第三方依赖**：核心包全部用 Python 标准库（`math`/`random`/`hashlib`/`itertools`/`dataclasses`/`enum`/`datetime`/`collections`）。无需 `pip install`，无需 `numpy`/`scipy`。
- 无需编译、无需数据库：当前为**内存实现**（`repository/` 为内存仓储），`schemas/ddl.sql` 仅作为将来接 PostgreSQL 的预留 DDL。
- 可选：`psql` + PostgreSQL（仅在将来把内存仓储替换为持久化仓储时需要）。

快速自检：

```bash
python3 --version          # 应 ≥ 3.10
python3 -c "import math,random,hashlib; print('stdlib OK')"
```

**数据流主链**（V2.2 §6 闭环）：

```
学生作答 → Evidence(schemas/evidence) → AssessmentEngine 写状态
  → FusionUpdater(DINA+IRT+遗忘先验) → StudentCognitiveState(schemas/state)
  → AdaptiveEngine 选题 / LearningDecisionEngine 决策 / TutorAgent 只读编排
  → 训练产生新 Evidence → 再测 → 迁移验证 → 成长报告
```

写权限边界（V2.2 §20）：`StudentCognitiveState` 的写路径**仅 `AssessmentEngine`**；
`TutorAgent` 只读，越权写抛 `AgentPermissionError`。

## 3. 三种启动方式

### 方式 ① 一键端到端演示（最快上手）

```bash
python3 run_demo.py
```

依次运行：MVP 闭环 → 四组核心实验 → Baseline A–E 对比 → 五项验收，
末尾打印合成数据下的总验收结论。约 30–60 秒。

### 方式 ② 跑最小闭环

```bash
# 直接运行模块
python3 -m mvp.closed_loop
# 或在代码中调用
python3 -c "from mvp.closed_loop import run_closed_loop; print(run_closed_loop().summary())"
```

输出某合成学生的：诊断题量、Top3 认知缺口、学习动作、干预前后掌握度、增益、迁移确认。

## 4. 在自己代码里用各引擎（最小示例）

```python
from repository import ItemRepository, EvidenceRepository, StateRepository
from assessment import AssessmentEngine
from fusion.updater import FusionUpdater
from governance.privacy import PrivacyGuard, AuditChain
from schemas.evidence import Evidence, EvidenceLevel, EvidenceSource

# 1) 组装组件
item_repo = ItemRepository()          # 题库（需先 put_item 注入题）
ev_repo   = EvidenceRepository()
state_repo = StateRepository()

# 2) 带治理的引擎：写/读/导出全落审计链、假名化
guard = PrivacyGuard(AuditChain(), salt="your-salt")
engine = AssessmentEngine(
    state_repo, ev_repo,
    updater=FusionUpdater(item_repo, irt_items=[]),   # 融合更新器
    governance=guard,                                  # 可选；不传则不审计
)

# 3) 采证 + 更新状态（唯一写路径）
ev = Evidence(id="E1", student_id="S1", item_id="I1", item_version="v1",
              score=1.0, source=EvidenceSource.DIRECT_ANSWER,
              evidence_level=EvidenceLevel.C)
engine.ingest_evidence(ev)
state = engine.update_state("S1", "K-实词义项", "v1", "文言文阅读", [ev])

# 4) Agent 只读
from tutor.agent import TutorAgent
agent = TutorAgent(assessment_engine=engine)
print(agent.explain_gap(state))        # 读，不写
# agent.update_mastery(...)           # 抛 AgentPermissionError

# 5) 导出给云 LLM（自动去标识化 + 落 export 审计）
print(engine.export_for_llm("S1", "K-实词义项"))
print("审计链完整:", guard.audit.verify())
```

关键约束：
- `state_repo.put()` 技术上公开，但**唯一 sanctioned 写路径是 `engine.update_state`**；真实部署在 service 边界强制。
- `export_for_llm` 返回的快照中 `student` 已假名化（`p:…` / `h:…`），不含原始姓名。

## 6. 常见问题

**Q: 报 `ModuleNotFoundError: No module named 'mvp'`?**
A: 必须在仓库根目录 `demo-laos/` 下运行，或 `export PYTHONPATH=$(pwd)`。包名即目录名。

**Q: `python3 -m mvp.closed_loop` 有 RuntimeWarning?**
A: 是 runpy 的包/模块加载顺序告警，不影响结果。用 `python3 -c "from mvp.closed_loop import run_closed_loop; run_closed_loop()"` 可消除。

**Q: 跑测试时个别断言失败?**
A: 合成数据带随机性，个别指标（如 AUC）波动正常。全量 13 套件在本机已验证通过；
若某套件偶发失败，重跑一次即可（`run_acceptance`/`run_baseline_comparison` 用固定 seed，应稳定）。

**Q: 要接真实数据库?**
A: `schemas/ddl.sql` 已备表结构；将 `repository/*_repo.py` 的内存 dict 换成 PostgreSQL 适配器即可，接口不变。

**Q: 要接真实题库?**
A: 见 `mvp/closed_loop.py` 的 `build_item_bank()` —— 它是合成题库的注入模板；
真实题按 `schemas/item.py` 的 `Item` 结构 `put_item` 即可。大规模真实标注属任务 #14，需教研专家。
