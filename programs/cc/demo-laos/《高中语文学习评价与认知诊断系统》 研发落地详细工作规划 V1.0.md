# 《高中语文学习评价与认知诊断系统》

# 研发落地详细工作规划 V1.0

## 一、总体研发目标

本项目不是传统的“AI题库 + AI答题 + AI批改”系统，而是建设一个：

> **以学生认知状态为核心，以可验证学习证据为基础，以测量模型为引擎，以诊断决策为核心，以干预和迁移验证形成闭环的 Learning Assessment OS。**

最终形成：

```text
课程标准 / 高考要求 / 学习目标
            ↓
      学习评价标准体系
            ↓
      语文认知知识图谱
            ↓
        题目与证据
            ↓
      学生认知状态估计
            ↓
       认知诊断引擎
            ↓
       学习优先级决策
            ↓
      个性化学习干预
            ↓
       再测 / 迁移测试
            ↓
      学习效果验证
            ↓
       更新认知状态
            ↺
```

研发的第一目标不是功能数量，而是：

> **首先用一个足够小的真实场景，把“诊断 → 决策 → 干预 → 再测 → 状态更新”完整跑通。**

---

# 二、总体研发原则

## 2.1 先建立测量系统，再建立AI系统

整个项目必须避免：

```text
LLM
 ↓
分析学生
 ↓
生成结论
```

而采用：

```text
标准
 ↓
测量模型
 ↓
证据
 ↓
概率状态
 ↓
决策
 ↓
LLM负责解释和执行
```

LLM/Agent属于：

> **Content Orchestration Layer**

而不是：

> **Assessment Authority**

---

# 三、研发阶段总览

建议分成 **9个阶段、约9～12个月**：

| 阶段      |    时间 | 核心目标          |
| ------- | ----: | ------------- |
| Phase 0 |    2周 | 项目定义与实验设计     |
| Phase 1 |    4周 | 标准体系与认知本体     |
| Phase 2 |  4～6周 | 数据模型与证据体系     |
| Phase 3 |  6～8周 | 题库与测量系统       |
| Phase 4 |  6～8周 | 认知诊断引擎        |
| Phase 5 |  4～6周 | 自适应测评         |
| Phase 6 |  4～6周 | 学习决策与AI Tutor |
| Phase 7 |  6～8周 | 迁移验证与闭环       |

其中：

> **Phase 1～4决定系统技术壁垒。**

> **Phase 5～7决定系统是否真正有效。**

> **Phase 8决定能否产品化。**

# 四、Phase 0：项目定义与实验设计

## 时间

2周。

## 目标

不要一开始做整个高中语文。

首先确定：

> **一个最小可验证认知领域。**

推荐第一阶段选择：

### 文言文阅读

原因：

* 知识结构相对清晰
* 题型成熟
* 认知层级明显
* 易于构造Q-matrix
* 容易做迁移测试
* 容易获得客观评分
* 适合验证CDM + IRT
* 与高考存在明确关联

---

## 4.1 MVP边界

第一版只做：

```text
文言文阅读
    ↓
实词
虚词
句式
特殊用法
句意理解
信息筛选
内容概括
推断
迁移
```

不要同时做：

* 全部现代文
* 全部作文
* 全部古诗词
* 全部高中知识点

---

## 4.2 建立实验组

至少准备：

### 学生

建议：

> 100～300名真实高中学生

最好分：

```text
高水平
中高水平
中水平
中低水平
低水平
```

---

## 4.3 建立Baseline

第一轮必须建立传统方法Baseline：

```text
Baseline A
单纯正确率

Baseline B
正确率 + 知识标签

Baseline C
IRT

Baseline D
DINA/GDINA

Baseline E
本系统
概率认知图 + CDM + IRT + Evidence
```

后续所有技术提升都必须和Baseline比较。

# 五、Phase 1：建立标准体系

## 时间

4周。

这是整个项目最重要的基础工程之一。

---

# 5.1 建立Standard Ontology

建立：

```text
Curriculum Standard
        ↓
Academic Quality
        ↓
Assessment Requirement
        ↓
Task Capability
        ↓
Cognitive Process
        ↓
Knowledge
```

建议建立标准对象：

```yaml
Standard:
  id:
  source:
  version:
  grade:
  subject:
  requirement:
  capability:
  evidence_requirement:
  assessment_rule:
```

---

# 5.2 建立四层认知模型

最终形成：

```text
L4 Core Literacy
       ↑
L3 Task Capability
       ↑
L2 Cognitive Process
       ↑
L1 Knowledge
```

例如：

```text
语言建构与运用
        ↑
文言文阅读
        ↑
理解 / 分析 / 推断
        ↑
虚词“之”
        ↑
具体用法
```

---

# 5.3 明确五类任务能力

建立：

```text
CA01 文言文阅读
CA02 现代文阅读
CA03 古诗词鉴赏
CA04 写作
CA05 综合语言运用
```

然后建立：

```text
Task Capability
       ↕
Core Literacy
```

映射矩阵。

不能简单定义：

> 一个任务能力 = 一个核心素养。

而应该允许：

```text
CA01
 ├── Language
 ├── Thinking
 └── Culture
```

# 六、Phase 2：建立数据与证据模型

## 时间

4～6周。

这是后续所有算法的基础。

---

# 6.1 建立Evidence Schema

系统中的核心对象不是“成绩”，而是：

> **Evidence**

例如：

```json
{
  "student_id": "S001",
  "item_id": "ITEM001",
  "item_version": "V3",
  "response": "B",
  "score": 1,
  "response_time": 18.2,
  "hint_used": false,
  "attempt": 1,
  "assessment_id": "A001",
  "rubric_version": "R2",
  "model_version": "CDM_1.0",
  "timestamp": "...",
  "source": "formal_assessment"
}
```

---

# 6.2 Evidence分层

建议：

### Level 1：直接证据

```text
答案
评分
作文文本
口头回答
```

### Level 2：行为证据

```text
答题时间
修改次数
跳过
提示
重复错误
```

### Level 3：诊断证据

```text
probe
错误类型
认知过程
知识缺陷
迁移表现
```

### Level 4：外部锚点

```text
标准化考试
学校考试
教师评价
人工评分
```

---

# 6.3 建立Evidence Provenance

每一个认知状态必须能回答：

> “为什么系统认为这个学生掌握了这个知识？”

例如：

```text
知识：之-宾前标志

Mastery = 0.81

证据：
 ├─ Item 102 正确
 ├─ Item 109 正确
 ├─ Item 115 错误
 ├─ Probe 07 正确
 ├─ Transfer 03 正确
 └─ Anchor Test 02 正确
```

这会成为系统极重要的解释能力。

```text

```

```text

 ↓

Task:
 T01 文言文阅读

Literacy:
 L01 语言建构

```

形成：

```text
Item
 ↓
Knowledge
 ↓
Cognitive Process
 ↓
Task Capability
 ↓
Core Literacy
```

# 八、Phase 4：认知诊断引擎

## 时间

6～8周。

这是整个系统的核心算法层。

---

# 8.1 建立统一学生状态

不要直接把：

```text
知识掌握
应用
迁移
稳定性
遗忘
错误类型
置信度
```

全部当成同一级latent variable。

建议重构为：

## A. 核心认知状态

```text
Mastery
Application
Transfer
```

## B. 动态状态

```text
Stability
Forgetting Risk
```

## C. 诊断状态

```text
Error Distribution
Misconception
```

## D. 不确定性

```text
Posterior Uncertainty
Confidence
Evidence Count
```

---

# 8.2 建立CDM

第一阶段：

> DINA / GDINA

用于：

```text
知识掌握诊断
属性掌握概率
Q-matrix诊断
```

但不能简单：

```text
做对一道题
→ mastery + 0.1
```

而应该：

```text
Evidence
 ↓
Likelihood
 ↓
Posterior
 ↓
P(Mastery | Evidence)
```

---

# 8.3 建立IRT

IRT负责：

```text
总体能力
领域能力
题目参数
测试信息量
```

例如：

```text
θ_language
θ_reading
θ_writing
θ_classical
```

不要让IRT直接“修改知识图谱权重”。

两者通过：

```text
Evidence Layer
```

进行融合。

---

# 8.4 建立层级测量模型

最终结构：

```text
Core Literacy Ability
        ↓
Task Ability
        ↓
Cognitive Process
        ↓
Knowledge Mastery
        ↓
Item Response
```

形成：

> Hierarchical Cognitive Measurement Model

这是未来最值得投入的算法方向。

---

# 8.5 建立概率更新机制

每次获得Evidence：

```text
New Evidence
      ↓
Likelihood
      ↓
Posterior Update
      ↓
Student State
      ↓
Uncertainty Update
```

而不是：

```text
规则加减分
```

---

# 九、Phase 5：自适应诊断系统

## 时间

4～6周。

---

# 9.1 第一阶段不要做复杂Agent

先做确定性Adaptive Engine：

```text
当前状态
 ↓
候选题集合
 ↓
过滤
 ↓
计算Information Gain
 ↓
选择下一题
 ↓
获得Evidence
 ↓
更新状态
 ↓
继续
```

---

# 9.2 Information Gain

核心目标：

> 下一道题应该最大程度减少当前认知状态的不确定性。

可以使用：

```text
Expected Information Gain
```

例如：

```text
EIG(item)
=
H(State)
-
E[H(State | Response)]
```

---

# 9.3 加入约束

不能单纯追求信息增益。

最终优化：

```text
Maximize:
Information Gain

Subject To:
├─ 内容覆盖
├─ 难度约束
├─ 题型约束
├─ 曝光约束
├─ 测试长度
├─ 学生疲劳
├─ Q-matrix可识别性
└─ 高考蓝图约束
```

---

# 9.4 Diagnostic Probe

建立：

```text
Recall Probe
     ↓
Discrimination Probe
     ↓
Explanation Probe
```

用于区分：

```text
不知道
vs
知道但不会用
vs
会用但不稳定
vs
理解但迁移失败
```

Probe属于：

> Diagnostic Evidence

而不是简单混入正式考试分数。

---

# 十、Phase 6：学习决策与AI Tutor

## 时间

4～6周。

这一阶段才真正引入Agent。

---

# 10.1 建立Learning Decision Engine

输入：

```text
Student State
+
Learning Goal
+
Available Time
+
Item Pool
+
Content Resources
```

输出：

```text
Next Learning Action
```

例如：

```text
优先修复：
虚词“之”的语境辨析

原因：
Mastery = 0.72
Application = 0.48
Transfer = 0.31
Uncertainty = 0.18

预计收益：
High

建议：
解释 → 对比例题 → 迁移题
```

---

# 10.2 优先级模型

不要简单采用：

```text
gap × exam weight × confidence
```

建议升级成：

```text
Expected Learning Utility

=
Expected Gain
× Goal Value
× Transfer Value
+
Exploration Value
-
Learning Cost
-
Risk
```

其中：

```text
Expected Gain
```

由历史干预效果模型预测。

---

# 10.3 AI Tutor

Agent负责：

```text
知识检索
内容组织
解释
举例
反例
生成练习
生成微课
对话
学习提醒
```

但不负责：

```text
修改Mastery
修改Threshold
决定最终成绩
修改标准
决定学生是否达标
```

---

# 10.4 技术隔离

不能只依靠Prompt约束。

必须建立：

```text
Agent API
    ↓
Read Student State
    ↓
Read Knowledge
    ↓
Generate Learning Action
    ↓
Submit Action
```

而：

```text
Update Student State
Update Assessment Standard
Update Threshold
```

属于：

> Assessment Engine

Agent没有写权限。

```text
Diagnosis
 ↓
Intervention
 ↓
```


```text

+

+

+
迁移题
```

# 11.2 四层验证

### Level 1

### Level 2

Application

### Level 3

Transfer

### Level 4

形成：

```text

 ↓

 ↓

```

---

# 11.3 建立Retention Test

例如：

```text

Day 7
Day 30
```

```text
Retention
```

> Personalized Retention Model

# 11.4 干预效果评价

```text

Effect Size

Transfer Gain
```

如果条件允许：

```text
Treatment Group
vs

```

# 十九、MVP验收指标

第一版不追求“AI有多聪明”，而验证五件事情。

## 19.1 Measurement Validity

系统估计是否稳定：

```text
Test-Retest Reliability
Classification Consistency
Calibration
```

---

## 19.2 Diagnostic Validity

与教师/专家判断比较：

```text
Precision
Recall
F1
AUC
Calibration
```

AUC不能作为唯一指标。

---

## 19.3 Adaptive Efficiency

比较：

```text
固定20题
vs
自适应10～15题
```

是否在相近诊断精度下减少测试量。

---

## 19.4 Learning Effect

比较：

```text
Pre-Test
Post-Test
Retention
Transfer
```

---

## 19.5 Decision Quality

最重要的是：

> 系统推荐的学习动作是否真的比随机练题更有效。

因此最终需要：

```text
AI Personalized Intervention
vs
Random Practice
```

进行实验。

# 二十一、项目真正的技术核心

这个系统最终真正有壁垒的并不是：

```text
LLM
Agent
RAG
```

而是下面五层。

## 第一层：标准模型

```text
什么叫“会”
```

---

## 第二层：证据模型

```text
如何证明“会”
```

---

## 第三层：认知测量模型

```text
如何从有限证据推断“到底会到什么程度”
```

---

## 第四层：决策模型

```text
下一步最应该学什么
```

---

## 第五层：效果验证模型

```text
学完以后到底有没有真正变强
```

最终形成：

> **Standard → Evidence → Measurement → Decision → Intervention → Transfer**

这才是整个产品最核心的技术闭环。
