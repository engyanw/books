# PART XIV Body of Knowledge（知识体系 AIBOK）
本篇定义 AIAF 完整知识体系（Autonomous Intelligence Body of Knowledge, AIBOK），是整个框架的术语基准、概念本体、标准对齐与知识沉淀总集。AIBOK 为全框架提供统一的语言体系与认知基础，确保不同角色、不同组织在应用 AIAF 时具备一致的概念理解与语义对齐，同时建立 AIAF 与全球主流标准框架的映射关系，为跨体系协作、行业落地与生态建设提供知识底座。

AIBOK 遵循「统一语义、标准对齐、持续沉淀、开放共建」的核心原则，既是 AIAF 体系的入门索引，也是深度应用的参考依据，同时承载框架的版本演进与未来路线规划。

## 本篇目标
1. 建立全框架统一的术语体系、核心本体与分类标准，确保语义一致
2. 提供完整的标准缩写对照表，降低阅读与理解门槛
3. 构建 AIAF 与全球主流架构、安全、AI 标准的映射关系
4. 梳理理论基础、标准规范与实践参考的推荐阅读体系
5. 解答落地常见问题，明确版本演进路线与生态共建机制

### Chapter 107 知识体系总览

#### 107.1 体系定位
AIBOK 是 AIAF 整个架构框架的「知识索引与语义基准」，横向覆盖所有架构域与十三个组成部分，纵向贯穿从基础概念到行业落地的全层级内容。它不是独立的方法论模块，而是整个框架的公共知识底座，所有部分的概念、术语、本体均以 AIBOK 为准。

> **规范性要求**：AIAF 所有组成部分的术语定义、本体关系、分类标准 **MUST** 与 AIBOK 保持一致；任何扩展与定制化 **SHOULD** 优先复用 AIBOK 定义的核心概念，避免语义分歧。

#### 107.2 核心目标
1. **统一语言**：建立标准化的术语与概念体系，消除跨角色、跨组织、跨行业的沟通歧义
2. **对齐标准**：明确 AIAF 与全球主流架构、治理、安全、AI 标准的对应关系，降低跨体系协作成本
3. **沉淀知识**：系统梳理自治智能领域的理论、方法、实践知识，形成体系化的知识沉淀
4. **指引落地**：为初学者提供入门路径，为实践者提供参考资料与常见问题解答
5. **支撑演进**：明确版本演进路线与生态共建机制，保障框架的可持续发展

#### 107.3 知识体系组成结构
AIBOK 由八大知识模块组成，覆盖从基础语义到长期演进的完整维度：

| 模块 | 核心内容 | 主要作用 |
|------|----------|----------|
| 术语表（Glossary） | 全框架核心术语的标准定义 | 统一语言、消除歧义 |
| 核心本体（Ontology） | 核心概念的实体、属性与关系定义 | 对齐元模型、保障语义一致 |
| 分类法（Taxonomy） | 各领域的标准化分类体系 | 规范分类、支撑结构化管理 |
| 缩写对照表 | 全框架标准缩写与全称对应 | 降低阅读门槛 |
| 外部标准映射 | 与主流架构、安全、AI标准的对应关系 | 跨体系对齐、降低适配成本 |
| 推荐阅读 | 理论、标准、实践类参考资料 | 深度学习与拓展参考 |
| 常见问题（FAQ） | 认知、落地、对比类常见问题解答 | 快速解惑、规避误区 |
| 版本路线图 | 历史版本、当前版本、未来演进规划 | 明确发展方向、指引生态建设 |

#### 107.4 使用与更新原则
1. **权威性原则**：AIBOK 是 AIAF 术语与概念的唯一权威来源，冲突时以最新版 AIBOK 为准
2. **向后兼容原则**：版本更新优先扩展概念，尽可能保持核心术语的向后兼容
3. **开放贡献原则**：支持社区贡献术语补充、标准映射更新与问题增补，经评审后纳入正式版本
4. **场景扩展原则**：行业与场景扩展术语可在行业架构中定义，核心通用术语需纳入 AIBOK

### Chapter 108 术语表（Glossary）
本术语表按领域分类，定义 AIAF 全框架的核心术语，所有术语均为标准官方表述，使用时应遵循本定义。

#### 108.1 基础概念类
| 术语 | 标准定义 |
|------|----------|
| **自治智能（Autonomous Intelligence）** | 在目标与约束范围内，具备自主感知、决策、执行、反思与学习能力，可动态适应环境变化、持续优化自身行为的智能形态，是智能体技术发展的高阶阶段 |
| **自治企业（Autonomous Enterprise）** | 企业级全链路自治体系，业务、技术、治理、运营全维度实现智能自治，人机协同形成新型组织形态，是自治智能的组织级终极形态 |
| **群体智能（Collective Intelligence）** | 多个自治智能体通过协作、博弈、共识机制形成的群体能力，整体能力超越单一个体，具备涌现性与自组织特征 |
| **智能体（Agent）** | 具备自主感知、决策、执行能力，可独立完成特定任务的运行实体，是自治智能系统的基本执行单元 |
| **多智能体系统（Multi-Agent System）** | 由多个分工协作的智能体组成的系统，通过协同完成复杂任务，具备分布式、自组织、涌现性等特征 |
| **世界模型（World Model）** | 智能系统内部对外部环境与自身状态的表征与模拟，是认知、规划与预测的基础，决定系统的认知上限 |
| **主动推理（Active Inference）** | 基于自由能原理的认知理论，认为智能体所有行为本质是最小化预期与感知的差异，通过优化内部模型与主动探索降低不确定性 |

#### 108.3 治理安全类
| 术语 | 标准定义 |
|------|----------|
| **治理由设计内嵌（Governance by Design）** | 治理能力在架构设计阶段内置，而非事后叠加，治理规则与系统实现深度融合，实现全流程自动管控 |
| **默认可信（Trust by Default）** | 零信任原则在自治智能场景的延伸，默认不信任任何智能体、工具与交互，所有访问与操作均需持续验证 |
| **运行时安全（Runtime Safety）** | 在运行层面建立独立的安全管控机制，对决策执行前、中、后全链路校验，确保系统行为不超出安全边界 |
| **分级治理（Tiered Governance）** | 按业务场景风险等级匹配差异化治理强度，高风险强管控、低风险高效率，平衡安全与效率 |
| **人机共治（Human-AI Collaboration Governance）** | 人类拥有最终决策权与监督权，系统负责自动化执行与辅助判断，人机权责边界清晰，共同完成治理 |
| **提示注入（Prompt Injection）** | AI原生攻击方式，通过在输入或上下文中嵌入恶意指令，诱导模型绕过安全限制、执行非预期操作 |
| **记忆污染（Memory Poisoning）** | 向智能系统的记忆或知识体系注入虚假、恶意信息，扭曲系统认知，导致错误决策与行为 |
| **零信任架构（Zero Trust Architecture）** | 「永不信任、始终验证」的安全架构思想，无内外网边界之分，所有访问均需身份认证与权限校验 |

#### 108.4 运行与学习类
| 术语 | 标准定义 |
|------|----------|
| **MAPE-K** | 监控-分析-规划-执行-知识库，自主计算领域的经典自治参考模型 |
| **OODA循环** | 观察-调整-决策-行动，经典的决策闭环模型，自治系统运行的核心逻辑 |
| **运行时控制器（Runtime Controller）** | 运行时的调度中枢，负责全局任务调度、状态管理、异常流转与组件协同 |
| **运行时安全控制器（Runtime Safety Controller）** | 独立于业务逻辑的安全护栏，负责全链路安全校验、行为监控与分级熔断，具备最高干预优先级 |
| **反思引擎（Reflection Engine）** | 对执行过程与结果进行复盘分析，识别偏差、总结规律、提炼优化点的组件，是连接执行与学习的枢纽 |
| **持续学习（Continuous Learning）** | 系统从运行实践中持续迭代认知、优化策略、提升能力的过程，是自治系统区别于静态系统的核心特征 |
| **能力演进（Capability Evolution）** | 系统自治能力阶梯式升级的过程，从单任务优化到全局能力进化，逐步提升自治等级 |
| **灰度发布（Gray Release）** | 学习更新小流量逐步放量，验证效果后全量上线的发布机制，降低更新风险 |

#### 108.5 评估成熟度类
| 术语 | 标准定义 |
|------|----------|
| **自治成熟度（Autonomy Maturity）** | 衡量自治系统能力水平的等级标尺，反映系统自主决策、执行、学习的综合能力 |
| **人工干预率** | 单位时间内需要人工介入的任务占比，是衡量自治程度的核心量化指标 |
| **任务闭环成功率** | 无需人工干预即可完整完成的任务比例，反映系统端到端自治能力 |
| **符合性评估** | 验证系统是否符合 AIAF 某一等级规范性要求的评估活动 |
| **能力评估** | 衡量系统自治能力实际水平与成熟度的评估活动 |
| **一致性等级** | AIAF 定义的三级架构符合度标准，分为 Core、Advanced、Enterprise 三级 |

### Chapter 109 核心本体与分类法

#### 109.1 核心本体（Core Ontology）
AIAF 核心本体与 Part II 架构元模型完全对齐，定义了整个框架的基础语义实体，所有扩展均基于核心本体延伸。

**顶层核心实体分类：**
1. **目标类实体**：使命、目标、约束、成功标准、优先级
2. **能力类实体**：能力、技能、模型、规划、决策
3. **知识类实体**：知识、本体、世界模型、记忆、事实、文档
4. **运行类实体**：智能体、任务、动作、工具、工作流、状态、事件
5. **治理类实体**：政策、规则、风险、合规、伦理、审计
6. **安全类实体**：身份、信任、威胁、漏洞、防护、沙箱
7. **运营类实体**：指标、日志、链路、告警、故障、运维
8. **组织类实体**：利益相关者、角色、职责、组织单元

所有实体均具备标准属性定义与关系定义，详见 Part II Chapter 8 架构元模型。

> **规范性要求**：所有 AIAF 兼容工具与实现 **MUST** 支持核心本体的基础语义；行业扩展本体 **SHOULD** 继承核心本体，而非重新定义。

#### 109.2 标准化分类法
AIAF 对核心领域建立统一分类标准，确保跨场景、跨组织的一致性。

##### （1）自治能力分类法
按能力层级分为三级：
- **基础能力层**：感知理解、知识检索、工具调用、简单执行
- **核心能力层**：推理决策、任务规划、异常处置、协作协同
- **高阶能力层**：自主学习、能力演进、群体协同、环境自适应

##### （2）风险等级分类法
统一四级风险分级：
- **低风险**：影响范围小、无实质损失、可自动恢复
- **中低风险**：局部影响、轻微损失、易处置
- **中高风险**：较大范围影响、一定损失、需人工介入
- **高风险**：全局性影响、重大损失、严重后果

##### （3）治理域分类法
七大治理域：政策治理、合规治理、风险管理、伦理治理、人力治理、成本治理、审计运营

##### （4）安全威胁分类法
六大类威胁：提示交互类、记忆知识类、智能体身份类、工具调用类、运行时行为类、供应链模型类

##### （5）成熟度等级分类法
六级成熟度：L0 无自治、L1 辅助执行、L2 半自治、L3 条件自治、L4 高度自治、L5 完全自治

### Chapter 111 外部标准映射
AIAF 并非孤立的架构体系，而是在现有成熟框架基础上，针对自治智能领域的专项深化。本章节明确 AIAF 与全球主流标准框架的对应关系，帮助已有相关体系基础的组织快速对齐与适配。

#### 111.1 企业架构类标准

##### TOGAF®（The Open Group Architecture Framework）
- **对应关系**：AIAF 继承 TOGAF 的企业架构思想与 ADM 开发方法，针对自治智能特性进行专项扩展
- **对齐点**：
  - 架构分层思想、利益相关者视图、元模型理念完全对齐
  - AIAM 十阶段开发方法借鉴 TOGAF ADM 的阶段化架构治理思路
  - 持续演进、架构治理的核心原则保持一致
- **差异与扩展**：
  - TOGAF 面向通用企业架构，AIAF 聚焦自治智能专项领域
  - AIAF 新增目标、知识、智能、学习等自治专属架构域
  - AIAF 强化运行时安全、AI原生治理、持续学习等自治特有能力
- **适配建议**：已有 TOGAF 基础的企业，可在现有企业架构体系内扩展 AIAF 自治智能专项架构域，无需重构整体架构体系。

##### SABSA®（Sherwood Applied Business Security Architecture）
- **对应关系**：AIAF 安全框架吸收 SABSA 的分层安全治理、风险驱动、业务对齐思想
- **对齐点**：
  - 自上而下从业务到技术的分层安全设计思路一致
  - 风险驱动的安全架构方法论对齐
  - 安全与业务深度融合的核心理念相同
- **差异与扩展**：
  - SABSA 面向通用信息安全架构，AIAF 安全框架聚焦自治智能原生安全
  - AIAF 新增提示安全、记忆安全、智能体身份、群体行为安全等AI专属安全域
  - 运行时安全控制器、沙箱分级隔离等是自治场景的专项扩展
- **适配建议**：已落地 SABSA 的企业，可在现有安全架构基础上扩展 AI 原生安全专项能力。

#### 111.2 治理与运营类标准

##### COBIT®（Control Objectives for Information and Related Technology）
- **对应关系**：AIAF 治理框架对齐 COBIT 的IT治理思想与管控目标体系
- **对齐点**：
  - 治理框架的分层结构、管控目标、度量体系思路一致
  - 价值导向、风险可控的治理目标对齐
  - 治理与运营分离的理念相同
- **差异与扩展**：

  - 治理规则内嵌运行时全链路，比传统IT治理更前置、更精细

### Chapter 113 常见问题（FAQ）

#### 113.1 基础认知类
**Q1：自治智能和传统AI、大模型应用有什么区别？**
A：传统AI与大模型应用多为「应答式、工具式」，人类下达指令、输出结果，系统不具备自主目标与闭环执行能力；自治智能以目标为驱动，具备自主规划、执行、反思、学习的完整闭环，可在边界内自主应对动态环境，无需人类逐步骤指令。简单来说：传统AI是「你问我答」，自治智能是「你定目标，我想办法完成」。

**Q2：AIAF 和 TOGAF、SABSA 是什么关系？是替代关系吗？**
A：不是替代，是延伸与专项深化。TOGAF、SABSA 是通用企业架构与安全架构框架，AIAF 是聚焦自治智能领域的专项架构框架，继承了通用框架的核心思想与方法论，同时针对自治智能的特性做了大量扩展。已有 TOGAF/SABSA 基础的企业，完全可以在现有体系上叠加 AIAF，无需推倒重来。

**Q3：自治是不是就是完全不用人管了？**
A：不是。AIAF 的核心理念是「人机共治」，人类始终拥有最终决策权与监督权。自治等级越高，人类介入的频率越低、介入的层级越高，但永远保留最终控制权与紧急接管能力。越高等级的自治，对治理安全的要求越严格，而非完全去掉人类。

#### 113.2 落地实践类
**Q4：企业落地 AIAF 应该从哪里起步？**
A：建议遵循「场景切入、价值先行、阶梯演进」的原则：
1. 先选一个边界清晰、价值明确、风险可控的业务场景
2. 按照 AIAM 方法从使命目标到落地执行跑通完整闭环
3. 达到 L2 半自治级，验证业务价值
4. 沉淀通用能力，逐步扩展更多场景
5. 阶梯式向 L3、L4 升级，不追求一步到位。

**Q5：是不是自治成熟度越高越好？**
A：不是。成熟度等级需要与业务场景的风险、价值、成本匹配。高风险场景不适合过高的自治等级，低价值场景也没必要投入高成本做高阶自治。合适的才是最好的——在风险可控的前提下，匹配业务需求与投入产出比，选择合理的目标成熟度。

**Q6：中小企业有必要用这套框架吗？会不会太重？**
A：AIAF 支持分级裁剪，Core 级要求非常轻量化，中小企业完全可以从 Core 级+单场景起步，只落地核心必备的架构与治理安全能力，不追求全量十四部分一步到位。框架的价值是提供标准指引与避坑参考，企业可按需取用，而非必须全量落地。

#### 113.3 架构与标准类
**Q7：AIAF 绑定特定技术栈或厂商吗？**
A：不绑定。AIAF 是架构标准与方法论，从能力与逻辑层面定义架构，不指定具体模型、框架、厂商产品。企业可基于任意技术栈落地，只要符合架构原则与规范性要求，即可声明对 AIAF 的符合性。

**Q8：AIAF 如何保障可扩展性，会不会跟不上技术发展？**
A：AIAF 采用分层设计，核心原则与元模型保持稳定，具体能力、模式、实现可随技术发展持续迭代；同时采用开放社区模式，吸收行业最新实践，定期更新版本，保障框架的时效性与生命力。
