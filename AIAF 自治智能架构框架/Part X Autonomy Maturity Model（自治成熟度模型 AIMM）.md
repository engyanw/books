# PART X Autonomy Maturity Model（自治成熟度模型 AIMM）
本篇定义 AIAF 自治成熟度模型（Autonomous Intelligence Maturity Model, AIMM），是衡量企业与系统自治能力水平的阶梯式标准体系。成熟度模型是 AIAF 框架的「能力标尺」，它将自治能力从无到有、从弱到强划分为 6 个等级，明确每个等级的能力特征、量化指标、准入条件与降级规则，为企业提供清晰的现状定位、演进路径与阶段目标。

AIMM 遵循「阶梯递进、量化可验、双向流动、价值导向、双轨评估」的核心思想，既评估技术平台的自治能力，也评估组织体系的适配能力，避免单纯技术导向的能力虚高，确保自治能力真正落地产生业务价值。

## 本篇目标
1. 定义 L0–L5 六级自治成熟度的完整等级体系与核心特征
2. 建立六大能力维度的分级成熟度映射标准
3. 明确各等级升级的硬性准入条件（Gate）与降级触发机制
4. 规范平台成熟度与组织成熟度双轨评估方法
5. 提供成熟度模型的落地应用流程与演进规划方法

### Chapter 72 成熟度模型总览

#### 72.1 模型定位
AIMM 是 AIAF 体系中用于能力等级判定的核心标尺，向上承接业务战略与演进目标，向下对接 AIAA 评估体系与架构开发方法。它既可以用于现状诊断、差距识别，也可以用于阶段验收、等级认证与行业对标，是企业规划自治能力建设路径的核心参考框架。

> **规范性要求**：企业自治能力建设 **SHOULD** 以 AIMM 等级为阶段目标，阶梯式推进；L3 及以上等级的认证 **MUST** 基于 AIAA 标准评估结果判定，不得自行声明。

#### 72.2 核心设计原则
1. **阶梯递进**：等级之间能力边界清晰，低等级是高等级的基础，高等级是低等级的升级，不可跳级建设。
2. **量化可验**：每个等级设置可量化的核心指标与硬性准入条件，避免主观判断，确保等级判定客观可比。
3. **双向流动**：成熟度并非只升不降，能力退化、安全事故、治理失效时触发降级，保证等级与实际能力匹配。
4. **价值导向**：等级提升必须对应业务价值提升，禁止脱离业务价值的纯技术能力升级。
5. **双轨评估**：同时评估技术平台能力与组织适配能力，两者共同决定整体成熟度，避免「技术到位、组织跟不上」的断层。

#### 72.3 模型总体结构
AIMM 采用「六级等级 + 六大维度 + 双轨评估 + 升降级机制」的总体结构：

```text
                    ┌─────────────────────────────────────────────┐
                    │        L5 完全自治级（Fully Autonomous）    │
                    ├─────────────────────────────────────────────┤
                    │        L4 高度自治级（Highly Autonomous）   │
                    ├─────────────────────────────────────────────┤
                    │        L3 条件自治级（Conditional Auto.）   │
                    ├─────────────────────────────────────────────┤
                    │        L2 半自治级（Semi-Autonomous）       │
                    ├─────────────────────────────────────────────┤
                    │        L1 辅助执行级（Assisted）            │
                    ├─────────────────────────────────────────────┤
                    │        L0 无自治级（Manual）                │
                    └─────────────────────┬───────────────────────┘
                                          │
          ┌───────────────┬───────────────┼───────────────┬───────────────┐
          │               │               │               │               │
  感知认知维度   决策规划维度   执行协作维度   治理安全维度   学习演进维度   组织适配维度
                                          │
                                  ┌───────▼───────┐
                                  │ 双轨评估机制  │

                                  └───────────────┘
```

### Chapter 73 六级自治成熟度等级定义

#### 73.1 L0：无自治级（Manual）
**核心定义**：系统完全由人工主导操作，不具备任何自主决策与执行能力，仅作为人工操作的工具载体。

**能力特征**：
- 所有决策与动作均由人类发起与执行
- 系统仅提供基础的数据展示、流程记录与工具支撑
- 无任何AI智能决策能力，规则完全由人工预设与调整
- 不存在自动化闭环，所有环节依赖人工流转

**人机协作模式**：人操作工具，系统完全被动执行指令，无任何主动性。

**典型业务表现**：传统信息化系统、纯人工业务流程、静态规则驱动的RPA（无智能决策能力）。

**核心量化基准**：
- 自动任务闭环率：0%
- 人工干预率：100%
- 自主决策占比：0%

---

#### 73.2 L1：辅助执行级（Assisted）
**核心定义**：系统具备基础的智能辅助能力，可完成部分标准化、重复性的单点任务，但所有关键决策与流程控制仍由人类主导，系统仅起辅助提升效率的作用。

**能力特征**：
- 具备基础的感知与识别能力，可替代人工完成简单重复性操作
- 可基于预设规则与静态模型输出决策建议，最终决策由人做出
- 单环节自动化，无法形成端到端任务闭环
- 无自主调整能力，规则与模型变更完全依赖人工

**人机协作模式**：人主导决策与流程，系统辅助执行、提供建议、处理标准化工作。

**典型业务表现**：传统智能客服（问答匹配）、智能审核辅助、报表自动生成、基础OCR识别、传统机器学习预测辅助。

**核心量化基准**：
- 单环节自动化率：30% ~ 50%
- 人工干预率：> 70%
- 决策建议采纳率：< 40%
- 能力迭代周期：月度/季度级，完全人工驱动

---

#### 73.3 L2：半自治级（Semi-Autonomous）
**核心定义**：系统在明确边界与规则约束下，可完成单一标准化任务的端到端闭环执行，但异常处理、复杂决策仍需人工介入，整体处于「人监督、系统执行」的半自治状态。

**能力特征**：
- 单一场景、标准化任务可实现端到端自动闭环
- 具备基础的任务规划与工具调用能力，可按预设目标执行多步骤任务
- 常规异常可自动重试与降级处理，复杂异常自动升级人工
- 具备基础的治理与安全校验机制，核心动作有规则管控
- 学习能力以人工驱动为主，可基于人工反馈做增量优化

**人机协作模式**：人设定目标与规则，系统自主执行常规任务，人负责监督、处理异常、裁决边界问题。

**典型业务表现**：标准化流程自动化Agent、常规客服全闭环处理、基础运维自动化、标准化单据自动审核。

**核心量化基准**：
- 标准任务自动闭环率：50% ~ 70%
- 人工干预率：30% ~ 50%
- 常规异常自动处置率：≥ 40%
- 核心治理规则自动化覆盖率：≥ 60%

> **规范性要求**：达到 L2 级的系统 **MUST** 具备明确的目标边界与基础安全管控机制，禁止无约束的自主执行。

---

#### 73.4 L3：条件自治级（Conditional Autonomous）
**核心定义**：在特定业务域、特定场景与约束条件下，系统可实现全链路自主运行，具备环境自适应与动态规划能力，仅低概率复杂场景、高风险决策需要人工介入，是企业级自治能力的核心里程碑。

**能力特征**：
- 特定业务域内多任务、多场景可实现端到端自治闭环
- 具备动态规划与重规划能力，可根据环境变化自主调整执行路径
- 拥有独立的运行时安全控制器与全链路治理校验，行为边界可控
- 具备基础的反思与学习闭环，可从运行经验中自主优化策略
- 可实现多智能体分工协作，共同完成复杂任务
- 异常处置能力较强，大部分常见异常可自主解决，仅极端情况升级人工

**人机协作模式**：人定义目标、边界与风险偏好，系统自主完成规划、执行、优化全流程，人仅处理高风险、低概率异常事件，进行结果验收。

**典型业务表现**：自治安全运营中心（SOC）、智能运维AIOps、全流程无人化客服、特定领域数字化员工、自治供应链调度。

**核心量化基准**：
- 场景内任务自动闭环率：≥ 70%
- 人工干预率：≤ 20%
- 常见异常自动处置率：≥ 80%
- 治理规则自动化覆盖率：≥ 90%
- 策略自主优化占比：≥ 30%

> **规范性要求**：达到 L3 级的系统 **MUST** 具备独立的运行时安全控制器与完整的治理校验链路；高风险决策 **MUST** 保留人工确认节点。

---

#### 73.5 L4：高度自治级（Highly Autonomous）
**核心定义**：跨多个业务域实现高度自治，系统可自主应对动态变化的业务环境，具备主动发现问题、自主定义优化方向的能力，人类仅需设定顶层目标与治理边界，几乎不介入日常运行。

**能力特征**：
- 跨业务域、多场景的端到端高度自治，覆盖绝大多数日常业务场景
- 具备主动感知与前瞻预判能力，可主动发现机会与风险，而非仅被动响应
- 具备完整的知识与能力演进闭环，可持续自主扩展能力边界
- 治理与安全体系成熟，具备动态自适应的管控能力，可应对复杂风险
- 多智能体群体协作成熟，可通过群体协同解决复杂开放性问题
- 仅极端异常、重大决策、伦理争议类场景需要人类介入

**人机协作模式**：人定义使命、顶层目标与价值边界，系统自主制定目标拆解、资源调配、执行优化全流程，人类履行最终监督与问责职责，日常运营几乎零人工干预。

**典型业务表现**：企业级自治运营平台、全链路自治供应链、自治数字员工团队、无人化数据中台。

**核心量化基准**：
- 常规业务场景自治覆盖率：≥ 90%
- 人工干预率：≤ 5%
- 异常自主处置率：≥ 95%
- 能力自主迭代占比：≥ 70%
- 连续无人工干预稳定运行时长：≥ 720 小时

---

#### 73.6 L5：完全自治级（Fully Autonomous）
**核心定义**：企业级全场景的完全自治，系统具备完整的自我进化与自适应能力，可在人类设定的使命与伦理边界内，自主应对未知场景、持续演化能力，实现组织级的智能自治。

**能力特征**：
- 全业务域、全场景覆盖的端到端完全自治，可应对未知场景与全新问题
- 具备自主目标优化能力，可基于环境变化自主调整子目标与优先级
- 拥有完整的自我演进能力，可持续扩展认知边界与能力范围
- 群体智能与企业级学习高度成熟，实现组织级的智慧涌现
- 治理与安全体系具备高度自适应性，可自主应对新型风险
- 人类仅负责顶层使命定义、伦理边界设定与终极问责，不介入任何具体运营

**人机协作模式**：人定使命与边界，系统全权负责从目标到执行到进化的全流程，人类行使最终控制权与问责权，形成「人类主导价值、系统全权执行」的高阶人机共治。

**典型业务表现**：完全自治型企业、全域自治产业体系、自主进化的智能经济体（当前阶段为远期愿景目标）。

**核心量化基准**：
- 业务场景自治覆盖率：≥ 99%
- 人工干预率：≤ 1%
- 未知场景自主适应率：≥ 90%
- 能力完全自主迭代：无需人工干预的持续进化
- 连续无人工干预稳定运行时长：≥ 8760 小时

### Chapter 74 六大核心能力维度成熟度映射

#### 74.1 维度总览
AIMM 从六个核心维度综合评估自治成熟度，每个维度对应 AIAF 核心架构域的能力要求，各维度独立分级，共同决定整体成熟度等级。

| 维度名称 | 对应架构域 | 核心考察内容 |
|----------|------------|--------------|
| 感知认知维度 | 知识架构、智能架构 | 环境感知、知识管理、世界模型、认知理解能力 |
| 决策规划维度 | 目标架构、智能架构 | 目标拆解、任务规划、多目标权衡、动态决策能力 |
| 执行协作维度 | 运行时架构 | 任务执行、工具调用、多智能体协作、异常处置能力 |
| 治理安全维度 | 治理架构、安全架构 | 规则管控、合规治理、安全防护、风险管控能力 |
| 学习演进维度 | 学习架构 | 反思复盘、知识进化、能力迭代、策略优化能力 |
| 组织适配维度 | 业务架构、运营架构 | 组织模式、人才能力、流程机制、业务价值落地能力 |

#### 74.2 分维度等级映射表

| 维度 | L0 | L1 | L2 | L3 | L4 | L5 |
|------|----|----|----|----|----|----|
| **感知认知** | 无智能感知，完全人工采集识别 | 基础识别能力，单模态标准化感知 | 单场景结构化认知，静态知识底座 | 多模态动态认知，实时世界模型，知识自动更新 | 全域认知融合，前瞻预判，知识自主进化 | 全场景自适应认知，自主扩展认知边界 |
| **决策规划** | 完全人工决策，无规划能力 | 输出辅助建议，无自主规划 | 单任务预设路径规划，无动态调整 | 多步骤动态规划，支持重规划与多方案权衡 | 跨域复杂决策，主动目标优化，前瞻规划 | 完全自主决策，自主目标拆解与动态优化 |
| **执行协作** | 纯人工执行，无自动化 | 单环节自动化执行，无协作 | 单任务端到端执行，基础异常处理 | 多任务多智能体协作，自主异常处置 | 跨域群体协作，复杂任务自主分工协同 | 全场景无边界协作，群体智能涌现 |
| **治理安全** | 无专项治理，人工管控 | 基础规则管控，事后人工审计 | 核心节点规则校验，基础安全防护 | 全链路治理校验，独立安全控制器，风险可控 | 自适应治理，动态安全防护，全链路可审计 | 自治型治理安全体系，自主应对新型风险 |
| **学习演进** | 无学习能力，完全人工迭代 | 人工驱动的模型规则更新 | 人工监督下的增量优化，无自主学习 | 闭环反思学习，策略自主优化，知识自动更新 | 全链路自主学习，能力持续迭代，迁移复用 | 完全自主进化，自主扩展能力边界 |
| **组织适配** | 无专门组织，传统运维模式 | 零星AI岗位，业务技术分离 | 专项团队，场景级对接机制 | 跨职能专职团队，配套流程机制 | 组织级适配，全链路人机协同流程 | 组织形态全面重构，人机共治模式成熟 |

> **规范性要求**：整体成熟度等级 **MUST** 遵循「短板原则」，即整体等级由最低维度的等级决定，不得出现维度短板但整体等级虚高的情况。

### Chapter 75 等级升级准入机制（Upgrade Gate）

成熟度升级必须通过硬性准入关口，仅综合评分达标不足以升级，必须同时满足核心量化指标、必备能力与治理安全底线三类条件。

#### 75.1 升级总原则
1. **阶梯升级**：原则上不得跳级，必须逐级提升；特殊场景需跳级的，必须经过专项评估与高阶审批。
2. **一票否决**：治理安全存在重大缺陷、发生重大责任事故的，暂停升级资格，整改完成后方可重新评估。
3. **持续验证**：升级后设置 3 个月观察期，观察期内指标持续达标方可正式确认等级，否则退回原等级。
4. **场景差异化**：不同风险等级的场景，升级门槛差异化设置；高风险行业（金融、医疗、工业控制）准入标准更严格。

#### 75.2 L0 → L1 准入条件
- **量化指标**：单环节自动化率 ≥ 30%，AI辅助类任务覆盖率 ≥ 20%
- **必备能力**：具备基础的智能识别或预测能力，可输出标准化决策建议
- **治理底线**：明确人工最终责任制，所有AI输出均有人工确认环节
- **组织要求**：有专门的AI技术支撑岗位，业务方明确使用规则

#### 75.3 L1 → L2 准入条件
- **量化指标**：标准任务自动闭环率 ≥ 50%，人工干预率 ≤ 50%，常规异常自动处置率 ≥ 40%
- **必备能力**：
  - 可完成单一标准化场景的端到端闭环执行
  - 具备基础的目标拆解与工具调用能力
  - 核心执行节点有规则校验与日志留痕
- **治理底线**：
  - 明确场景边界与禁止事项
  - 建立异常升级人工的机制
  - 关键操作完整可追溯
- **组织要求**：成立跨业务技术的场景运营团队，明确人机权责划分

#### 75.4 L2 → L3 准入条件
> L3 是企业级自治能力的核心里程碑，准入标准显著提升。

- **量化指标**：
  - 目标场景内任务自动闭环率 ≥ 70%
  - 人工干预率 ≤ 20%
  - 常见异常自动处置率 ≥ 80%
  - 核心治理规则自动化覆盖率 ≥ 90%
- **必备能力**：
  - 具备动态规划与重规划能力，可应对环境变化调整路径
  - **MUST** 具备独立的运行时安全控制器
  - 具备多智能体分工协作能力
  - 具备基础的反思学习闭环，可自主优化执行策略
  - 全链路决策可追溯、可解释
- **治理底线**：
  - 建立完整的治理规则体系与全链路控制点
  - 高风险决策 100% 保留人工确认节点
  - 建立定期安全与治理评审机制
  - 发生安全事件可快速熔断与追溯
- **组织要求**：
  - 建立专职的自治系统治理与运营团队
  - 明确各角色人机权责边界
  - 建立常态化的运营与优化机制

#### 75.5 L3 → L4 准入条件
- **量化指标**：
  - 跨场景自治覆盖率 ≥ 90%
  - 人工干预率 ≤ 5%
  - 异常自主处置率 ≥ 95%
  - 能力自主迭代占比 ≥ 70%
  - 连续无重大人工干预稳定运行 ≥ 30 天
- **必备能力**：
  - 跨多业务域的端到端自治能力
  - 具备主动感知与前瞻预判能力
  - 完整的知识、能力、策略全链路自主学习闭环
  - 成熟的多智能体群体协作与治理能力
  - 自适应的安全与治理管控能力
- **治理底线**：
  - 建立企业级统一治理体系与专职治理委员会
  - 具备完善的伦理审查与风险管控机制
  - 全量操作与决策 100% 可审计追溯
  - 建立成熟的应急响应与灾难恢复机制
- **组织要求**：
  - 企业级跨部门治理决策机制成熟
  - 组织流程与人机协作模式完成适配性重构
  - 具备完整的人才梯队与能力培养体系

#### 75.6 L4 → L5 准入条件
> L5 为远期愿景级目标，当前阶段暂无企业可达到，准入标准随技术与实践发展动态更新。

- 全业务域自治覆盖率 ≥ 99%，人工干预率 ≤ 1%
- 具备未知场景自主适应与能力扩展能力
- 企业级组织与治理体系完全适配人机共治模式
- 通过最高等级的安全、伦理与合规认证
- 连续 1 年以上稳定运行，无重大责任事故

### Chapter 76 降级触发与恢复机制

成熟度并非终身制，当系统能力退化、出现重大风险或治理失效时，触发等级降级，确保等级与实际能力匹配。

#### 76.1 降级原则
1. **实事求是**：实际能力低于等级标准时，必须降级，不得维持虚高等级。
2. **分级处置**：根据问题严重程度，分为临时降级与正式降级。
3. **可恢复**：降级后完成整改并通过验证，可恢复原等级。
4. **公开透明**：等级变更需正式记录并同步相关利益相关者。

#### 76.2 降级触发条件
满足以下任一条件时，触发降级评估：
1. **能力持续退化**：核心指标连续 30 天低于当前等级基准要求
2. **重大安全事故**：发生严重安全事件、数据泄露、系统失控等重大事故
3. **治理合规失效**：出现严重合规违规、治理体系失效、重大伦理问题
4. **重大架构变更**：系统架构、业务范围发生重大调整，原等级基础不复存在
5. **定期评估不达标**：年度例行评估未达到当前等级标准

#### 76.3 降级分级
1. **临时降级**
   - 触发场景：短期能力波动、一般安全事件、局部治理问题
   - 处理方式：临时降低等级，设定 1~4 周整改期，整改通过后恢复原等级
   - 影响范围：仅影响对应业务场景，不影响整体等级认证
2. **正式降级**
   - 触发场景：重大事故、长期能力不达标、严重合规失效、整改无效
   - 处理方式：正式下调成熟度等级，更新等级认证结果
   - 影响范围：整体等级下调，需重新开展升级评估方可恢复

#### 76.4 等级恢复机制
1. 降级后制定整改计划，明确整改措施、责任人与时间节点
2. 整改完成后开展专项复核评估，验证问题是否解决、能力是否恢复
3. 临时降级整改通过后，即时恢复原等级
4. 正式降级整改通过后，需经过至少 1 个月观察期，指标持续稳定，方可重新申请升级评估

### Chapter 77 平台成熟度与组织成熟度双轨评估

自治能力的落地不仅取决于技术平台，更取决于组织的适配程度。AIMM 采用双轨评估模型，分别评估技术平台与组织体系，避免「技术很先进、组织用不起来」的能力断层。

#### 77.1 双轨模型设计思路
- **平台成熟度**：衡量技术系统本身的自治能力水平，对应架构、能力、安全、学习等技术维度
- **组织成熟度**：衡量企业组织、流程、人才、文化对自治系统的适配与支撑能力
- 整体成熟度取两者中的较低值，即「短板决定整体水平」

#### 77.2 平台成熟度评估维度
1. 架构完备性：九大架构域覆盖度、参考架构遵循度
2. 能力水平：感知、决策、执行、协作的实际能力表现
3. 治理安全：治理体系完备度、安全防护有效性、合规达标率
4. 学习演进：学习闭环完整度、能力迭代速度、自主进化水平
5. 运行可靠性：系统稳定性、可用性、容错能力、运维成熟度

#### 77.3 组织成熟度评估维度
1. **战略与组织**：自治战略清晰度、组织架构适配性、跨部门协作机制
2. **人才与能力**：团队能力匹配度、人才梯队建设、技能培养体系
3. **流程与机制**：人机协同流程、治理决策机制、运营优化机制
4. **业务价值落地**：业务场景覆盖度、价值量化体系、投资回报水平
5. **文化与认知**：全员对自治智能的认知接受度、数据驱动文化、创新容错文化

#### 77.4 整体成熟度判定规则
1. 分别评估平台成熟度等级与组织成熟度等级
2. 整体成熟度 = min(平台成熟度, 组织成熟度)
3. 若两者相差一个等级以上，判定为「等级断层」，需优先补齐短板维度
4. 典型断层场景：平台 L3，组织 L2 → 整体 L2，核心改进方向是组织适配与流程落地

> **实践提示**：多数企业在建设初期，平台成熟度会快于组织成熟度；长期来看，组织成熟度才是自治能力真正落地的核心瓶颈，需同步建设。

### Chapter 78 AIMM 落地应用方法

#### 78.1 与 AIAA 评估体系的对应关系
- AIMM 是等级标准，定义「什么是 L3」；AIAA 是评估方法，定义「怎么测是不是 L3」
- AIAA 六大评估域的得分结果，直接对应 AIMM 各维度的等级判定
- 正式的 AIMM 等级认证 **MUST** 基于 AIAA 标准评估流程输出结果

#### 78.2 成熟度评估执行流程
1. **现状初判**：基于业务与系统现状，初步判定当前所处等级区间
2. **正式评估**：按照 AIAA 标准流程，开展全维度量化评估
3. **维度定级**：对六个核心维度分别判定等级
4. **整体定级**：基于短板原则与双轨模型，判定整体成熟度等级
5. **差距分析**：识别升级到下一等级的核心差距与短板项
6. **路线规划**：制定分阶段升级方案与里程碑目标
7. **定期复评**：每半年/年度开展复评，跟踪升级进度

#### 78.3 典型应用场景
1. **现状诊断**：全面评估企业当前自治能力水平，明确定位与短板
2. **战略规划**：以成熟度等级为阶段目标，制定中长期建设路线图
3. **阶段验收**：作为项目阶段验收与价值验证的核心标准
4. **行业对标**：与行业基准、竞品对比，明确自身定位与竞争优势
5. **等级认证**：开展第三方 AIAF 成熟度认证，提升行业公信力
