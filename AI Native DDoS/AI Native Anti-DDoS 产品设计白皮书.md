## 卷首语
本卷是整套白皮书体系的产品落地总纲，承接第一卷《AI Native DDoS：从流量防护到 AI Runtime Availability》的七大核心理论，以及第二卷《AI Runtime Availability Platform 总体架构》的十二层参考架构，系统性回答**「我们应该构建什么样的产品」**这一核心命题。

全卷以「Protect AI Runtime Availability」为核心使命，将AI原生可用性安全的理论与架构转化为可落地、可商业化、可持续演进的产品体系，定义下一代AI Native Anti-DDoS的产品形态与产业标准。

## 第一章 Product Vision
### 1.1 产品使命
**Protect AI Runtime Availability.**

传统Anti-DDoS的使命是「保护网络与应用的连通性」，核心价值是保障流量可达、服务在线；而本产品的使命是「保障AI运行时的持续可信可用」，核心价值是守护AI时代的核心生产力。这不是防护对象的简单扩展，而是产品价值底层逻辑的跃迁——从守护网络管道，升级为守护AI业务的运行根基。

这一使命决定了产品的所有设计决策：所有能力围绕可用性构建，所有指标围绕可用性设计，所有价值围绕可用性交付。

### 1.2 四大产品目标
围绕核心使命，产品确立四大层级目标，形成从技术到业务的完整价值传递链条。

#### 目标一：Availability（可用性保障）
产品的核心本体目标。
- 核心内涵：保障AI Runtime全栈可用性，覆盖推理性能、上下文状态、工具调用、工作流执行、Agent运行的全维度可用
- 核心指标：AI Runtime可用率、推理SLA达标率、业务中断时长、攻击下性能下降幅度
- 价值定位：替代传统的「服务在线率」，成为AI时代可用性保障的核心标准

#### 目标二：Efficiency（效率最优）
产品的经济可行性目标。
- 核心内涵：实现防护成本远低于攻击成本，同时最大化算力资源利用效率，避免防护本身成为性能与成本负担
- 核心指标：单位防护成本、攻击-防护成本比、算力资源利用率、防护额外时延
- 价值定位：构建可持续的经济模型，让大规模商业化落地成为可能

#### 目标三：Autonomy（自治防御）
产品的能力范式目标。
- 核心内涵：实现全链路自主检测、自主分析、自主决策、自主响应、自主学习，以AI防御AI
- 核心指标：自动处置率、平均响应时长、人工介入频次、模型自主迭代效率
- 价值定位：应对AI时代高速、智能、多变的攻击形态，突破人工运营的能力边界

#### 目标四：Business Continuity（业务连续性）
产品的最终业务价值目标。
- 核心内涵：将技术层面的可用性能力，转化为业务层面的连续性保障，支撑企业级业务目标
- 核心指标：业务SLA达标率、业务中断损失、容灾恢复时间、核心业务保障等级
- 价值定位：让产品价值从技术部门传导到业务部门，从运维指标升级为业务KPI

### 1.3 产品愿景
未来五到十年，AI Native Anti-DDoS将从一款边缘安全产品，演进为AI时代的核心基础设施。它将像今天的网络、算力一样，成为所有AI业务的默认底座能力，无处不在、无感运行，默默守护整个数字世界的AI运行时可用性。

## 第二章 产品定位
### 2.1 重新定义AI Native Anti-DDoS
本产品对AI原生抗DDoS给出明确定义，作为整个产品体系的定位基石：

> **AI Native Anti-DDoS = AI Runtime Availability + Resource Protection + Agent Traffic Governance**

三者构成完整的产品价值三角：
- **AI Runtime Availability**：核心价值本体，是产品最终交付的结果，即保障AI运行时持续、稳定、可信运行
- **Resource Protection**：核心执行手段，通过对算力、缓存、队列、内存等核心资源的防护与调度，实现可用性保障
- **Agent Traffic Governance**：核心治理场景，针对智能体流量、工具调用、工作流执行进行全链路治理，适配AI Native业务形态

### 2.2 与传统Anti-DDoS的本质区别
这一定义标志着Anti-DDoS产品的代际跃迁，二者在底层逻辑上存在本质差异：

| 维度 | 传统Anti-DDoS | AI Native Anti-DDoS |
| :--- | :--- | :--- |
| 核心目标 | 保障网络连通与服务在线 | 保障AI Runtime持续可信可用 |
| 防护对象 | 网络带宽、连接数、应用接口 | 算力、缓存、工作流、Agent |
| 核心资源 | 带宽 | 算力 |
| 检测依据 | 流量特征、访问频率 | 语义特征、行为模式、资源消耗 |
| 防护手段 | 流量清洗、拦截、限流 | 资源调度、分级降级、行为治理 |
| 产品属性 | 边界安全设备 | 运行时内生保障平台 |
| 价值衡量 | 清洗带宽（Tbps） | 可用性保障等级、算力防护效率 |

### 2.3 三层定位
#### 对客户：AI业务的可用性保障平台
它不是一款锦上添花的安全设备，而是AI业务的刚需基础设施。没有它，大模型推理、Agent服务、自动化工作流随时可能被低成本攻击击穿，造成业务中断与经济损失。

#### 对产业：AI原生安全的核心品类
它将重构Anti-DDoS产业的边界与标准，推动整个产业从「带宽竞赛」转向「算力防护竞赛」，催生新的赛道、新的厂商与新的产业格局。

#### 对华为云：AI原生安全体系的核心组件
它与昇腾算力底座、大模型服务、Agent平台、MCP生态深度协同，共同构成华为云AI原生技术体系，是华为云全栈AI能力的重要组成部分。

## 第三章 产品边界
### 3.1 边界划分原则
以「AI Runtime可用性」为核心边界，纵向聚焦资源层到运行时层的可用性防护，横向与周边安全产品能力互补、数据打通、策略联动。
- 不越界：不做内容安全、身份管理、漏洞防护等非可用性领域的能力
- 不重叠：与周边产品明确职责划分，避免能力重复与产品打架
- 强协同：通过标准化接口与周边产品数据互通、策略联动、能力互补

### 3.2 与周边产品的职责划分
#### 1. AI Gateway（AI网关）
- **核心职责**：请求路由、模型编排、协议转换、流量分发、版本管理
- **本产品定位**：以内嵌模块或旁挂模式部署在AI网关层，提供可用性防护能力
- **协作关系**：AI网关负责流量路由，本产品负责流量的可用性治理；共享请求数据，协同执行限流、降级等动作

#### 2. WAAP（Web应用与API防护）
- **核心职责**：Web漏洞防护、API注入攻击防护、数据泄露防护、应用层攻击拦截
- **本产品定位**：聚焦可用性安全，WAAP聚焦机密性与完整性安全
- **协作关系**：共享流量数据与检测结果，策略联动；WAAP负责拦截恶意注入，本产品负责拦截耗尽型攻击

#### 3. Bot Management（机器人管理）
- **核心职责**：人机识别、爬虫治理、作弊防护、账号安全
- **本产品定位**：继承基础Bot检测能力，向上扩展Agent识别与可用性维度的Bot治理
- **协作关系**：共享客户端指纹与IP信誉数据；传统Bot治理由Bot产品负责，AI场景下的Agent治理与算力耗尽Bot由本产品负责

#### 4. API Security（API安全）
- **核心职责**：API资产发现、权限管控、数据泄露防护、API漏洞管理
- **本产品定位**：聚焦API层面的可用性防护（如API耗尽攻击、调用风暴）
- **协作关系**：共享API资产数据；API安全负责权限与数据安全，本产品负责API可用性保障

#### 5. AI Runtime Security（AI运行时安全）
- **核心职责**：运行时漏洞防护、模型安全、Prompt内容安全、模型防窃取
- **本产品定位**：二者共同构成AI运行时安全体系，分别对应可用性与机密性/完整性维度
- **协作关系**：共享运行时埋点数据，统一Agent身份体系，协同构建运行时安全纵深

#### 6. Guardrails（AI护栏）
- **核心职责**：大模型输出的内容合规、伦理安全、风险管控、有害内容拦截
- **本产品定位**：不涉及内容合规，聚焦服务可用性
- **协作关系**：在Prompt检测层共享语义数据，分别从合规与可用性两个维度进行检测与处置

#### 7. IAM（身份与访问管理）
- **核心职责**：身份认证、权限管控、访问控制、身份治理
- **本产品定位**：对接现有IAM体系，不重复建设身份能力
- **协作关系**：基于IAM的身份体系，实现用户级、应用级、Agent级的精细化配额与策略管理

#### 8. AI SOC（AI安全运营中心）
- **核心职责**：全局安全事件运营、威胁狩猎、合规审计、安全态势管理
- **本产品定位**：作为AI SOC的核心数据源与执行端
- **协作关系**：本产品上报可用性安全事件与遥测数据，接收SOC的全局调度指令与策略

#### 9. MCP Gateway（模型上下文协议网关）
- **核心职责**：MCP协议接入、工具注册、权限管控、上下文交互管理
- **本产品定位**：在MCP网关层植入可用性防护模块，实现工具与上下文的可用性治理
- **协作关系**：共享工具与上下文数据，协同执行调用限流、循环熔断等防护动作

### 3.3 边界总结
本产品始终聚焦「AI Runtime可用性」这一核心命题，做深、做透、做专，通过生态协同构建完整的AI原生安全体系，而非大而全的全能型产品。清晰的边界划分是产品保持专注、构建核心竞争力的前提。

## 第四章 产品能力地图
### 4.1 能力体系设计原则
打破传统Anti-DDoS按网络层级（L3/L4/L7）划分能力的模式，围绕AI Runtime的防护对象与能力属性，构建七大能力域。每个能力域既具备独立的产品价值，又可协同形成完整的防护体系。

### 4.2 七大核心能力域
#### 能力域一：全域可用性保障（Availability Protection）
面向业务视角的顶层总览能力，将底层技术能力转化为可度量的业务可用性价值。
- **核心子能力**
  - 全局可用性评分：统一度量AI Runtime综合可用性水平
  - 业务分级保障：基于业务等级提供差异化SLA与防护等级
  - 可用性SLA管理：SLA定义、监控、告警、达标统计与赔付核算
  - 全局容灾调度：跨区域、跨集群的可用性容灾与流量调度
- **核心场景**：企业级业务连续性管理、多业务分级防护、容灾切换

#### 能力域二：推理服务防护（Inference Protection）
针对推理服务层的核心防护能力，直接作用于推理请求与推理过程。
- **核心子能力**
  - 推理请求分级调度：按业务优先级调度推理请求
  - 推理动态降级：多档位推理降级，保障基础服务可用
  - 推理超时管控：异常请求强制终止，避免长期占用资源
  - 推理队列治理：队列分级、反压控制、超时清理
- **核心场景**：推理峰值冲击、高消耗请求攻击、推理服务过载

#### 能力域三：算力资源防护（GPU Protection）
底层核心防护能力，针对GPU、HBM、KV Cache等算力资源进行防护与调度。
- **核心子能力**
  - 多级算力配额：租户/应用/会话/用户级算力配额隔离
  - 算力优先级调度：高优先级业务算力抢占与保障
  - HBM显存防护：显存配额、碎片治理、溢出保护
  - KV Cache防护：缓存配额、智能回收、分片隔离
- **核心场景**：算力耗尽攻击、多租户算力争抢、缓存资源挤占

#### 能力域四：智能体防护（Agent Protection）
AI Native场景的特色能力，针对Agent运行时进行身份管控与行为治理。
- **核心子能力**
  - Agent身份与准入：身份认证、接入鉴权、信誉体系
  - Agent行为限流：推理、工具调用、任务并发多级限流
  - Agent异常终止：死循环、状态异常的自动检测与终止
  - A2A交互治理：多Agent协作的流量管控与异常检测
- **核心场景**：恶意Agent接入、Agent风暴攻击、协作链路异常

#### 能力域五：工作流与工具防护（Workflow & Tool Protection）
业务执行层防护能力，针对工作流与工具调用进行全链路治理。
- **核心子能力**
  - 工作流全链路防护：步骤限制、时长管控、死循环熔断
  - 工具调用治理：调用配额、循环检测、高消耗工具管控
  - MCP协议防护：MCP交互状态机校验与资源管控
  - 依赖死锁检测：自动识别并解除工作流依赖死锁
- **核心场景**：工作流死循环攻击、工具风暴、递归调用攻击

#### 能力域六：AI运行时遥测（AI Telemetry）
全栈感知支撑能力，为所有检测、分析、防护提供统一数据底座。
- **核心子能力**
  - 全栈指标采集：从硬件到Agent的全层级遥测数据采集
  - 统一遥测流水线：聚合、标准化、关联、存储全链路处理
  - 可用性基线管理：自动学习正常基线，识别异常偏离
  - 数据开放服务：标准化OpenAPI，支撑第三方系统对接
- **核心场景**：故障排查、性能监控、攻击检测、运营分析

#### 能力域七：自治防御运营（Autonomous Defense）
智能化运营能力，实现防御的自动化、自主化与持续演化。
- **核心子能力**
  - 自动检测与响应：已知攻击的自动检测与自动处置
  - 智能根因分析：可用性故障的自动根因定位
  - 攻击自学习：攻击特征自动提取与模型自主迭代
  - 智能运营助手：自然语言交互的运营辅助能力
- **核心场景**：自动化攻击处置、智能排障、策略自优化

### 4.3 能力成熟度分级
七大能力域均定义四级成熟度，支撑产品分阶段演进：
- L1 基础级：具备基础能力，可应对典型场景
- L2 增强级：能力完善，覆盖绝大多数主流场景
- L3 智能级：引入AI能力，实现自动化与智能化
- L4 自治级：完全自主运行，具备自我演化能力

## 第五章 产品总体架构
### 5.1 架构设计原则
产品总体架构严格遵循第二卷提出的「控制面/数据面分离」核心架构理论，同时兼顾产品化落地的可运维性、可扩展性与商业交付能力，遵循三大设计原则：
1. **分层解耦**：管理、控制、防护、执行分层，各层独立迭代、弹性扩展
2. **性能优先**：数据面极致性能，控制面极致智能，各司其职
3. **部署灵活**：支持公有云、私有化、软硬一体等多种部署形态

### 5.2 五层产品总体架构
产品整体采用五层架构，自上而下依次为运营接入层、管理平面、控制平面、运行时防护平面、边缘数据平面。

```text
                 Console  运营控制台
                    │
         Management Plane  管理平面
                    │
            Control Plane  控制平面
                    │
    AI Runtime Protection Plane  运行时防护平面
                    │
          Edge Data Plane  边缘数据平面
```

#### 第一层：Console（运营控制台）
- **定位**：产品的统一人机交互入口，面向运营人员、安全人员、租户管理员
- **核心组件**：统一驾驶舱、策略管理中心、攻击复盘中心、仿真演练中心、AI运营助手
- **核心能力**：可视化运营、策略配置、事件管理、报表分析、系统管理
- **对应第二卷架构**：AI Runtime Availability Center

#### 第二层：Management Plane（管理平面）
- **定位**：产品的管理与运维中枢，负责租户、权限、配置、计量、审计等通用管理能力
- **核心组件**：租户管理、权限管理、配置管理、计量计费、审计日志
- **核心能力**：多租户隔离、RBAC权限控制、配置灰度发布、用量计量、全链路审计
- **架构价值**：将通用管理能力与业务能力解耦，支撑多形态商业化交付

#### 第三层：Control Plane（控制平面）
- **定位**：产品的智能大脑，负责全局分析、策略生成、自治决策、调度指挥
- **核心组件**：语义分析引擎、行为分析引擎、策略引擎、自治防御系统、遥测控制中心
- **核心能力**：全局检测、深度分析、策略生成、自治决策、调度指令下发
- **对应第二卷架构**：语义检测层、行为分析层、策略引擎、统一控制平面
- **性能特征**：秒级到分钟级决策周期，追求分析深度与决策准确性

#### 第四层：AI Runtime Protection Plane（AI运行时防护平面）
- **定位**：核心防护执行层，嵌入AI Runtime内部，实现运行时层面的资源防护与调度
- **核心组件**：推理防护模块、算力防护模块、缓存防护模块、Agent防护模块、工作流防护模块
- **核心能力**：运行时资源管控、请求调度、降级隔离、异常终止
- **对应第二卷架构**：可用性防护层、AI Runtime层、Agent Runtime层
- **性能特征**：毫秒级执行时延，与运行时深度融合

#### 第五层：Edge Data Plane（边缘数据平面）
- **定位**：边界接入与流量预处理层，负责流量接入、基础清洗、快速检测
- **核心组件**：网络层清洗引擎、协议安全引擎、基础Bot检测、速率限制引擎、流缓存系统
- **核心能力**：L3/L4 DDoS清洗、协议异常过滤、基础限流、流量分发
- **对应第二卷架构**：边缘防护层
- **性能特征**：微秒级处理时延，线速处理大流量

### 5.3 架构优势
1. **分层解耦，独立演进**：各层职责清晰，可独立迭代升级，数据面性能优化与控制面智能升级互不干扰
2. **性能可控，智能兼顾**：数据面保障极致低时延，控制面提供深度智能，二者协同达到最优平衡
3. **弹性扩展，容量线性**：各层均支持水平扩展，容量随节点数线性增长，支撑从百G到百T的平滑扩容
4. **部署灵活，全场景覆盖**：支持云服务、私有化、软硬一体等多种部署形态，适配不同客户需求

## 第六章 Data Plane（边缘数据平面）
### 6.1 平面定位与设计目标
边缘数据平面是产品的第一道防线，也是所有流量的必经入口。核心目标是**「以极致性能终结99%的已知攻击」**，将无效流量拦截在最外层，避免消耗上层算力与智能检测资源。

核心设计原则：硬件卸载优先、内核加速优先、确定性执行、亚毫秒级时延。

### 6.2 核心技术栈与能力模块

- **技术栈**：ASIC芯片、SmartNIC智能网卡、FPGA
- **核心能力**：L3/L4报文线速清洗、SYN/UDP/ICMP洪水硬件级拦截、流量统计硬件卸载、源认证硬件加速
- **性能指标**：单卡百G级处理能力，亚微秒级处理时延
- **防护覆盖**：SYN Flood、UDP Flood、ICMP Flood、ACK Flood、DNS/NTP反射放大攻击等所有传统网络层攻击

#### 模块二：内核加速层
- **技术栈**：XDP、eBPF、DPDK

- **性能指标**：单节点万兆级处理能力，微秒级处理时延
- **核心价值**：兼顾性能与灵活性，支撑防护规则的快速迭代与热更新

#### 模块三：协议安全层
- **技术栈**：原生QUIC、TLS 1.3、HTTP/3协议栈
- **核心能力**：协议握手验证、畸形报文过滤、加密流量指纹识别、连接速率管控
- **重点能力**：QUIC协议原生防护，适配AI业务HTTP/3主流部署趋势，解决传统设备无法解析QUIC流量的防护盲区

#### 模块四：基础Bot与API限流
- **核心能力**：客户端指纹识别、基础人机验证、API接口速率限制、IP信誉过滤
- **定位**：基础级Bot治理，拦截明显的自动化工具与爬虫；复杂语义级Bot由上层语义平面处理
- **价值**：在边缘层过滤低风险、高频率的自动化流量，减轻上层检测压力

#### 模块五：流缓存与快速路径
- **核心能力**：会话流缓存、白名单快速放行、历史风险快速匹配、已认证会话直通
- **核心价值**：已认证的正常流量直接走快速路径，跳过重复检测，大幅降低平均处理时延
- **性能收益**：80%以上的正常流量可走快速路径，平均时延降低一个数量级

### 6.3 核心性能指标
- 网络层攻击检测与拦截时延：**≤50μs**
- 单节点处理能力：≥100Gbps
- 全局清洗容量：≥100Tbps
- 规则热更新时延：<1s
- 正常业务额外时延：<1ms

### 6.4 与上层协同机制

- 将流量日志、攻击事件、流统计数据上报给遥测层与控制面
- 攻击大规模爆发时，接收控制面的流量调度指令，执行流量牵引与分流

## 第七章 Semantic Plane（语义检测平面）
### 7.1 平面定位与核心理念
语义检测平面是数据面的核心智能检测层，部署在请求进入AI Runtime前的实时路径上，负责识别请求的语义风险与算力消耗风险。

**核心设计理念：Cost-to-Defend < Cost-to-Attack**
> 防护的单位算力成本，必须低于攻击的单位算力成本，这是AI原生防护能够成立的经济前提。如果每防护一个请求的算力消耗，高于攻击一个请求的算力消耗，防护体系将在经济上不可持续，最终被攻击方以成本优势击穿。

基于这一理念，明确排除「通用大模型实时检测」方案：大模型推理算力成本高、时延长，防护成本高于攻击成本，不具备大规模落地的经济可行性。因此采用**三级轻量检测架构**，逐级提升检测深度，同时严格控制算力成本。

### 7.2 三级语义检测流水线
```text
Embedding → SLM → Intent Classification & Risk Scoring
```

#### 第一级：Embedding轻量特征提取
- **技术方案**：轻量级Embedding模型，百万级参数，针对攻击场景专项优化，推理极致加速
- **核心能力**：文本向量化、语义复杂度初判、异常相似度匹配、基础异常过滤
- **性能指标**：单请求时延<1ms，算力消耗仅为通用大模型的千分之一
- **过滤效果**：80%以上的正常请求快速通过，明显异常请求直接标记进入下一级

#### 第二级：SLM专用小模型检测
- **技术方案**：针对攻击场景专项训练的小语言模型（SLM），十亿级以内参数，配合量化、蒸馏等优化技术
- **核心能力**：高消耗Prompt识别、攻击句式识别、注入意图初判、算力消耗预估
- **性能指标**：单请求时延<5ms，算力消耗为通用大模型的百分之一
- **过滤效果**：识别90%以上的已知语义攻击，输出风险类型与预估算力消耗

#### 第三级：意图分类与风险评分
- **技术方案**：特征工程+分类器+规则引擎结合
- **核心能力**：细粒度请求意图分类、多维度风险加权评分、处置策略匹配
- **评分维度**：语义风险、预估算力消耗、上下文风险、历史行为风险
- **输出结果**：0-100风险评分、风险标签、建议处置动作（放行/限流/降级/拦截）
- **性能指标**：单请求时延<0.5ms

### 7.3 核心检测场景
1. **Prompt洪水攻击识别**：识别批量高消耗Prompt攻击，精准预估算力消耗
2. **长上下文攻击识别**：识别蓄意挤占KV Cache的长文本攻击
3. **算力耗尽型注入识别**：识别诱导模型执行高算力任务的注入攻击
4. **异常请求聚类**：自动识别批量生成的特征相似的攻击请求

### 7.4 成本与效率优势
三级检测架构的平均单请求算力消耗，仅为攻击请求平均算力消耗的**1/50~1/100**，真正实现防护成本远低于攻击成本，具备大规模商业化落地的经济可行性。这一成本优势是产品核心竞争力的重要组成部分。

## 第八章 Behavior Plane（行为分析平面）
### 8.1 平面定位
行为分析平面是控制面的核心分析组件，异步运行，不占用实时请求路径的时延预算。它负责构建全局行为视图，识别复杂、隐蔽、新型的攻击行为，支撑深度检测、攻击溯源与威胁狩猎。

如果说语义检测平面是「看单个请求好不好」，行为分析平面就是「看整个行为链正不正常」。它能够发现单点检测无法识别的高级攻击，是产品深度防护能力的核心体现。

### 8.2 六大行为图谱
基于全栈遥测数据与语义检测数据，构建六大维度的行为图谱，全方位刻画AI Runtime中的实体与交互关系。所有图谱统一存储、统一关联，形成全局统一的Behavior Graph。

#### 1. Agent Graph（智能体图谱）
- **核心实体**：Agent实例、用户、应用、租户、身份凭证
- **核心关系**：归属关系、协作关系、调用关系、权限关系
- **分析价值**：识别恶意Agent接入、异常协作链路、Agent权限滥用、信誉异常

#### 2. Workflow Graph（工作流图谱）
- **核心实体**：工作流定义、执行节点、分支、依赖、运行实例
- **核心关系**：执行关系、跳转关系、依赖关系、循环关系
- **分析价值**：检测工作流死循环、异常分支利用、逻辑漏洞攻击

#### 3. Memory Graph（记忆图谱）
- **核心实体**：会话、上下文片段、记忆条目、知识库
- **核心关系**：引用关系、继承关系、修改关系、共享关系
- **分析价值**：识别上下文污染、记忆注入、跨会话记忆干扰等隐蔽攻击

#### 4. Tool Graph（工具图谱）
- **核心实体**：工具、接口、后端服务、数据资源
- **核心关系**：调用关系、依赖关系、权限关系、数据流关系
- **分析价值**：检测工具循环调用、高消耗工具滥用、越权工具访问

#### 5. Knowledge Graph（知识图谱）
- **核心实体**：知识条目、概念、文档、数据对象
- **核心关系**：关联关系、引用关系、推理关系
- **分析价值**：识别知识库污染、虚假信息注入、推理链路误导

#### 6. Reasoning Graph（推理图谱）
- **核心实体**：推理步骤、中间结果、决策节点
- **核心关系**：推导关系、因果关系、跳转关系
- **分析价值**：深度刻画模型推理过程，识别推理劫持、逻辑误导等高级攻击

### 8.3 核心产品能力
基于统一行为图谱，输出三大核心产品能力：
1. **异常行为检测**：通过基线对比、图算法、时序分析，识别偏离正常模式的异常行为，发现未知攻击
2. **攻击全链路溯源**：攻击发生后，沿着行为图谱回溯完整攻击路径、影响范围与攻击源头
3. **威胁狩猎**：支持安全分析师通过图查询语言进行主动威胁狩猎，发现潜伏的高级攻击与新型攻击模式

### 8.4 MCP状态机建模
针对MCP协议交互场景，采用有限状态机建模方法，精准刻画Agent与工具、上下文的交互状态变迁。定义所有合法状态与合法变迁路径，自动识别偏离状态机的异常交互，特别适用于检测协议级漏洞利用与异常交互攻击。

## 第九章 Telemetry Plane（遥测平面）
### 9.1 平面定位
遥测平面是整个产品的感知神经系统，负责全栈运行数据的采集、处理、存储与分发，为所有检测、分析、决策、防护能力提供统一的数据底座。它是「可观测性驱动」设计原则的直接体现。

### 9.2 统一遥测七步流水线
```text
Collection → Aggregation → Normalization → Correlation → Storage → Detection → Policy & Visualization
```

#### 1. Collection（多源采集）
- **采集对象**：边缘节点、AI Runtime、算力硬件、Agent、工作流、工具
- **采集方式**：原生埋点（最高精度）、eBPF探针、日志解析、API拉取
- **采集粒度**：支持请求级、会话级、租户级、节点级多粒度采集
- **开销控制**：自适应采样策略，整体采集开销严格控制在**5%以内**

#### 2. Aggregation（流式聚合）
- 基于流计算引擎，对原始数据进行多维度聚合
- 聚合维度：时间维度、租户维度、应用维度、节点维度、模型维度
- 核心价值：降低数据量，提升后续处理效率，支撑宏观态势感知

#### 3. Normalization（标准化处理）
- 统一指标Schema、统一单位、统一标签体系、统一数据格式
- 对多源异构数据进行归一化处理，消除组件间的数据差异
- 核心价值：支撑跨组件、跨层级的关联分析，避免数据孤岛

#### 4. Correlation（全链路关联）
- 单请求全链路关联：将单个请求从边缘到推理的全路径数据串联
- 资源-业务关联：底层资源指标与上层业务指标关联
- 行为-状态关联：行为事件与运行状态关联
- 核心价值：构建完整的上下文，支撑根因分析与深度检测

#### 5. Storage（分层存储）
- **热数据**：内存数据库，秒级查询，保留7天，支撑实时检测与监控
- **温数据**：时序数据库，分钟级查询，保留3个月，支撑近中期分析
- **冷数据**：对象存储，归档备份，保留1年以上，支撑审计与复盘
- 核心价值：平衡查询性能与存储成本，兼顾实时性与长期性需求

#### 6. Detection（实时检测输出）
- 流式异常检测：基于动态基线的实时异常识别
- 阈值告警：基础指标的阈值告警与趋势告警
- 实时推送：将检测信号实时推送给语义检测、行为分析与策略引擎
- 核心价值：将遥测数据转化为检测信号，驱动防护闭环

#### 7. Policy & Visualization（策略反馈与可视化）
- 策略反馈：实时资源状态反馈给策略引擎，动态调整策略阈值
- 可视化输出：支撑控制台的大盘展示、多维下钻、趋势分析
- 数据开放：标准化OpenAPI，支撑第三方系统对接与客户自定义分析

### 9.3 核心遥测指标体系
覆盖八大类核心指标，形成完整的指标体系：推理性能指标、队列指标、算力资源指标、缓存指标、Prompt语义指标、工作流指标、Agent行为指标、内存指标。每类指标均配套默认告警规则、基线模型与可视化视图。

## 第十章 Policy Engine（统一策略引擎）
### 10.1 引擎定位
统一策略引擎是产品的策略中枢，负责全品类防护策略的统一建模、管理、下发与生效，实现**「一处配置，全栈生效，全局协同」**。

传统安全产品各模块各自管理策略，存在策略冲突、配置复杂、联动困难等问题。统一策略引擎从架构层面解决这一问题，将策略能力抽象为独立的基础组件，为所有防护平面提供策略服务。

### 10.2 十大类统一策略体系
覆盖从边缘到运行时的全部防护场景，形成十大类统一策略体系。

| 策略类别 | 核心管控对象 | 典型策略规则 |
| :--- | :--- | :--- |
| Prompt策略 | 请求输入 | 长度限制、高消耗降级、风险Prompt拦截 |
| GPU算力策略 | 算力资源 | 配额规则、优先级规则、抢占规则、过载降级 |
| KV Cache策略 | 缓存资源 | 上下文配额、缓存回收、分片隔离 |
| 队列策略 | 推理队列 | 队列长度、超时时间、调度优先级、反压阈值 |
| 工作流策略 | 工作流 | 步骤限制、时长限制、循环熔断、并发限制 |
| 工具策略 | 工具调用 | 调用配额、权限分级、循环调用熔断 |
| 内存策略 | 内存资源 | 内存配额、泄漏检测、溢出处理 |
| Agent策略 | 智能体 | 准入规则、行为限流、异常终止、信誉分级 |
| API策略 | 接口层 | 接口限流、访问频次、异常参数拦截 |
| Bot策略 | 机器人 | IP信誉、指纹规则、人机验证、爬虫拦截 |

### 10.3 两级引擎架构
采用「控制面集中管理 + 数据面分布式执行」的两级架构，兼顾策略的统一性与执行的高性能。

#### 控制面策略中心
- 负责策略的定义、编辑、审核、发布、版本管理
- 负责策略冲突检测、效果评估、优化建议
- 负责全局策略的统一编排与协同调度

#### 数据面执行端
- 分布式部署在各防护节点，本地缓存策略规则
- 负责策略的高速匹配与执行，保障微秒级时延
- 负责执行结果的上报与反馈

### 10.4 核心产品能力
1. **可视化策略编排**：拖拽式、引导式策略配置，降低使用门槛
2. **策略冲突自动检测**：自动识别策略冲突、重叠与覆盖，给出优化建议
3. **策略灰度发布**：按租户、按比例、按区域灰度生效，降低变更风险
4. **策略仿真验证**：基于历史流量仿真策略效果，预估拦截率与误判率
5. **策略效果统计**：自动统计策略命中数、防护效果、业务影响，支撑优化迭代

## 第十一章 Autonomous Defense（自治防御体系）
### 11.1 自治防御的必要性
AI Native时代，攻击呈现三大特征，使得人工运营的防御模式彻底失效：
- 速度快：算力耗尽攻击数秒内即可打满算力资源，人工分钟级响应完全来不及
- 变化快：AI可快速生成新型攻击模式，人工规则跟不上变化节奏
- 复杂度高：攻击深入运行时内部，涉及多层资源与复杂行为，人工排查难度极大

因此，防御系统必须具备自治能力，实现**以AI防御AI**，以自动化、智能化的防御体系应对自动化、智能化的攻击。

### 11.2 四步自治防御闭环
```text
Attack → Reason → Mitigate → Learn
```

#### 第一步：Attack（攻击感知）
- 多源数据融合：融合遥测、语义检测、行为分析的多源数据，全面感知攻击事件
- 攻击自动识别：自动识别攻击类型、攻击等级、影响范围
- 告警收敛：多源告警关联收敛，避免告警风暴
- 输出：标准化攻击事件，包含完整上下文与初步定级

#### 第二步：Reason（推理研判）
- 根因分析：自动定位攻击根因与攻击入口
- 影响评估：自动评估业务影响范围、受影响的租户与应用
- 态势预测：预测攻击的发展趋势、峰值强度、持续时长
- 输出：攻击研判结论与处置建议方案

#### 第三步：Mitigate（缓解处置）
- 策略自动生成：基于攻击类型与场景，自动生成最优处置策略
- 多平面协同执行：边缘、语义、运行时多层平面协同执行防护动作
- 执行状态监控：实时监控防护执行状态与业务指标变化
- 处置迭代：防护无效时自动调整策略，迭代优化
- 输出：处置执行记录与效果评估报告

#### 第四步：Learn（学习演化）
- 攻击特征提取：自动提取新型攻击的特征与模式
- 检测模型迭代：更新语义检测模型与行为检测规则
- 处置策略优化：优化处置策略库，提升防护效果
- 知识库更新：沉淀攻击案例与处置经验，丰富防御知识库
- 输出：迭代后的模型、规则与策略，实现防御能力持续进化

### 11.3 自治能力分级
- **L1 自动响应级**：已知攻击场景，基于预设策略自动执行处置，覆盖80%常见攻击
- **L2 自主决策级**：未知攻击场景，自主分析、自主决策、自主处置，覆盖绝大多数新型攻击
- **L3 自主演化级**：攻击结束后自主学习、自主迭代，防御能力持续进化，形成永久免疫力

### 11.4 人工介入边界
自治防御并非完全替代人工，而是建立分级的人机协作机制：
- 常规攻击：完全自治，无需人工介入
- 超大规模攻击、跨产品协同处置、高业务影响的策略变更：自治系统提供决策建议，人工一键确认执行
- 高级威胁狩猎、策略体系优化、重大事件复盘：由人工主导，自治系统提供辅助支撑

## 第十二章 产品功能规格（PRD）
本章为核心产品需求规格，按模块定义功能需求与性能指标，可直接支撑研发落地。

### 模块一：边缘网络防护（Edge Protection）
- **需求背景**：终结传统网络层DDoS攻击，将99%的已知攻击拦截在边缘，避免消耗上层资源
- **核心功能**
  1. L3/L4 DDoS攻击防护：支持SYN、UDP、ICMP、ACK等洪水攻击的检测与拦截
  2. 反射放大攻击防护：支持DNS、NTP、SSDP等各类反射放大攻击防护
  3. 协议异常防护：畸形报文、协议异常的识别与过滤
  4. 高级协议支持：原生支持QUIC、HTTP/3、TLS 1.3协议防护
  5. IP信誉与黑白名单：全局IP信誉库、自定义黑白名单
- **性能指标**
  1. 全局清洗容量：≥100Tbps
  2. 单节点处理能力：≥100Gbps
  3. 网络层攻击检测时延：≤50μs
  4. 攻击拦截准确率：≥99.9%
- **验收标准**：指定攻击流量下，业务可用性≥99.99%，攻击拦截率≥99.9%，业务额外时延≤1ms

### 模块二：Prompt洪水防护（Prompt Flood Protection）
- **需求背景**：识别高消耗Prompt攻击，防范语义级算力耗尽攻击
- **核心功能**
  1. Prompt算力消耗实时预估
  2. 高消耗请求识别与分级处置
  3. 长上下文攻击识别与缓存保护
  4. 批量攻击自动聚类与拦截
  5. 放行/限流/降级/拦截四级处置
- **性能指标**
  1. 单请求语义检测时延：≤5ms
  2. 攻击识别准确率：≥95%
  3. 正常请求误判率：≤0.1%
  4. 支持并发：≥100万QPS
- **验收标准**：典型Prompt洪水攻击下，攻击拦截率≥95%，正常请求误判率≤0.1%

### 模块三：GPU算力防护（GPU Protection）
- **需求背景**：保障算力资源可控分配，防范算力耗尽攻击
- **核心功能**
  1. 四级算力配额：租户/应用/会话/用户级配额配置
  2. 五级算力优先级调度，高优先级业务算力抢占
  3. HBM显存防护：配额隔离、溢出保护、碎片治理
  4. 算力过载自动降级，按优先级逐级降级
  5. 算力指标秒级监控与告警
- **性能指标**
  1. 算力配额精度：≥95%
  2. 调度决策时延：≤10ms
  3. 租户间算力干扰：≤5%
- **验收标准**：单租户算力耗尽攻击下，其他租户业务性能下降≤5%，核心业务SLA 100%达标

### 模块四：KV Cache防护（KV Cache Protection）
- **需求背景**：防范长上下文挤占缓存资源，保障缓存高效利用
- **核心功能**
  1. 单会话/单用户上下文长度配额
  2. 智能缓存回收，基于价值优先回收低价值缓存
  3. 租户级缓存分片隔离
  4. 上下文无损/有损压缩
  5. 缓存命中率监控与优化
- **性能指标**
  1. 缓存配额精度：≥98%
  2. 缓存回收时延：≤100ms
  3. 有损压缩比：≥4:1
- **验收标准**：长上下文攻击下，正常业务缓存命中率下降≤10%

### 模块五：工具风暴防护（Tool Storm Protection）
- **需求背景**：防范工具滥用与循环调用攻击，保障工具资源可控
- **核心功能**
  1. 单Agent/单会话工具调用配额管理
  2. 工具循环调用自动检测与熔断
  3. 高消耗工具单独配额与管控
  4. 工具调用拓扑可视化
- **性能指标**
  1. 循环调用检测准确率：≥99%
  2. 熔断响应时延：≤100ms
- **验收标准**：工具循环攻击下，100ms内触发熔断，后端工具可用性≥99.9%

### 模块六：工作流防护（Workflow Protection）
- **需求背景**：防范工作流死循环、死锁攻击，保障工作流稳定执行
- **核心功能**
  1. 工作流最大步骤数、最大时长限制
  2. 死循环自动检测与熔断终止
  3. 依赖死锁自动检测与解除
  4. 异常工作流断点恢复
- **性能指标**
  1. 死循环检测准确率：≥95%
  2. 熔断响应时延：≤1s
- **验收标准**：死循环攻击下，1s内触发终止，正常工作流不受影响

### 模块七：Agent行为治理（Agent Protection）
- **需求背景**：防范恶意Agent接入与异常行为，保障Agent运行秩序
- **核心功能**
  1. Agent统一身份认证与接入鉴权
  2. Agent信誉体系与差异化管控
  3. Agent多维度行为限流
  4. 异常Agent自动检测与终止
  5. A2A交互流量治理
- **性能指标**
  1. 身份鉴权时延：≤1ms
  2. 异常Agent识别准确率：≥90%
- **验收标准**：恶意Agent接入场景下，攻击请求拦截率≥90%

### 非功能需求
- 产品自身可用性：≥99.99%
- 水平扩展性：容量随节点数线性增长
- 兼容性：兼容主流大模型框架、推理引擎与Agent平台
- 安全性：符合等保三级要求，全链路数据加密，细粒度权限管控

## 第十四章 产品商业模式
### 14.1 商业设计原则
基于不同客户类型、部署场景与交付形态，设计多元化商业模式，覆盖从中小客户到大型企业、从公有云到私有化的全场景需求，实现商业价值最大化。

### 14.2 六大商业模式
#### 1. 云服务模式（Cloud Service）
- **形态**：公有云托管服务，客户按需开通、按量付费
- **计费方式**：按防护流量、算力防护量、请求数阶梯计费，提供基础版/专业版/企业版分级订阅
- **目标客户**：中小客户、互联网企业、云原生业务
- **核心优势**：开箱即用、弹性扩容、无需运维
- **商业定位**：流量型基础收入，扩大客户覆盖

#### 2. SaaS模式
- **形态**：独立SaaS服务，跨云、跨环境统一防护
- **计费方式**：年度订阅费 + 超量使用费
- **目标客户**：多云部署客户、混合云客户、非华为云客户
- **核心优势**：统一管理、多云协同、快速接入

#### 3. 软硬一体设备（Appliance）
- **形态**：硬件盒子 + 软件授权，私有化部署
- **计费方式**：硬件采购费 + 年度软件授权服务费
- **产品档位**：入门级、部门级、数据中心级，对应不同性能档位
- **目标客户**：金融、政府、大型企业等私有化需求客户
- **核心优势**：数据本地化、高性能、自主可控
- **商业定位**：高价值收入，服务大客户

#### 4. 托管安全服务（MSS）
- **形态**：产品 + 7*24小时专家运营服务，交付防护效果
- **计费方式**：年度服务费 + 用量费用
- **目标客户**：中大型企业、无专业安全团队的客户
- **核心价值**：交付结果而非产品，客户无需专业运营团队
- **商业定位**：高附加值服务，提升客户粘性与ARPU

#### 5. API服务模式
- **形态**：核心能力以API形式开放，供客户集成到自有系统
- **计费方式**：按调用次数、按算力消耗阶梯计费
- **开放能力**：语义检测API、风险评分API、遥测数据API、策略管理API
- **目标客户**：平台型客户、ISV、AI应用开发商
- **商业定位**：生态型收入，拓展产品边界

#### 6. OEM与生态合作模式
- **形态**：产品能力OEM输出，集成到合作伙伴的产品与解决方案中
- **计费方式**：授权费 + 业务分成
- **合作伙伴**：AI平台厂商、网关厂商、安全厂商、服务器厂商
- **商业定位**：生态拓展，扩大产品覆盖场景与市场空间

### 14.3 整体商业策略
以公有云服务为核心基本盘，以软硬一体与MSS为高价值增长点，以API与OEM拓展生态边界，形成多层次、全覆盖、可持续的商业体系。

## 第十五章 产品演进五阶段
产品演进遵循「从已知到未知、从边缘到内核、从防护到自治」的总体路径，分五个阶段逐步落地、平滑演进，每个阶段都具备独立的商业价值与客户价值。

### Phase 1：Cloud DDoS（云原生DDoS阶段）
- **阶段定位**：基础能力打底，继承传统云DDoS全部能力
- **核心能力**：L3/L4网络层清洗、CC攻击防护、基础Bot防护、全球清洗网络
- **产品形态**：云清洗服务、边缘DDoS防护
- **目标客户**：全量云客户，基础防护需求
- **价值**：构建底层流量防护底座，承接现有客户需求

### Phase 2：Application DDoS（应用层DDoS阶段）
- **阶段定位**：向应用层延伸，覆盖API与应用级耗尽攻击
- **核心能力**：API安全防护、高级Bot管理、应用层CC防护、API速率限制
- **产品形态**：WAAP增强版、API安全防护
- **目标客户**：互联网应用、API密集型业务客户
- **价值**：防护能力从网络层升级到应用层，应对传统应用层耗尽攻击

### Phase 3：AI Runtime（AI运行时防护阶段）
- **阶段定位**：核心能力跃迁，正式进入AI原生防护赛道
- **核心能力**：推理防护、算力防护、KV Cache防护、Prompt语义检测、AI遥测
- **产品形态**：AI Native Anti-DDoS核心产品
- **目标客户**：大模型业务客户、AIGC应用厂商、推理服务提供商
- **价值**：真正进入AI Runtime防护领域，形成核心差异化竞争力

### Phase 4：Agent Runtime（智能体运行时防护阶段）
- **阶段定位**：向业务层延伸，覆盖Agent与工作流全场景
- **核心能力**：Agent身份治理、工作流防护、工具防护、MCP协议防护、行为图谱
- **产品形态**：Agent安全治理套件
- **目标客户**：Agent应用客户、企业级数字员工、多Agent协作系统
- **价值**：防护能力从推理层升级到智能体层，覆盖AI Native业务全场景

### Phase 5：Autonomous Availability Platform（自治可用性平台阶段）
- **阶段定位**：终极形态，从防护产品升级为自治可用性平台
- **核心能力**：全链路自治防御、数字孪生、智能运营、全局可用性调度、业务连续性管理
- **产品形态**：AI Runtime可用性平台
- **目标客户**：大型企业、关键业务系统、AI原生企业
- **价值**：从被动防护升级为主动保障，成为AI时代业务连续性的核心基础设施

## 第十七章 竞争定位与差异化优势
### 17.1 全球主流厂商现状
#### AWS
- 现状：Shield服务提供传统DDoS防护，在WAF中新增基础LLM防护能力，依托Bedrock平台逐步布局AI安全
- 优势：云生态完善，客户基数大
- 不足：AI Runtime防护能力零散，未形成体系化的AI原生可用性架构，算力协同能力不足

#### Azure
- 现状：Azure DDoS Protection提供传统防护，结合OpenAI服务布局AI内容安全，可用性防护尚未体系化
- 优势：OpenAI生态深度绑定
- 不足：聚焦内容安全与合规，可用性防护非重点，底层算力协同不足

#### Google Cloud
- 现状：Cloud Armor提供应用层DDoS，依托Vertex AI布局AI安全，在BeyondProd架构基础上延伸AI场景
- 优势：零信任与云原生架构领先，技术理念前沿
- 不足：产品落地节奏慢，商业化程度低，未形成独立的AI DDoS产品

#### Cloudflare
- 现状：全球最大的边缘DDoS厂商，在边缘WAAP中新增基础Prompt防护能力
- 优势：边缘节点多，带宽容量大，成本低
- 不足：缺乏底层算力栈，无法深入AI Runtime内部，仅能做边缘语义检测，防护深度不足

#### 国内厂商
- 阿里云、腾讯云等厂商传统DDoS业务成熟，依托自有大模型探索AI安全，但AI原生可用性防护均处于早期零散功能阶段，未形成完整的参考架构与产品体系

### 17.2 本产品核心差异化优势
#### 1. 体系化架构领先
全球首个完整的AI原生可用性安全产品体系，从理论、架构到产品形成完整闭环，而非零散功能叠加。七大防护平面、控制面数据面分离、三级语义检测等原创设计，领先行业1-2代。

#### 2. 全栈算力协同优势
深度绑定昇腾算力底座，实现从硬件到应用的全栈协同。硬件级算力隔离、调度、防护能力，是纯软件厂商无法比拟的。算力感知安全织网，实现安全与算力、网络、调度的深度联动，防护效果与效率大幅提升。

#### 3. 防护深度领先
防护边界深入AI Runtime内部，覆盖GPU、HBM、KV Cache、工作流、Agent全层级，而非仅在边缘做语义检测。行为图谱、自治防御等高级能力，实现从被动拦截到主动治理的跃迁。

#### 4. 经济模型领先
三级轻量语义检测架构，实现防护成本远低于攻击成本，具备大规模商业化落地的经济可行性，避免了大模型实时检测的高成本陷阱，在性能、成本、准确率之间取得最优平衡。

#### 5. 全场景部署能力
支持公有云、私有化、SaaS、软硬一体等多种部署形态，覆盖从互联网到政企的全场景客户。依托华为云全栈云能力与政企服务体系，具备端到端的交付与服务能力。
