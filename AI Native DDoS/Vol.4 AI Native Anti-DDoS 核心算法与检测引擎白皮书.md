# 第一篇 Detection Foundation（检测基础）
## 第一章 Detection Architecture（五层检测栈）
### 1.1 传统检测体系的本质局限
传统DDoS检测体系建立在「网络流量特征」之上，核心检测对象是报文、连接与访问频率，所有算法都围绕L3-L7协议特征展开。这一体系在网络时代高效可靠，但在AI Native时代面临根本性的能力盲区：
- **看不到算力消耗**：同样的HTTP请求，算力消耗可相差千倍，流量特征完全无法区分
- **看不到运行时状态**：KV Cache耗尽、推理队列拥堵、工作流死锁等核心故障，网络层完全无感知
- **看不到行为语义**：Agent协作、工具调用、推理过程中的异常模式，无法通过流量特征识别

仅靠Packet层检测，已经无法应对AI原生的耗尽型攻击。检测体系必须向更深层级、更多维度系统性跃迁。

### 1.2 五层检测栈：从数据包到意图
本卷提出AI Native时代的统一检测分层模型——**五层检测栈**，自下而上覆盖从物理流量到业务意图的全维度检测，对应数据面到控制面的不同时延与精度要求。

```text
Intent Layer 意图层
↑
Behavior Layer 行为层
↑
Semantic Layer 语义层
↑
Session Layer 会话层
↑
Packet Layer 数据包层
```

#### Packet Layer（数据包层）
- **检测对象**：网络报文、协议特征、IP五元组
- **核心能力**：传统DDoS攻击检测、协议异常识别、基础速率限制
- **时延要求**：微秒级，线速处理
- **部署位置**：边缘数据平面
- **价值**：终结99%的已知传统攻击，过滤无效流量

#### Session Layer（会话层）
- **检测对象**：连接会话、请求频率、会话行为模式
- **核心能力**：CC攻击检测、Bot识别、API滥用检测、会话异常识别
- **时延要求**：毫秒级
- **部署位置**：边缘数据平面 + 接入层
- **价值**：识别应用层耗尽攻击，过滤自动化恶意流量

#### Semantic Layer（语义层）
- **检测对象**：请求内容、Prompt语义、向量特征、算力消耗预估
- **核心能力**：Prompt洪水检测、高消耗请求识别、语义异常检测
- **时延要求**：毫秒级，单请求<5ms
- **部署位置**：数据面语义检测平面
- **价值**：识别语义级算力攻击，是AI原生检测的第一道智能防线

#### Behavior Layer（行为层）
- **检测对象**：会话全链路行为、Agent交互、工作流执行、工具调用链
- **核心能力**：行为图谱分析、循环调用检测、异常模式识别、攻击溯源
- **时延要求**：秒级到分钟级，异步分析
- **部署位置**：控制面行为分析平面
- **价值**：识别复杂、隐蔽、多步的高级攻击，发现单点检测无法识别的威胁

#### Intent Layer（意图层）
- **检测对象**：请求真实意图、攻击目标、攻击策略、群体协同意图
- **核心能力**：攻击意图推断、恶意行为识别、协同攻击检测、态势预测
- **时延要求**：分钟级，深度推理
- **部署位置**：控制面自治引擎
- **价值**：从「识别攻击行为」升级为「理解攻击目的」，支撑全局智能决策

### 1.3 第一项原创模型：Multi-Layer Detection Pyramid（多层检测金字塔）
**正式提出**：AI Native检测体系呈金字塔结构，底层处理海量流量、规则简单、时延极低，上层处理流量逐级递减、分析深度逐级加深、智能程度逐级提升。各层协同联动，形成「快速过滤-精准识别-深度分析-意图研判」的完整检测闭环。

**模型内涵**：
1. **流量金字塔分布**：99%的流量在底层被快速处理，仅1%的可疑流量进入上层深度分析
2. **能力逐级增强**：从规则匹配到语义分析，再到行为推理、意图研判，检测深度逐层提升
3. **时延逐级放宽**：底层微秒级，上层分钟级，不同层级匹配不同的时延要求
4. **结果逐层反馈**：上层分析结果实时下发到下层，更新下层检测规则，形成上下联动

**架构价值**：完美解决了「检测深度与性能开销」的核心矛盾，在保障极致性能的同时，实现了深度智能检测，是AI原生检测体系的核心架构方法论。

## 第二章 Feature Engineering（特征工程）
### 2.1 特征体系的代际跃迁
特征是检测算法的基础。传统DDoS的特征体系完全围绕网络协议构建，约100+维核心特征，足以支撑网络层与应用层的检测需求。进入AI Native时代，检测对象从网络流量转向AI运行时，特征空间发生了数量级的扩展，新增大量运行时、语义、行为维度的特征。

### 2.2 六大类核心特征体系
#### 1. 网络层特征（传统特征）
继承传统DDoS的全部网络特征，是底层检测的基础。
- 典型特征：报文数、字节数、SYN/ACK比例、TTL分布、TCP Option分布、源IP离散度、目的端口分布
- 检测价值：识别网络层洪水攻击、协议异常、扫描行为

#### 2. 会话层特征
面向连接与会话的统计特征，支撑应用层攻击检测。
- 典型特征：会话时长、请求频率、并发连接数、请求间隔分布、状态码分布、UA指纹、IP信誉
- 检测价值：识别CC攻击、爬虫、慢速连接攻击、API滥用

#### 3. 语义层特征
AI时代新增的核心特征，描述请求内容的语义与消耗属性。
- **Prompt Entropy（Prompt熵值）**：衡量内容的混乱程度与随机性，熵值异常通常对应批量生成的攻击内容
- **Token Velocity（Token增速）**：单位时间内请求/响应的Token增长速率，识别Token爆炸攻击
- **语义复杂度**：基于Embedding计算的语义复杂程度，预估推理算力消耗
- **文本结构特征**：长度、段落数、特殊符号占比、指令关键词密度
- 检测价值：识别Prompt洪水、高消耗请求、语义注入攻击

#### 4. AI运行时资源特征
最具AI特色的特征维度，直接反映底层资源的负载状态。
- **KV Occupancy（KV缓存占用率）**：全局与租户级缓存占用比例
- **GPU Queue Depth（GPU队列深度）**：GPU内核队列等待长度
- **推理时延特征**：TTFT（首Token延迟）、TPS（Token生成速率）、推理总时长
- **显存特征**：HBM带宽占用率、显存使用率、显存碎片率
- **队列特征**：推理队列深度、入队/出队速率、超时率
- 检测价值：直接识别资源耗尽状态，支撑算力感知检测

#### 5. 行为层特征
描述实体交互行为的特征，基于时序与图结构构建。
- **Agent Hop（智能体跳转数）**：单任务中Agent间的交互跳转次数
- **Workflow Width/Depth（工作流宽度/深度）**：工作流的并行分支数与执行步骤数
- **Tool Chain Length（工具调用链长度）**：单次任务中工具调用的链路长度
- **Memory Growth Rate（内存增长率）**：会话/Agent内存的增长速率
- **Reasoning Depth（推理深度）**：思考链步骤数、推理迭代次数
- 检测价值：识别循环调用、行为异常、工作流爆炸等高级攻击

#### 6. 意图层特征
面向攻击目的与策略的高阶特征，通过深度推理提取。
- 典型特征：攻击目标指向性、行为策略性、群体协同度、攻击演化趋势
- 检测价值：支撑意图研判、态势预测、全局决策

## 第三章 AI Runtime Feature Space（AI运行时特征空间）
### 3.1 第二项原创模型：AI Runtime Feature Space
**正式提出**：将网络、会话、语义、运行时资源、行为、意图六大类特征统一映射到标准化的高维特征空间，形成AI运行时统一特征空间。所有检测算法、决策模型、自治引擎均基于该统一特征空间构建，避免多套特征体系带来的数据割裂与重复建设。

**模型内涵**：
1. **统一建模**：所有维度的特征归一化到同一向量空间，支撑跨维度融合计算
2. **可学习性**：特征空间支持机器学习模型直接训练与推理，支撑算法持续迭代
3. **可扩展性**：支持新特征的平滑接入，适配AI Runtime的持续演进
4. **共享复用**：检测、决策、学习全链路复用同一特征空间，保障数据一致性

### 3.2 特征空间矩阵设计
统一特征空间总计500+维核心特征，形成完整的特征矩阵：

| 特征大类 | 特征数量 | 核心维度 | 更新频率 | 主要服务层级 |
| :--- | :--- | :--- | :--- | :--- |
| 网络层特征 | 120+ | 协议、流量、报文、连接 | 微秒级 | 数据包层 |
| 会话层特征 | 80+ | 会话、频率、指纹、状态 | 毫秒级 | 会话层 |
| 语义层特征 | 100+ | 文本、向量、熵值、复杂度 | 毫秒级 | 语义层 |
| 运行时资源特征 | 90+ | 算力、缓存、队列、内存、时延 | 秒级 | 语义层+行为层 |
| 行为层特征 | 80+ | 图结构、时序、交互、链路 | 秒级-分钟级 | 行为层 |
| 意图层特征 | 30+ | 策略、协同、趋势、目标 | 分钟级 | 意图层 |

### 3.3 特征工程核心机制
#### 特征归一化与降维
- 不同量级、不同量纲的特征通过标准化、归一化处理，映射到[0,1]区间
- 采用PCA、自编码器等方法对高维特征降维，在保留核心信息的前提下降低计算开销
- 针对不同检测场景，自动选择最优特征子集，提升检测效率

#### 特征重要性动态评估
- 基于SHAP、信息增益等方法持续评估各特征的检测价值
- 自动淘汰无效特征，加权高价值特征，保障特征空间的高效性
- 新型攻击出现后，自动挖掘新的有效特征，实现特征空间自主演化

#### 特征生命周期管理
- 实时特征：秒级更新，支撑实时检测
- 短期特征：小时级聚合，支撑行为分析
- 长期特征：天级聚合，支撑基线学习与态势分析
- 分层存储，平衡查询性能与存储成本

# 第二篇 AI Runtime Detection Engine（AI运行时检测引擎）
## 第四章 Prompt Flood Detection（Prompt洪水检测）
### 4.1 攻击定义与分类
Prompt洪水是最基础、最常见的AI原生耗尽攻击，攻击者通过构造大量高消耗Prompt请求，挤占推理算力与缓存资源，造成服务不可用。与传统CC攻击不同，其破坏力不来自请求频率，而来自单请求的算力消耗。

主流攻击类型包括：
1. **长度型洪水**：构造超长Prompt，直接挤占KV Cache与算力
2. **熵变型洪水**：生成高熵值、高复杂度的随机文本，最大化推理计算量
3. **循环扩展型**：诱导模型不断扩展输出，形成输出爆炸
4. **递归型洪水**：构造递归式指令，让推理过程自我嵌套
5. **Prompt Bomb（Prompt炸弹）**：极短输入触发极长输出与极高算力消耗，投入产出比极高
6. **注入型耗尽**：通过Prompt注入触发高消耗任务，如复杂代码生成、大规模计算

### 4.2 多层级检测算法体系
#### 1. 统计特征快速检测
基于表层统计特征实现毫秒级快速过滤，覆盖80%以上的简单攻击。
- **长度异常检测**：基于动态基线的Prompt长度异常识别，区分正常长文本与攻击长文本
- **Token速率检测**：单位时间内单用户/单IP的Token请求速率异常检测
- **熵值异常检测**：Prompt信息熵分布异常识别，批量随机生成内容的熵值显著异于正常文本
- **关键词密度检测**：高消耗指令关键词（如「详细分析」「分步推导」「完整代码」）的异常密度检测

#### 2. Embedding相似度检测
基于向量特征识别批量相似攻击与语义变体攻击。
- **批量聚类检测**：短时间内大量请求的Embedding向量高度聚类，通常对应批量生成的攻击
- **异常距离检测**：请求向量与正常请求基线中心的距离异常，识别偏离正常分布的请求
- **语义变体识别**：同一攻击语义的不同表述变体，通过向量相似度统一识别

#### 3. 序列模式检测
针对循环、递归、扩展等复杂攻击模式，基于序列建模识别。
- **循环模式识别**：检测Prompt中的循环指令、自我引用模式
- **递归深度预估**：基于语义特征预估推理递归深度，识别递归型攻击
- **膨胀模式检测**：识别会导致输出指数级膨胀的Prompt模式

#### 4. 算力消耗预估模型
基于多维度特征构建单请求算力消耗预估模型，直接识别异常高消耗请求。
- 输入特征：Prompt长度、语义复杂度、指令类型、历史平均消耗
- 输出：预估算力消耗值（GPU毫秒数）
- 检测逻辑：消耗值远超同类型请求基线，判定为高风险攻击
- 模型精度：预估误差控制在20%以内，足以支撑分级限流与调度

### 4.3 检测性能指标
- 单请求检测时延：≤5ms
- 典型攻击识别准确率：≥95%
- 正常请求误判率：≤0.1%
- 支持并发：≥100万QPS

## 第五章 Slow Token Detection（慢速Token攻击检测）
### 5.1 攻击定义：AI时代的Slowloris
Slow Token攻击是AI原生的慢速耗尽攻击，对标传统网络的Slowloris攻击，是极具隐蔽性的高级攻击形态。

**攻击原理**：攻击者发起推理请求后，控制输出速率维持在极低水平（如1 token/s甚至更低），长时间占用推理会话、KV Cache资源与GPU算力槽位。单次请求持续数十分钟甚至数小时，用极少的请求数即可占满全部并发槽位，导致新请求无法接入。

**攻击特点**：
- 流量极小，完全符合协议规范，传统检测完全无感知
- 单请求即可占用一路并发，攻击成本极低
- 攻击持续时间长，资源释放慢，恢复难度大
- 隐蔽性极强，与正常慢速输出场景边界模糊

### 5.2 攻击破坏路径
```text
慢速请求发起 → 占用推理会话槽位 → 长期占用KV Cache → 锁住GPU并发通道
                          ↓
新请求排队 → 队列溢出 → 服务不可用
```

### 5.3 核心检测算法
#### 1. TPS动态基线检测
最核心的检测指标，识别异常偏低的Token生成速率。
- 为不同业务、不同模型、不同请求类型建立TPS正常基线
- 单会话Token生成速率持续低于基线阈值，触发风险标记
- 结合请求类型与上下文长度，排除正常的慢速推理场景（如复杂代码生成）

#### 2. TTFT与推理时长检测
- **首Token延迟（TTFT）异常**：正常范围内的TTFT是推理性能的体现，异常超长的TTFT通常对应异常请求或攻击
- **推理总时长异常**：单会话推理总时长远超同类型请求基线，是Slow Token攻击的核心特征
- 时长-长度偏离度：推理时长与输出Token长度的比值异常偏高，说明单位Token生成时间过长

#### 3. KV Cache心跳检测
基于缓存驻留特征识别长期占用的异常会话。
- **缓存驻留时长**：单会话KV Cache持续驻留时间远超基线
- **缓存活跃度**：驻留期间缓存访问频率极低，说明会话处于低活性状态
- **缓存资源占比**：少量长驻留会话占用了大量缓存空间，是攻击的典型特征

#### 4. 会话资源效率评估
从资源投入产出比的角度识别异常。
- 定义资源效率 = 有效输出Token数 / 资源占用时长
- 资源效率显著低于正常基线的会话，判定为高风险
- 结合语义特征，区分正常长时推理与恶意慢速攻击

### 5.4 误判规避机制
- 白名单机制：已知的长时推理任务、流式输出场景加入白名单
- 业务维度区分：不同业务设置不同阈值，避免一刀切
- 多因子综合判定：多维度特征融合评分，避免单一指标误判
- 渐进式处置：先预警、再限流、最后终止，避免误杀正常请求

## 第六章 Context Flood Detection（上下文洪水检测）
### 6.1 攻击原理与模式
上下文洪水攻击针对大模型的上下文记忆机制，通过持续注入内容、扩展对话窗口，造成上下文内存爆炸、KV Cache耗尽、推理性能断崖式下降。

主流攻击模式：
1. **窗口持续增长型**：每轮对话持续追加内容，让上下文窗口无限增长，逐步占满缓存
2. **记忆注入型**：向Agent记忆中批量注入无效内容，造成记忆膨胀，检索效率下降
3. **共享上下文污染型**：在多租户共享缓存场景下，通过特定请求挤占全局共享缓存，影响所有租户
4. **上下文碎片型**：大量短会话频繁创建销毁，产生大量缓存碎片，导致连续缓存空间不足

### 6.2 核心检测算法
#### 1. 上下文增长动力学检测
基于时序模型检测上下文的异常增长模式。
- **窗口增长斜率**：单会话上下文Token数的增长速率，斜率异常持续升高为风险信号
- **增长模式拟合**：正常对话的上下文增长呈收敛趋势，攻击呈线性/指数增长趋势
- **累计长度分布**：会话总上下文长度的分布异常，长尾占比显著提升

#### 2. 内存增长曲线检测
从内存资源维度反向验证上下文爆炸。
- 会话内存占用的增长曲线与上下文长度增长曲线的匹配度分析
- 单位Token内存占用异常升高，识别内存泄漏型攻击
- 全局内存占用率与会话数的偏离度检测

#### 3. 上下文有效性评估
通过语义分析识别冗余无效的上下文注入。
- **信息密度检测**：上下文中有效信息占比，攻击注入的内容通常冗余度极高
- **重复度检测**：大量重复、相似内容的注入是攻击的典型特征
- **语义相关性检测**：新增内容与对话主题的相关性极低，对应恶意注入

#### 4. 跨会话关联检测
针对共享缓存场景的攻击识别。
- 多会话同时出现上下文异常增长，存在协同攻击嫌疑
- 全局缓存命中率突然下降，碎片率升高，对应碎片型攻击
- 租户间缓存占用不均衡，单租户异常占用大量缓存

## 第七章 Embedding Flood Detection（向量洪水检测）
### 7.1 攻击定义与场景
Embedding洪水是针对向量计算服务的专用耗尽攻击，目标是RAG系统、向量数据库、Embedding服务等向量化组件。攻击者构造大批量高维向量计算请求，打面向量化算力与索引查询资源。

**典型攻击场景**：
- 大批量文本向量化请求，打满Embedding GPU算力
- 高频ANN检索请求，占满向量数据库查询资源
- 构造极端维度/批次的向量请求，造成索引服务崩溃

### 7.2 攻击破坏路径
```text
批量向量请求 → Embedding算力耗尽 → 向量索引查询拥堵
                          ↓
RAG服务不可用 → 依赖向量的推理服务全面降级
```

### 7.3 核心检测算法
#### 1. 请求特征检测
基于向量请求的统计特征快速识别攻击。
- 批次大小异常：单请求向量计算批次远超正常基线
- 请求频率异常：单用户/单IP的向量请求频率异常升高
- 维度分布异常：请求的向量维度、文本长度分布偏离正常范围

#### 2. 索引负载检测
从向量数据库与索引服务侧检测异常。
- 查询深度异常：单次召回结果数、检索深度远超正常水平
- 索引计算耗时：单次查询耗时持续升高，对应索引资源耗尽
- 索引吞吐量：单位时间处理的查询量突增，伴随时延飙升

#### 3. 向量相似度分布检测
识别批量生成的攻击向量。
- 批量请求的向量相似度极高，对应批量生成的相似内容
- 向量分布异常，集中在特征空间的局部区域
- 语义无效向量，内容无实际意义，仅用于消耗算力

#### 4. 计算效率基线检测
- 单位向量的计算耗时异常升高，对应算力饱和
- 计算吞吐量与请求量的非线性偏离，识别资源瓶颈点
- 向量计算错误率、超时率异常升高

## 第八章 Inference Queue Flood Detection（推理队列洪水检测）
### 8.1 队列动力学基础
推理队列是连接请求与GPU算力的缓冲层，也是可用性故障的核心发生点。当请求到达速率超过GPU处理能力时，队列深度持续增长，最终导致请求超时、服务不可用。

队列洪水分为两类：
- **正常峰值**：业务突发流量导致的队列增长
- **恶意攻击**：攻击者发起大量请求恶意挤占队列资源

### 8.2 核心检测算法
#### 1. 队列时序异常检测
基于时序模型识别队列的异常增长模式。
- 核心指标：队列深度、入队速率、出队速率、平均等待时长、超时率
- 检测方法：
  - 动态阈值检测：基于历史基线的自适应阈值告警
  - 趋势预测检测：通过ARIMA、LSTM等时序模型预测队列增长趋势，提前预警
  - 增长斜率检测：队列深度短时间内陡峭上升，通常对应攻击

#### 2. 排队论模型拟合检测
基于M/M/c排队论模型识别异常状态。
- 建立正常业务下的排队模型，计算理论队列深度与等待时长
- 实际指标显著偏离理论值，说明存在异常请求或攻击
- 实时计算服务强度ρ，ρ>0.8时进入预警状态，ρ>0.95时进入告警状态

#### 3. 全链路传导检测
识别队列拥堵的传导链路，定位拥堵根因。
- 传导路径：请求到达 → 队列增长 → 时延升高 → 超时率上升
- 检测各环节的传导关系是否匹配正常模式
- 区分「入口请求过多」与「后端处理变慢」两种不同根因

#### 4. 攻击与正常峰值区分算法
核心难点，也是检测的关键价值。
- **请求构成差异**：攻击流量的高消耗请求占比显著高于正常峰值
- **用户分布差异**：攻击流量的源IP、用户ID离散度更高，新用户占比高
- **资源消耗差异**：同等QPS下，攻击造成的算力消耗远高于正常峰值
- **行为模式差异**：攻击请求行为模式单一，正常峰值呈现多样性

## 第九章 GPU Starvation Detection（GPU饥饿检测）
### 9.1 攻击定义：GPU级拒绝服务
GPU饥饿攻击是最底层、破坏力最强的AI原生耗尽攻击。攻击者构造极端算力消耗的推理任务，打满GPU计算核心、HBM带宽、内核调度队列，造成GPU算力完全饱和，所有共享该GPU的业务全部性能暴跌。

**攻击分类**：
1. **HBM带宽耗尽型**：构造高显存访问需求的任务，打满HBM带宽，让计算核心空等数据
2. **计算核心占满型**：构造高计算密度任务，100%占满SM核心与张量核心
3. **内核队列阻塞型**：大量小内核任务持续提交，占满内核调度队列，造成调度死锁
4. **显存碎片型**：频繁申请释放显存，产生大量碎片，导致大显存需求无法分配

### 9.2 第三项原创模型：Compute-aware Detection（算力感知检测）
**正式提出**：AI原生检测必须是算力感知的，检测算法不能仅依赖请求本身的特征，必须结合GPU、HBM、KV Cache、推理队列等底层硬件资源的实时状态。只有将流量特征与资源状态结合，才能精准识别算力耗尽攻击，区分正常负载与恶意攻击。

**模型内涵**：
1. **资源状态是检测的核心依据**：是否发生算力耗尽，最终由资源状态判定
2. **请求特征与资源状态关联**：将单个请求与它造成的资源消耗关联，定位攻击源
3. **动态基线随资源状态调整**：检测阈值随硬件负载动态变化，避免高负载下误判
4. **根因定位到资源维度**：精准定位是哪类资源耗尽，支撑针对性缓解

### 9.3 核心检测算法
#### 1. 硬件性能计数器检测
基于GPU硬件底层的性能计数器数据，实现最精准的资源状态感知。
- **SM利用率**：流式多处理器的利用率，持续100%且伴随性能下降为异常
- **HBM带宽利用率**：高带宽显存的读写带宽占比，是最核心的瓶颈指标
- **张量核心利用率**：张量计算核心的占用率
- **内核队列深度**：GPU内核调度队列的等待长度，队列持续增长为异常
- **显存碎片率**：显存空闲但连续空间不足的比例

#### 2. 单请求算力消耗归因
将全局算力消耗归因到单个请求，精准定位攻击源。
- 基于请求特征预估算力消耗，匹配实际资源增量
- 采用因果推断方法，关联请求进入与资源变化的时序关系
- 租户级、会话级、请求级的算力消耗归因，粒度逐级细化

#### 3. 算力效率异常检测
从投入产出比角度识别异常。
- 定义算力效率 = 有效输出Token数 / GPU算力消耗
- 算力效率持续低于基线，说明存在无效算力消耗，大概率为攻击
- 不同业务、不同模型设置差异化的效率基线

#### 4. 多租户算力干扰检测
针对共享GPU场景，识别单租户挤占全部算力的攻击。
- 单租户算力占用比例远超其配额
- 单租户负载升高导致其他租户性能同步下降
- 租户间算力隔离失效的检测与告警

## 第十章 KV Cache Protection（KV缓存防护）
### 10.1 KV Cache的战略地位
KV Cache是大模型推理的核心性能组件，存储上下文的键值计算结果，避免重复计算。它的容量极其有限，是推理性能最核心的瓶颈资源，也是攻击者最青睐的靶点。

**核心攻击模式**：
- 长上下文挤占：超长上下文一次性占满缓存
- 缓存驻留耗尽：大量长会话长期驻留缓存不释放
- 缓存碎片攻击：频繁创建销毁短会话，产生大量碎片
- 共享缓存污染：跨会话挤占全局共享缓存

### 10.2 检测与防护算法体系
#### 1. 缓存占用时序检测
- 全局与租户级缓存占用率的实时监控与异常告警
- 缓存占用增长速率检测，识别快速挤占攻击
- 缓存命中率异常下降检测，对应缓存污染或碎片

#### 2. 缓存生命周期检测
- 单缓存块的驻留时长分布检测，异常长驻留会话识别
- 缓存访问频率检测，低访问频率的缓存优先回收
- 缓存生命周期与业务类型的匹配度分析

#### 3. 缓存碎片检测
- 实时计算缓存碎片率：空闲缓存中不可用碎片的占比
- 碎片增长速率异常检测，识别碎片型攻击
- 连续大空间占比下降告警

#### 4. 智能缓存回收算法
防护侧的核心能力，基于价值的缓存调度。
- 缓存价值评分：综合访问频率、业务优先级、剩余时长、上下文重要性
- 智能淘汰策略：优先回收价值最低的缓存，保障高价值业务
- 主动碎片整理：低负载时自动整理缓存碎片，提升可用空间
- 租户级分片隔离：不同租户的缓存物理分片，避免相互挤占

# 第三篇 Agent Detection Engine（智能体检测引擎）
## 第十一章 Agent Graph（智能体行为图谱）
### 11.1 第四项原创模型：Behavior Graph（行为图谱）
**正式提出**：将Agent、工具、工作流、记忆、交互关系统一建模为动态行为图谱，通过图算法检测异常行为模式。行为图谱是Agent时代检测高级攻击的核心方法论，能够识别单点特征无法发现的循环、协同、链式攻击。

**模型内涵**：
1. **统一图建模**：所有实体与交互都抽象为图的节点与边，统一建模框架
2. **结构即特征**：图的结构特征（环、路径、子图）是攻击检测的核心依据
3. **动态演化**：图谱随时间持续演化，检测也是动态的流式过程
4. **全局视角**：从全局图谱视角识别协同攻击、扩散攻击，突破单点检测局限

### 11.2 行为图谱的构建
#### 核心节点类型
- Agent节点：各类智能体实例，包含属性：ID、类型、优先级、信誉分
- 工具节点：各类工具与API接口，包含属性：类型、消耗、权限等级
- 工作流节点：工作流定义与实例，包含属性：步骤数、预期时长、业务等级
- 记忆节点：上下文、记忆、知识库，包含属性：大小、访问频率、所属主体
- 用户节点：触发任务的用户/应用，包含属性：身份、权限、历史行为

#### 核心边类型
- 调用边：Agent调用工具、Agent调用Agent、工作流调用工具
- 跳转边：工作流步骤跳转、Agent状态跳转、推理步骤跳转
- 依赖边：资源依赖、数据依赖、执行依赖
- 归属边：Agent归属用户、记忆归属Agent、工具归属工作流

#### 图谱属性体系
- 结构属性：节点度、介数中心性、路径长度、环数量
- 时序属性：调用频率、响应时长、执行时长、出现时间
- 风险属性：风险评分、历史异常次数、信誉分

### 11.3 基于图谱的核心检测能力
1. **环检测**：自动识别调用环、执行环、依赖环，对应循环攻击
2. **路径异常检测**：执行路径长度、跳转次数远超基线
3. **子图异常检测**：异常子结构、异常交互模式识别
4. **传播扩散检测**：异常行为在图谱中的扩散传播识别
5. **群体协同检测**：多节点协同异常行为识别

## 第十二章 Tool Storm（工具风暴检测）
### 12.1 攻击定义与原理
工具风暴是Agent场景下的典型耗尽攻击，攻击者诱导Agent高频调用工具、循环调用工具、批量调用高消耗工具，耗尽后端工具服务的算力与接口资源。

**攻击模式**：
1. **循环调用**：让Agent在多个工具间循环调用，形成调用死循环
2. **高频调用**：短时间内发起海量工具调用请求，打满接口配额
3. **高消耗工具滥用**：持续调用最消耗算力的工具（如代码解释器、文件分析）
4. **链式调用放大**：一个工具调用触发更多工具调用，形成链式放大效应

### 12.2 核心检测算法
#### 1. 调用频次与并发检测
- 单Agent/单会话的工具调用频率、并发数异常检测
- 单位时间调用次数的动态基线告警
- 工具接口的整体QPS、错误率、时延异常检测

#### 2. 循环调用检测
基于行为图谱的环检测能力，精准识别工具调用循环。
- 有向环检测：在工具调用有向图中检测环路
- 循环次数统计：循环执行次数超过阈值触发熔断
- 循环变体识别：参数微调的近似循环调用识别

#### 3. 工具消耗评估
- 建立每种工具的基准算力消耗与时间消耗
- 单工具调用的消耗异常升高检测
- 高消耗工具的调用占比异常升高，对应针对性攻击

#### 4. 调用链异常模式识别
- 调用链长度异常，远超正常业务的平均长度
- 调用链的业务相关性低，无明确业务目标
- 调用模式匹配已知攻击图谱，直接判定风险

## 第十三章 Workflow Explosion（工作流爆炸检测）
### 13.1 攻击定义与模式
工作流爆炸攻击针对多步骤Agent工作流，构造异常工作流实例，造成步骤爆炸、分支爆炸、循环执行、依赖死锁，耗尽工作流引擎资源与后端算力。

**攻击模式**：
1. **深度爆炸**：工作流执行步骤无限延伸，流程深度失控
2. **宽度爆炸**：触发大量并行分支，工作流宽度指数级增长
3. **循环执行**：工作流在若干步骤间循环往复，永不结束
4. **依赖死锁**：构造循环依赖，导致工作流实例永久等待

### 13.2 核心检测算法
#### 1. DAG结构异常检测
- 工作流有向无环图（DAG）的深度、宽度、节点数异常检测
- 节点数与业务复杂度的匹配度分析
- 并行分支数远超正常业务基线

#### 2. 循环执行检测
- 工作流实例的步骤跳转图谱中的环检测
- 重复步骤执行次数超限告警
- 执行路径的自相似性检测，识别循环变体

#### 3. 执行时长异常检测
- 单工作流实例的总执行时长远超同类型基线
- 单步骤执行时长异常，对应步骤阻塞
- 执行进度停滞检测，长时间无进展

#### 4. 依赖死锁检测
- 基于图的依赖环检测，预判死锁风险
- 等待状态持续时长检测，永久等待识别
- 资源等待图谱分析，定位死锁根源

## 第十四章 Reasoning Abuse（推理滥用检测）
### 14.1 攻击定义：隐蔽的算力黑洞
推理滥用是极具隐蔽性的高级算力耗尽攻击，攻击者通过Prompt诱导模型进行无限链式思考（Chain-of-Thought）、多步递归推理、自我追问式推导，让推理深度失控，输出Token指数级增长，用极低输入成本占用GPU算力极长时间。

**攻击特点**：
- 表面是正常的提问与推导，语义上完全合法
- 单请求即可长时间占用算力，攻击成本极低
- 传统长度检测、频率检测完全失效
- 是目前全球研究最少、防护最薄弱的攻击形态

### 14.2 第五项原创模型：Intent-aware Decision（意图感知决策）
**正式提出**：AI原生检测必须从「请求是否合法」升级为「请求意图是什么」。通过语义理解与行为分析，推断请求的真实目的与潜在影响，而不仅基于表层特征判断。只有识别出「滥用推理」的真实意图，才能有效防御推理滥用这类隐蔽攻击。

**模型内涵**：
1. **从特征到意图**：检测的核心依据从表层特征升级为真实意图
2. **上下文关联**：结合历史行为与完整上下文，推断请求真实目的
3. **影响预判**：预判请求对资源与可用性的潜在影响，而非事后检测
4. **分级处置**：基于意图风险等级执行差异化处置，而非简单拦截

### 14.3 核心检测算法
#### 1. 推理深度识别
- 输出内容中的思考步骤数、推理层级数统计
- 自我追问、分步推导、递归思考等模式的语义识别
- 推理深度与输入复杂度的偏离度检测，正常问题推理深度有限

#### 2. 算力消耗偏离度评估
- 单位输入Token对应的输出Token数，远超基线为异常
- 单位输入对应的GPU算力消耗，偏离度越高风险越高
- 推理过程的算力消耗曲线异常，呈持续高位而非逐步下降

#### 3. 推理有效性评估
- 推理过程的有效信息密度，大量重复、无意义推导为异常
- 逻辑闭环检测，推理是否指向明确结论，还是无限发散
- 推理结果与输入问题的相关性，相关性越低越可能是滥用

#### 4. 意图分类模型
- 基于SLM的细粒度意图分类，区分正常咨询、正常推导、恶意推理滥用
- 结合历史行为序列，提升意图识别准确率
- 输出意图风险评分，支撑后续决策

## 第十五章 Memory Flood（记忆洪水检测）
### 15.1 攻击定义与模式
记忆洪水攻击针对Agent的长期记忆与知识库系统，通过批量注入无效、冗余、恶意内容，造成记忆膨胀、检索效率下降、内存资源耗尽，甚至污染共享记忆影响所有Agent。

**攻击模式**：
1. **容量耗尽型**：批量写入大量内容，占满记忆存储空间
2. **性能降级型**：注入大量低价值记忆，降低检索准确率与速度
3. **污染型**：注入错误、恶意的记忆内容，误导Agent行为
4. **遍历攻击**：高频遍历整个记忆库，耗尽检索算力

### 15.2 核心检测算法
#### 1. 记忆增长速率检测
- 单Agent/单知识库的记忆增长速率异常检测
- 写入频率、写入量的动态基线告警
- 内存占用与记忆条数的匹配度分析

#### 2. 记忆质量评估
- 内容冗余度、重复度检测，大量重复内容为攻击特征
- 语义有效性评估，无实际意义的内容占比异常
- 记忆与业务主题的相关性检测

#### 3. 访问行为异常检测
- 异常批量读取、全量遍历行为识别
- 检索频率、检索深度异常
- 检索结果的利用率极低，对应无效遍历攻击

#### 4. 记忆污染检测
- 记忆内容的语义异常、错误信息识别
- 异常记忆的扩散传播检测
- 记忆对Agent行为的负面影响评估

## 第十六章 Agent Swarm（智能体集群攻击检测）
### 16.1 攻击定义：群体协同攻击
Agent Swarm攻击是多智能体时代的新型攻击形态，攻击者控制大量恶意Agent协同发起攻击，分工配合、多维度同时发力，形成集群攻击效应，破坏力远大于单Agent攻击。

**攻击模式**：
1. **共识型协同**：大量Agent同时发起同类攻击，形成流量/算力共振
2. **分工型协同**：不同Agent负责不同攻击维度，有的打算力、有的打工具、有的打记忆
3. **链式传导型**：一个恶意Agent感染更多Agent，攻击链逐级放大
4. **A2A风暴**：Agent间大量无效交互，形成Agent间的通信风暴

### 16.2 核心检测算法
#### 1. 群体行为聚类检测
- 多Agent的行为特征向量聚类，高度相似的Agent集群为高风险
- 请求时间、请求内容、行为模式的同步性检测
- 新注册Agent批量出现，同时发起高消耗请求

#### 2. 交互图谱异常检测
- Agent间交互拓扑异常，形成密集交互的恶意集群
- 交互频率异常升高，无明确业务目标的无效交互
- 异常传播路径检测，识别攻击从单Agent向多Agent的扩散

#### 3. 资源共振检测
- 多Agent同时发起高消耗任务，造成资源负载的共振峰值
- 资源负载的周期性波动，对应协同攻击的节奏
- 不同维度资源同时耗尽，对应多维度协同攻击

#### 4. 群体信誉评估
- 基于Agent的历史行为、身份来源、关联关系，计算群体信誉分
- 低信誉Agent集群出现高风险行为，直接判定攻击
- 信誉体系动态更新，持续识别新型恶意Agent集群

# 第四篇 Decision Engine（决策引擎）
## 第十七章 Risk Score（统一风险评分）
### 17.1 多维度风险融合框架
统一风险评分是决策引擎的核心输入，将六大类检测结果融合为0-100的标准化风险分，支撑后续的策略匹配与处置执行。

**融合公式**：
```
RiskScore = W1 × TrafficRisk + W2 × SemanticRisk + W3 × BehaviorRisk + W4 × ResourceRisk
```
- TrafficRisk：网络与流量维度风险分
- SemanticRisk：语义与内容维度风险分
- BehaviorRisk：行为与图谱维度风险分
- ResourceRisk：运行时资源维度风险分
- W1-W4：动态权重，随场景、业务、资源状态自适应调整

### 17.2 各维度评分计算
#### 流量风险分
- 基于IP信誉、访问频率、协议异常、Bot特征计算
- 侧重识别传统网络层与应用层攻击
- 实时性最高，计算时延最低

#### 语义风险分
- 基于Prompt特征、Embedding相似度、意图识别结果计算
- 侧重识别Prompt洪水、推理滥用等语义级攻击
- 毫秒级计算时延

#### 行为风险分
- 基于行为图谱、历史行为序列、交互模式计算
- 侧重识别循环攻击、协同攻击、高级持久攻击
- 秒级到分钟级计算时延

#### 资源风险分
- 基于GPU、缓存、队列、内存等资源状态计算
- 反映当前资源耗尽程度与攻击实际影响
- 是风险评分的兜底校准维度

### 17.3 风险等级划分
基于风险评分划分为四个等级，对应不同的处置策略：
- **低风险（0-30）**：正常请求，直接放行
- **中风险（30-60）**：可疑请求，限流/降级处理，持续观察
- **高风险（60-85）**：恶意请求，隔离/暂停，进一步核验
- **极高风险（85-100）**：明确攻击，直接拦截/终止，加入黑名单

### 17.4 动态校准机制
- **资源状态校准**：资源越紧张，相同行为的风险评分越高
- **业务优先级校准**：核心业务的风险判定更谨慎，避免误判影响
- **历史反馈校准**：基于历史误判漏判反馈，动态调整权重与阈值

## 第十八章 Policy Engine（策略引擎）
### 18.1 第六项原创模型：Adaptive Policy Engine（自适应策略引擎）
**正式提出**：AI原生防护的策略引擎必须是自适应的，基于实时风险评分、运行时资源状态与业务优先级动态生成最优策略，而非依赖固定的人工规则。固定规则无法适配AI场景的多变性与动态性，自适应是唯一可行的策略范式。

**模型内涵**：
1. **策略动态生成**：没有预设的固定规则，策略实时计算生成
2. **多因子决策**：综合风险、资源、业务、成本多维度因子
3. **持续优化**：基于防护效果反馈持续优化策略生成模型
4. **分级精准**：从放行到拦截之间存在大量分级策略，而非二元决策

### 18.2 十大类策略体系
策略引擎统一管理全品类防护策略，覆盖从边缘到运行时的全部场景。
1. **Prompt策略**：长度限制、降级规则、拦截规则
2. **GPU算力策略**：配额调整、优先级调度、抢占规则
3. **KV缓存策略**：配额调整、回收优先级、分片隔离
4. **队列策略**：队列长度调整、调度优先级、反压阈值
5. **工作流策略**：步骤限制、时长限制、熔断规则
6. **工具策略**：调用配额、权限管控、熔断规则
7. **内存策略**：配额限制、回收规则、隔离规则
8. **Agent策略**：准入规则、行为限流、异常终止
9. **API策略**：接口限流、频次限制、访问控制
10. **Bot策略**：IP封禁、指纹拦截、人机验证

### 18.3 策略生成与执行机制
#### 策略生成逻辑
```
输入：风险等级 + 资源状态 + 业务优先级 + 场景类型
↓
策略匹配模型
↓
输出：最优策略组合 + 执行强度 + 生效范围 + 持续时长
```

#### 核心机制
- **策略冲突检测**：自动检测多策略间的冲突与重叠，生成最优组合
- **策略灰度生效**：按比例、按租户逐步生效，避免全局震荡
- **策略效果实时评估**：生效后持续评估防护效果与业务影响
- **策略自动回退**：造成严重业务影响的策略自动回滚，保障可用性

## 第十九章 Mitigation Engine（缓解执行引擎）
### 19.1 五级缓解手段体系
缓解执行引擎提供从温和到严厉的五级缓解手段，根据风险等级精准匹配，最小化业务影响。

#### 一级：流量调节类（最温和）
- **速率限制**：降低请求通过速率，平滑峰值
- **平滑排队**：将请求放入低优先级队列，延后处理
- **流量调度**：将流量调度到空闲节点，分散压力
- 适用场景：低风险、疑似异常、正常峰值

#### 二级：资源管控类
- **配额限制**：收紧对应实体的资源配额
- **资源隔离**：将可疑实体隔离到独立资源池
- **优先级降级**：降低调度优先级，保障高优先级业务
- 适用场景：中风险、确认异常但不宜直接拦截

#### 三级：服务降级类
- **推理降级**：降低推理精度、缩短最大输出、切换小模型
- **上下文截断**：截断超长上下文，限制缓存占用
- **功能降级**：临时关闭非核心功能，如工具调用、高级推理
- 适用场景：高负载、攻击期间，保障核心功能可用

#### 四级：暂停冻结类
- **工具冻结**：暂停对应实体的工具调用权限
- **工作流暂停**：暂停异常工作流实例的执行
- **Agent挂起**：挂起可疑Agent，等待进一步核验
- 适用场景：高风险、明确异常，需临时阻断

#### 五级：终止封禁类（最严厉）
- **请求终止**：终止当前异常请求
- **会话断开**：断开异常会话，释放资源
- **Agent销毁**：销毁恶意Agent实例
- **IP/身份封禁**：加入黑名单，禁止接入
- 适用场景：极高风险、明确攻击

### 19.2 缓解执行原则
1. **最小影响原则**：优先使用温和手段，尽可能保障业务可用
2. **渐进式处置**：从温和到严厉逐步升级，避免误判造成严重影响
3. **协同执行原则**：多维度缓解手段协同生效，形成合力
4. **自动恢复原则**：攻击结束后自动解除限制，恢复正常服务

# 第五篇 Autonomous Defense（自治防御）
## 第二十章 Autonomous Reasoning（自治推理）
### 20.1 自治推理的定位
自治推理是自治防御的大脑，负责攻击事件的深度分析、根因研判与态势预测，运行在控制面，异步执行，不占用数据面时延预算。

它的核心价值是：替代人工完成攻击分析与研判，将人工响应的分钟级时延压缩到秒级，跟上AI攻击的速度。

### 20.2 七步推理闭环
```
事件聚合 → 链路还原 → 根因定位 → 影响评估 → 态势预测 → 方案生成 → 决策输出
```

#### 1. 事件聚合
- 多源告警关联收敛，将零散告警聚合为完整攻击事件
- 补充事件上下文：时间、范围、涉及资产、当前状态
- 去重降噪，避免告警风暴

#### 2. 链路还原
- 基于行为图谱与全链路遥测，还原完整攻击路径
- 定位攻击入口、攻击传播链路、影响范围
- 可视化呈现攻击全流程

#### 3. 根因定位
- 分析攻击的根本原因：是哪类攻击、利用了什么脆弱点
- 定位故障的核心瓶颈：是算力耗尽、缓存不足还是队列拥堵
- 输出根因结论与置信度

#### 4. 影响评估
- 评估受影响的租户、应用、业务
- 评估业务损失程度、SLA受影响情况
- 评估攻击的持续风险与扩散风险

#### 5. 态势预测
- 预测攻击的发展趋势：峰值强度、持续时长、演化方向
- 预测系统资源负载的后续变化
- 预判可能出现的次生故障

#### 6. 方案生成
- 基于攻击类型、影响范围、资源状态，生成最优处置方案
- 给出多套备选方案，评估各方案的效果与业务影响
- 推荐最优方案与执行步骤

#### 7. 决策输出
- 输出标准化决策指令，下发给缓解执行引擎
- 同步给运营控制台，呈现给人工运营人员
- 等待执行结果反馈，进入后续验证与学习环节

### 20.3 大模型在自治推理中的应用
- 攻击事件自然语言理解与摘要生成
- 根因分析报告自动生成
- 处置方案推理与优化建议
- 自然语言人机交互，支撑运营助手
- **明确原则**：大模型仅用于控制面异步分析，不用于数据面实时检测

---

## 第二十一章 Self Learning（自学习体系）
### 21.1 第七项原创模型：Autonomous Defense Loop（自主防御闭环）
**正式提出**：AI原生防御体系必须形成完整的自主防御闭环——Detect → Understand → Reason → Decide → Mitigate → Verify → Learn，实现自我检测、自我分析、自我决策、自我优化。防御系统在与攻击的对抗中持续进化，越防御越强大，真正实现以AI防御AI。

**模型内涵**：
1. **全链路闭环**：从检测到学习形成完整闭环，无需人工介入
2. **持续进化**：每一次攻击都让防御能力得到提升
3. **自适应演化**：能够跟上攻击的演化速度，应对新型攻击

# 第六篇 Algorithm Engineering（算法工程化）
## 第二十四章 SLM：为什么用0.5B不用70B
### 24.1 核心问题：成本-效益平衡
在数据面实时检测场景，通用大模型（70B级）不是最优解，甚至是不可行解。核心原因在于三个维度的不可接受：
1. **时延不可接受**：70B模型单请求推理时延数百毫秒，远高于5ms的实时检测要求，会严重影响业务性能
2. **成本不可接受**：每请求检测的算力成本接近甚至超过被保护的推理请求本身，防护成本高于攻击成本，经济上不可持续
3. **必要性不足**：针对特定攻击检测场景，专用小模型经过专项训练，准确率并不比通用大模型低多少

### 24.2 SLM的技术优势
专用小语言模型（Small Language Model，亿级参数）是实时语义检测的最优技术路线。
- **极致性能**：经过量化、蒸馏、算子优化后，单请求推理时延<5ms，满足实时性要求
- **极低开销**：算力开销仅为70B模型的百分之一到千分之一，防护成本远低于攻击成本
- **场景优化**：针对攻击检测场景专项训练，聚焦核心能力，准确率有保障
- **部署灵活**：可分布式部署在边缘节点，无需集中式大算力集群

### 24.3 SLM训练与优化方法
1. **知识蒸馏**：用大模型作为教师模型，蒸馏出小模型，保留核心检测能力
2. **专项微调**：用海量攻击样本与正常样本专项微调，适配检测场景
3. **量化压缩**：INT4/INT8量化，体积压缩到原来的1/4-1/8，性能大幅提升
4. **算子优化**：针对推理硬件做算子级优化，极致压榨性能
5. **持续迭代**：基于新攻击样本持续增量训练，保持检测能力更新

## 第二十五章 Embedding：为什么Embedding最快
### 25.1 Embedding检测的技术定位
向量嵌入（Embedding）是语义检测的第一道关卡，也是最快的语义特征提取方式。它负责快速过滤80%以上的正常请求，将真正可疑的请求送入后续更深层的SLM检测。

### 25.2 核心优势
1. **计算效率极高**：轻量Embedding模型参数量仅百万级，推理速度亚毫秒级，支持百万级QPS
2. **语义捕捉能力**：能够捕捉语义相似性，识别同一攻击的不同表述变体，优于关键词匹配
3. **可解释性强**：向量距离、聚类结果直观可解释，便于调试与优化
4. **成本极低**：单请求计算成本可忽略不计，适合全量请求覆盖

### 25.3 工程化优化
- **模型量化**：FP16/INT8量化，降低显存占用，提升推理速度
- **批量计算**：批量处理请求，提升吞吐
- **缓存复用**：高频请求的Embedding结果缓存，避免重复计算
- **硬件加速**：适配GPU/NPU加速向量计算

### 25.4 核心应用场景
- 快速异常过滤，粗粒度风险初筛
- 批量攻击聚类，识别大规模同质攻击
- 语义相似度匹配，识别已知攻击变体
- 作为更高层检测的特征输入

## 第二十六章 Behavior Graph Algorithm（行为图谱算法）
### 26.1 核心图算法体系
行为图谱的检测能力建立在四大类图算法之上，覆盖结构分析、异常检测、模式挖掘、动态演化四大场景。

#### 1. 图遍历与结构分析算法
- BFS/DFS广度/深度优先遍历：用于路径分析、连通性分析
- 环检测算法：有向图/无向图的环检测，识别循环调用、死锁
- 最短路径/最长路径：分析调用链长度、执行深度
- 中心性算法：度中心性、介数中心性、接近中心性，识别关键节点

#### 2. 频繁子图挖掘算法
- gSpan、FP-growth等频繁子图挖掘算法
- 挖掘常见的正常行为子图，作为基线模式
- 挖掘异常出现的子图结构，识别新型攻击模式

#### 3. 图异常检测算法
- 基于结构的异常检测：节点度异常、子图结构异常
- 基于属性的异常检测：节点/边的属性值偏离基线
- 基于谱分析的异常检测：图拉普拉斯谱异常识别

#### 4. 流式图计算
- 增量式图更新：边和节点实时增删，无需全量重算
- 增量式异常检测：图谱更新时仅重算受影响部分
- 窗口机制：基于时间窗口的动态图谱，聚焦近期行为

## 第二十七章 GNN（图神经网络）
### 27.1 GNN在行为检测中的价值
图神经网络（Graph Neural Network）是行为图谱的高阶智能检测能力，能够自动学习图结构与属性中的异常模式，识别人工规则无法发现的复杂攻击。

### 27.2 主流GNN选型与适配
| GNN类型 | 适用场景 | 优势 |
| :--- | :--- | :--- |
| GCN（图卷积网络） | 节点分类、风险评分 | 结构简单，计算高效，适合同构图 |
| GAT（图注意力网络） | 异常节点识别、关键边识别 | 注意力机制可解释性强，适配异构图 |
| GraphSAGE | 大规模图、动态图 | 支持归纳学习，适合动态增长的行为图谱 |

### 27.3 核心应用场景
1. **Agent风险评分**：基于Agent的关联关系与行为，计算节点风险分
2. **异常子图识别**：识别整体异常的子图结构，发现协同攻击
3. **攻击链路预测**：预测攻击的下一步传播路径，提前防御
4. **攻击分类**：基于子图特征自动分类攻击类型

### 27.4 工程化优化
- **子图采样**：每次推理仅采样相关子图，避免全图计算
- **批量推理**：批量处理多个节点/子图，提升吞吐
- **增量更新**：图谱变化时增量更新模型输出，无需全量重推理
- **异步运行**：部署在控制面，异步运行，不影响数据面性能

## 第二十八章 RL（强化学习）
### 28.1 强化学习在策略优化中的定位
自适应策略引擎的核心算法支撑是强化学习（Reinforcement Learning）。传统规则策略需要人工调参，无法适配动态变化的攻防场景；强化学习能够通过与环境的交互，自主学习最优策略决策。

### 28.2 问题建模
将策略决策建模为马尔可夫决策过程（MDP）：
- **状态空间S**：资源负载状态、业务状态、攻击状态、风险分布
- **动作空间A**：各类策略调整动作，如限流、降级、隔离、调度
- **奖励函数R**：综合业务可用性、防护效果、资源利用率的多目标奖励
  - 正向奖励：攻击被成功拦截、业务SLA达标
  - 负向奖励：业务受影响、攻击未拦截、资源浪费

### 28.3 算法选型与落地
- **PPO（近端策略优化）**：最主流的深度强化学习算法，训练稳定，适合连续动作空间，是策略优化的首选算法
- **DQN（深度Q网络）**：适合离散动作空间的简单场景
- **落地路径**：
  1. 离线预训练：基于历史攻防数据在离线环境预训练模型
  2. 孪生环境训练：在数字孪生环境中持续训练优化
  3. 灰度上线：小流量灰度验证效果，逐步扩大范围
  4. 在线微调：生产环境小步快跑，持续微调优化

- 协调各Agent协同工作，形成防御合力

### 29.3 多Agent协作机制

- 任务协同协议：标准化的任务交接与协同流程

- **攻击回放系统**：攻击数据沉淀与回放，支撑复盘与测试
- **强化学习训练平台**：离线训练环境，支撑策略模型持续优化
- **自监督学习流水线**：自动数据标注、模型增量训练、自动评估上线

## 第三十章 总结
### 30.1 七大原创检测模型汇总
本卷系统性提出七大原创检测模型，构成AI原生检测的完整方法论体系：
1. **多层检测金字塔**：五层检测栈的金字塔架构，兼顾性能与深度
2. **AI运行时特征空间**：500+维统一特征空间，支撑全品类检测
3. **算力感知检测**：结合底层资源状态的检测范式，精准识别算力耗尽
4. **行为图谱**：统一图建模，检测循环、协同、链式高级攻击
5. **意图感知决策**：从特征到意图，识别推理滥用等隐蔽攻击
6. **自适应策略引擎**：动态生成最优策略，替代固定人工规则
7. **自主防御闭环**：七步自治闭环，实现防御系统自我进化

### 30.2 三大引擎的技术壁垒
检测引擎、决策引擎、自治引擎三大引擎，共同构成了AI Native Anti-DDoS的核心技术壁垒。
- **检测引擎是感知核心**：决定了能不能发现攻击，是所有能力的基础
- **决策引擎是指挥中枢**：决定了能不能精准处置，是效果与成本的平衡器
- **自治引擎是进化能力**：决定了能不能持续成长，是长期竞争力的核心

### 30.3 最终结论
> **未来AI Native Anti-DDoS的核心竞争力，不在于清洗能力，而在于Detection Engine、Decision Engine、Autonomous Engine三大智能引擎。真正的护城河将来自AI Runtime Feature Space、Behavior Graph、AI Telemetry、Policy Engine与Compute-aware Detection体系，而不是单一的规则库或大模型能力。**

本卷构建的算法与引擎体系，是前三卷理论、架构、产品的技术落地基石，也定义了下一代Anti-DDoS的技术标准与产业高度。
